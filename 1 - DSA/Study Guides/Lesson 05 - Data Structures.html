Data Structures

Covers: atomic and composite data types, how they differ, and what a data structure is (its data, its structure and its operations). This is the foundation for stacks, queues and trees in the next lessons. No prior lecture attendance needed.

Learning outcomes

  • Describe an atomic data type
  • Describe a composite data type
  • Explain the differences between atomic and composite data types
  • Define a data structure
  • Explain the data, structure and operations associated with a data structure

1. Why this lesson?

A program works with data. Choosing how the data is organised decides how easy and how fast the program is (the efficiency ideas of Lessons 2–4 apply directly). This lesson gives the vocabulary; Lessons 6–8 then study three important data structures: stacks, queues and trees.

2. Atomic data type

DefinitionA set of non-decomposable data. It consists of a set of homogeneous data (all of the same kind) and a set of operations that can be performed on that data.
  • Non-decomposable: you cannot split a value into smaller meaningful parts of the type. The value 7 of type int is a single, whole thing.
  • Also called primitive (or elemental) data types: char, bool, short, int, long, float, double.
  • Homogeneous: every value belongs to the same set (for int, whole numbers).
  • Operations come with the type: for int they include + − * / %, comparison, assignment.

3. Composite data type

DefinitionA set of decomposable data, composed using atomic and composite data types. It could consist of a set of homogeneous or heterogeneous data.
  • Decomposable: it can be broken into parts (its members).
  • Heterogeneous means the parts can be of different types (an int, a string and another composite).
  • It can be built from atomic types and from other composite types.

Example: struct Day and struct Person

struct Day {              // composed of atomic data types
    int year;
    int month;
    int date;
};
Day birthDay;             // birthDay.year, birthDay.month, birthDay.date

struct Person {           // composed of atomic AND a composite
    char name[30];        // atomic items (array of char)
    int  weight;          // atomic
    Day  dob;             // composite inside a composite
};
Person he;

5. Data structure

DefinitionA structure that holds a set of atomic or composite data. It consists of a set of homogeneous or heterogeneous data and a set of operations that can be performed on the data.

Every data structure therefore has three parts:

PartMeaningExample (array int num[] = {3, 2, 1})
DataThe values it holds (atomic or composite).The three integers 3, 2, 1.
StructureHow the data are organised and related (their arrangement).Elements one after another in order, reached by index 0, 1, 2.
OperationsWhat you can do with the data.get: print num[0]; and set: num[2] = 5;

Example 1: array of atomic data

int num[] = {3, 2, 1};
print num[0];      // get operation  -> 3
num[2] = 5;        // set operation  -> {3, 2, 5}

Example 2: array of composite data

Person employee[] = { {"Perera", 60, {1990, 02, 10}},
                      {"Silva",  45, {1998, 05, 31}} };

print employee[0].name;     // get operation  -> Perera
employee[1].weight = 57;    // set operation

Features of this structure: heterogeneous (name, weight and date are different kinds of data), made of both atomic and composite data, and linear (the two employees sit one after the other). Operations: get (employee[0].name) and set (employee[1].weight = 57).

Whenever we study a data structure we ask the same three questions: what data does it hold, what structure (arrangement) does it use, and what operations does it offer?

Written questions

W1. Define atomic data type and composite data type and give two differences between them.

Atomic: a set of non-decomposable data; consists of a set of homogeneous data and a set of operations that can be performed on the data. Composite: a set of decomposable data, composed using atomic and composite data types; could consist of homogeneous or heterogeneous data.

Differences: (1) atomic data cannot be broken down, composite data can; (2) atomic data is homogeneous, composite data may be heterogeneous; (3) composite types are built from atomic and/or other composite types, atomic types are the basic building blocks.

W2. Define a data structure and explain its data, structure and operations using an array of integers.

A data structure is a structure that holds a set of atomic or composite data; it consists of a set of homogeneous or heterogeneous data and a set of operations that can be performed on the data. For int num[] = {3, 2, 1}: the data are the integers 3, 2, 1 (atomic, homogeneous); the structure is that they are arranged one after another and reached by index 0, 1, 2 (linear); the operations are get (print num[0]) and set (num[2] = 5).

W3. Write C++ struct declarations for a Person that has a name (up to 30 characters), a weight and a date of birth made of year, month and date. State which parts are atomic and which are composite. 
struct Day    { int year; int month; int date; };
struct Person { char name[30]; int weight; Day dob; };

Atomic: year, month, date, weight and the characters of name. Composite: Day (built from atomic ints) and Person (built from atomic types and the composite Day).

W4. Describe the data structure Person employee[] holding two employees, and give a get and a set operation.

It is an array of composite elements: heterogeneous (name, weight, date of birth), containing both atomic and composite data, and linear (elements one after another). Get: print employee[0].name;. Set: employee[1].weight = 57;.
