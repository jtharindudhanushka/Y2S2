1. What is space complexity?

Space complexity is the amount of memory (RAM) that a program written with a particular algorithm needs in order to run to completion. It belongs to performance analysis (Lesson 1): we work it out from the algorithm instead of measuring a running program.

Why are we interested?

ReasonMeaning
Will it fit?Find out whether the available memory is enough to run the program written with our algorithm.
Choose the lighter oneWhen several algorithms solve the same problem, prefer the program that uses less memory.
Largest problemEstimate the largest problem our algorithm can solve with the memory available.

2. The three components

Memory used by a running program falls into three parts.

ComponentWhat it isDepends on
Instruction spaceMemory needed to load the compiled version of the program (its instructions).The compiler used; the compiler options used (for example code-size optimisation vs execution-time optimisation); the architecture of the target computer.
Data spaceMemory needed to hold all the constants and variables of the program.The data types and the number of named constants, primitive variables and structured variables used.
Environment stack spaceMemory needed for the environment stack (also called the run-time stack or call stack).How functions call each other, and whether they are recursive.
Same source, different instruction spaceThe machine code produced from one piece of source code can differ in size depending on the compiler and its options, which is why instruction space depends on them.

3. The environment stack

The environment stack is a data structure that keeps the information needed to resume execution of partially completed functions. A stack works Last In, First Out (LIFO): the newest item is removed first.

When a function is called, the computer pushes a frame on the stack holding:

  • the return address: a pointer to the calling instruction in the caller, so the caller can continue when the callee returns,
  • the function's parameters,
  • the function's local variables.

When the function returns, its frame is popped and its local variables are destroyed.

Example: function1 calls function2, which calls function3

Each call pushes a frame; each return pops it, newest first. If function1 calls function2, the stack keeps the return address in function1 so execution can resume there. The peak number of frames on the stack decides the environment stack space.

4. Sensitive and insensitive factors

Some factors are not known at the time the algorithm is developed (for example how big the input will be). So we separate the memory that stays the same from the memory that changes with the problem.

Insensitive (fixed)Sensitive (variable)
MeaningRelatively insensitive to the problem being solved: same memory whatever the input.Sensitive to the problem being solved: memory changes with the input.
Instruction spaceAlways insensitive.–
Data spaceLiteral constants, named constants and primitive variables.Structured variables (arrays etc.) and dynamic memory allocation. Example: a program that sorts an array of n integers.
Environment stack spaceNon-recursive functions.Recursive functions. Example: a function that recursively computes the factorial of a given n.
IntuitionIf int a; exists, it uses the same memory whether the user enters 10 or 10 million. But int arr[n]; uses 40 bytes when n = 10 and 4000 bytes when n = 1000: it changes with the input. The variable part is what space complexity is really about.

5. The formula

Space complexity is a function of n, the instance characteristic (a number describing the size of the problem, such as the number of array elements).

S(n) = c + SA(n)

  • c = the insensitive (constant) space contribution.
  • SA(n) = the sensitive space contribution of algorithm A, a function of n.
CaseMeaning
SA(n) = 0Only fixed memory is used. Memory never grows with the input: constant space, written O(1).
SA(n) grows with nMore input needs more memory (arrays, dynamic allocation, recursion depth).

Quick checks: int sum(int a, int b, int c) uses only 3 integers, memory never changes, variable space = 0. A for (i = 0; i < n; i++) loop: n changes but no extra variables are created (only i), so variable space = 0 and overall space complexity is O(1).

6. Worked examples

Example 1: iterative sum (non-recursive)

ALGORITHM sum(REF a[] INTEGER, n INTEGER)
   returns sum of integers in array
1  s ← 0
2  i ← 0
3  LOOP (i < n)
4     s ← s + a[i]
5     i ← i + 1
6  END LOOP
7  RETURN s
END sum

Trace with a = {5, 1, 3}, n = 3: s goes 0 → 5 → 6 → 9, returns 9.

ItemSensitive?Why
n, s, iNoPrimitive variables: always the same memory.
array aNo (for this algorithm)It is a structured variable, but it is passed by reference (REF), so the algorithm makes no copy of it; its memory is not charged to this algorithm.
Environment stackNoThe algorithm is non-recursive: one call, one frame.

So SA(n) = 0 and S(n) = c: constant space, O(1).

Example 2: recursive sum

ALGORITHM sum(REF a[] INTEGER, n INTEGER)
   returns sum of integers in array
1  IF (n > 0)
2     RETURN sum(a, n - 1) + a[n - 1]
3  ELSE
4     RETURN 0
5  END IF
END sum

Trace with a = {5, 1, 3}, calling sum(a, 3):

sum(a,3) = sum(a,2) + a[2]  = ... + 3
sum(a,2) = sum(a,1) + a[1]  = ... + 1
sum(a,1) = sum(a,0) + a[0]  = ... + 5
sum(a,0) = 0                (base case, n is not > 0)
Unwinding:  0 → 5 → 6 → 9      result = 9
ItemSensitive?Why
nNoPrimitive variable.
a[]NoDeclared outside the algorithm's scope and passed by reference.
Environment stackYesThe algorithm is recursive. For every call the stack keeps n, a and the return address. The recursion depth grows with n.

Assuming a 32-bit machine (n = 4 bytes, a = 4 bytes, return address = 4 bytes), each call keeps 4 + 4 + 4 = 12 bytes. The recursion makes n + 1 calls, so the stack needs about 12(n + 1) bytes: space grows linearly with n. Compare with Example 1, which does the same job in constant space.

Key takeawayThe same task can have very different space complexity. The iterative sum is O(1); the recursive sum is O(n) because every pending call keeps a frame on the environment stack. When memory is tight, prefer the version with the smaller sensitive part.

7. How to analyse an algorithm (checklist)

  1. List every variable and constant. Primitive ones and literals are insensitive (they go into c).
  2. Look for arrays, structured variables and dynamic allocation whose size depends on n. These are sensitive. Check whether the array is only passed in by reference (then not charged to this algorithm).
  3. Is the algorithm recursive? If so, estimate the maximum recursion depth and the size of one frame (parameters + local variables + return address). That is a sensitive contribution.
  4. Instruction space is always treated as insensitive.
  5. Write S(n) = c + SA(n).
Lecture prototype question (Question 4a)The recursive sum(REF a, VAL n) above was set as an exam-style question: determine the space complexity, assuming a 32-bit machine. Model answer: each call needs environment stack space for a, n and the return address. a is an array passed by reference, so only its reference (4 bytes on a 32-bit machine) is stored; n is an integer (4 bytes); the return address is a pointer (4 bytes). Recursion depth is n + 1. So S(n) = 12(n + 1).
