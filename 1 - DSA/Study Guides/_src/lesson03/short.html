Short note: revision sheet

TopicRemember
Time complexityAmount of time a program written with a particular algorithm needs to run to completion. It counts work as a function of n; it is not actual seconds.
WhyReal-time response · prefer the faster algorithm · guarantee completion without time-out
Depends onInput size n (main), hardware and software, types of operations. Same factors as space complexity; some are sensitive to the problem.
FormulaT(n) = c + TA(n); c = constant time, TA(n) = time that depends on n
Two approachesOperation count · Step count
Operation countCount how many times the key (most time-consuming) operation runs. Weaknesses: does not measure actual time; picking the key operation can be hard.
Step countCount the steps (statement executions) of the whole program.
Loop ruleLOOP test runs n + 1 times for n iterations; body lines run n times.
max (operation count)Key operation a[i] < a[c]: T(n) = n − 1
find (comparison x ≠ a[c])Best 1, worst n, average (n + 1) / 2
Iterative sum (step count)T(n) = 3n + 4 (T(3) = 13)
Recursive sum (step count)T(n) = 2n + 2
Programming instrumentationAdd extra code (a global counter g, g++ at each step) to collect information about execution; g = T(n) at the end.
Useful sum1 + 2 + ... + n = n(n + 1) / 2
Exam tipShow the table of lines and how many times each runs, then add them up. Remember the extra +1 for the loop's final failing test, and the single execution of lines before and after the loop.
