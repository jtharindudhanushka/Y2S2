TopicRemember
Best / worst / averageMinimum / maximum / average of T(n) over the instance characteristic n.
T(n) propertiesFunction of n; n ≥ 0; T(n) ≥ 0. We want to know if it gets reasonably or incredibly slow as the problem grows.
LinearCounter adds: T(n) = 2n + 2 (y = mx + c). Sequential search.
LogarithmicCounter doubles: T(n) = 6 log2 n + 2. Binary search. 2iterations = n, so iterations = log2 n.
n log nLinear loop around a doubling loop: T(n) = 2n log2 n + 4n + 2.
QuadraticTwo nested n-loops: T(n) = 2n2 + 4n + 2.
Growth order1 < log n < n < n log n < n2 < n3 (polynomial) < 2n (exponential) < n! (factorial)
Asymptotic notationRunning time as a growth rate: drop less significant terms and constant coefficients (3n2 + 50n + 200 grows like n2).
Big-OAsymptotic notation for the worst case. T(n) = O(f(n)) if there exist positive c and n0 with T(n) ≤ c f(n) for all n ≥ n0.
Proof examples3n + 2 ≤ 4n (c = 4, n0 = 2): O(n) · 10n2 + 4n + 2 ≤ 11n2 (c = 11, n0 = 5): O(n2) · 4n3 + 2n2 ≤ 5n3 (c = 5, n0 = 2): O(n3) · ½(n + 1) ≤ n (c = 1, n0 = 1): O(n)
Sequential searchUnordered list. Best 1, worst n, average (n + 1) / 2. O(n).
Binary searchSorted list only. Compare with the middle, discard half. Worst O(log n). Faster than sequential search.
Selection sortFind the smallest of the unsorted part, swap into place. n(n − 1)/2 comparisons always, n − 1 swaps. O(n2).
Bubble sortSwap neighbours that are out of order; largest bubbles to the end each pass. n(n − 1)/2 comparisons (this version), swaps vary. O(n2).
Useful sum(n − 1) + (n − 2) + ... + 1 = n(n − 1)/2
Exam tipFor a Big-O proof write the chain of inequalities, state c and n0 explicitly, then conclude T(n) = O(f(n)). For a loop, ask: does the counter add (n), double (log n), or is it nested (multiply the counts)?
