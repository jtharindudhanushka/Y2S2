1. What is a queue?

DefinitionA linear data structure in which data additions are restricted to one end, the rear, and removals can only be done from the other end, the front. The rule is First In, First Out (FIFO): the item that arrived first leaves first.

Think of a line at a ticket counter: people join at the back and are served from the front, in order of arrival.

Operations and errors

ItemMeaning
enqueue(d)Add item d at the rear.
dequeue(d)Remove the item at the front and hand it back.
OverflowTrying to add an item to a full queue.
UnderflowAttempting to remove an item from an empty queue.

Stack vs queue

RuleLIFOFIFO
Ends usedOne (top)Two (rear to add, front to remove)

Typical useUndo, reversing, backtrackingServing in arrival order (scheduling, spooling)

2. Array-based queue

Arrays are finite, but imagine for a moment that they were not: front would be the left end and rear the right end, and with insertions and removals both would move to the right. The problem: they eventually fall off the right end of the array while free cells sit unused at the left. The fix is to treat the array as a circle (circular array): after the last cell, wrap around to cell 0.

The queue needs these variables:

VariableMeaning
pPointer to the array (the storage).
sizeCapacity of the array.
frontIndex of the first element (where dequeue takes from).
rearIndex of the cell after the last element, i.e. where the next enqueued item goes.
countNumber of items currently in the queue.
Why do we need count?When the queue is empty front and rear are at the same place; when it is full they are again at the same place. Looking at front and rear alone cannot tell the two apart, so count does (0 = empty, size = full).

First snapshot from the lecture (size 10): a queue holding b c d e f in cells 1 to 5 has count = 5, front = 1 (cell of b) and rear = 6 (the free cell after f). Conceptually the line is b c d e f with front at the left end and rear at the right end.

Picture the array bent into a ring with its two ends joined. Above: 9 items, front at cell 7 (item h), rear at cell 6 (the free cell where the next item goes).

Pseudocode

global variables
   p POINTER to DATATYPE, size INTEGER, count INTEGER,
   front INTEGER, rear INTEGER

ALGORITHM create(VAL s INTEGER)
1  size ← s
2  front ← rear ← count ← 0
3  p ← ALLOCATE MEMORY DATATYPE[size]
END create

ALGORITHM destroy()
1  RELEASE MEMORY[] p
END destroy

ALGORITHM isFull()
1  IF (count = size)
2     RETURN true
3  ELSE
4     RETURN false
5  END IF
END isFull

ALGORITHM isEmpty()
1  IF (count = 0)
2     RETURN true
3  ELSE
4     RETURN false
5  END IF
END isEmpty

ALGORITHM enqueue(VAL d DATATYPE)
1  IF (isFull())
2     RETURN false           // overflow
3  ELSE
4     p[rear] ← d
5     rear ← rear + 1
6     count ← count + 1
7     rear ← rear MOD size
8     RETURN true
9  END IF
END enqueue

ALGORITHM dequeue(REF d DATATYPE)
1  IF (isEmpty())
2     RETURN false           // underflow
3  ELSE
4     d ← p[front]
5     front ← front + 1
6     count ← count - 1
7     front ← front MOD size
8     RETURN true
9  END IF
END dequeue

MOD size is what makes the array circular (line 7 of both algorithms): when rear (or front) reaches size, size MOD size = 0 sends it back to cell 0. The index is first incremented, then reduced with MOD.

C++ implementation

//ArrayQueue.h
class queue
{
    public:
        queue(int);              // create()
        ~queue();                // destroy()
        int enqueue(char);
        int dequeue(char &);
    private:
        int isEmpty();
        int isFull();
        int size, count, front, rear;
        char *p;
};

queue::queue(int s)
{
    size = s; front = rear = count = 0;
    p = new char[size];          // allocates memory
}
queue::~queue()
{
    delete[] p;                  // releases memory
}
int queue::isFull()  { return (count == size) ? 1 : 0; }
int queue::isEmpty() { return (count == 0) ? 1 : 0; }

int queue::enqueue(char d)            int queue::dequeue(char &d)
{                                     {
    if (isFull())                         if (isEmpty())
        return 0;                             return 0;
    else                                  else
    {                                     {
        p[rear++] = d;                        d = p[front++];
        count++;                              count--;
        rear = rear % size;                   front = front % size;
        return 1;                             return 1;
    }                                     }
}                                     }
  • p[rear++] = d;: store at rear, then increment rear (post-increment). d = p[front++];: read at front, then increment front.
  • rear = rear % size; is the C++ form of rear MOD size: the remainder after dividing by size.
//TestArrayQueue.cpp
#include <iostream>
#include "ArrayQueue.h"
int main()
{
    const int queueSize = 10;
    queue q(queueSize);
    char data;
    std::cin >> data;
    while (data != '.' && q.enqueue(data))
        std::cin >> data;
    std::cout << std::endl;
    while (q.dequeue(data))
        std::cout << data;
    return 0;
}

3. Linked list-based queue

Each item is a node (data + next). front points to the first node and rear points to the last node (note: unlike the array version, here rear is the last element itself). The last node's next is null. Both pointers are null when the queue is empty.

No size or isFull is needed: nodes are created on enqueue and released on dequeue, so the queue can hold any number of items (it grows and shrinks at run time).

Pseudocode

TYPE node
   data DATATYPE
   next POINTER to node
END node
global variables
   front POINTER to node, rear POINTER to node

ALGORITHM create()
1  front ← null
2  rear ← null
END create

ALGORITHM destroy()
1  LOOP (front ≠ null)
2     p ← front
3     front ← front->next
4     RELEASE MEMORY p
5  END LOOP
END destroy

ALGORITHM isEmpty()
1  IF (front = null)
2     RETURN true
3  ELSE
4     RETURN false
5  END IF
END isEmpty

ALGORITHM enqueue(VAL d DATATYPE)
1  p ← ALLOCATE MEMORY node
2  p->data ← d
3  p->next ← null
4  IF (front ≠ null)
5     rear->next ← p
6  ELSE
7     front ← p
8  END IF
9  rear ← p
END enqueue

ALGORITHM dequeue(REF d DATATYPE)
1  IF (isEmpty())
2     RETURN false
3  ELSE
4     d ← front->data
5     p ← front
6     IF (front = rear)
7        front ← rear ← null
8     ELSE
9        front ← front->next
10    END IF
11    RELEASE MEMORY p
12    RETURN true
13 END IF
END dequeue

How enqueue and dequeue work

  • enqueue: make a new node holding d with next = null. If the queue is not empty, link it after the current last node (rear->next ← p); if it is empty, it becomes the front too (front ← p). In both cases it becomes the new rear.
  • dequeue: read the front's data and remember that node in p. If front and rear are the same node, it was the only one, so the queue becomes empty (both set to null); otherwise move front to the next node. Finally release p.

C++ implementation

//LinkedListQueue.h
struct node
{
    char data;
    node *next;
};
class queue
{
    public:
        queue();                 // create()
        ~queue();                // destroy()
        void enqueue(char);
        int dequeue(char &);
    private:
        int isEmpty();
        node *front, *rear;
};

queue::queue() { front = rear = 0; }        // sets to null
queue::~queue()
{
    while (front)
    {
        node *p = front;
        front = front->next;
        delete p;                            // releases memory
    }
}
int queue::isEmpty() { return (front == 0) ? 1 : 0; }

void queue::enqueue(char d)
{
    node *p = new node;                      // allocates memory
    p->data = d;
    p->next = 0;
    (front ? rear->next : front) = p;
    rear = p;
}
int queue::dequeue(char &d)
{
    if (isEmpty())
        return 0;
    else
    {
        d = front->data;
        node *p = front;
        if (front == rear)
            front = rear = 0;
        else
            front = front->next;
        delete p;
        return 1;
    }
}

The line (front ? rear->next : front) = p; is the pseudocode's IF (front ≠ null) rear->next ← p ELSE front ← p written with the ternary operator: if front is non-null assign to rear->next, otherwise assign to front. Also front = rear = 0; sets both to null (chained assignment).

#include <iostream>
#include "LinkedListQueue.h"
int main()
{
    queue q;
    char data;
    std::cin >> data;
    while (data != '.')
    {
        q.enqueue(data);
        std::cin >> data;
    }
    std::cout << std::endl;
    while (q.dequeue(data))
        std::cout << data;
    return 0;
}

4. Queue applications

ApplicationWhy a queue fits
Process scheduling in an operating systemProcesses waiting for the CPU are served in the order they arrived.
Printer spoolingPrint jobs wait and are printed first come, first served.
Network traffic handlingPackets are buffered and forwarded in the order received.
Other data processing and service-providing applicationsAnything that must serve requests in arrival order.

Worked example: SMS gateway (lecture prototype question 2)

An SMS gateway feeds incoming text messages from different mobile networks into one end of a data structure and releases them from the other end to their own network for delivery, in the order they arrive. It must handle any number of incoming messages.

  • Suitable data structure: a linked list-based queue: FIFO gives the arrival order, and the linked list has no fixed capacity.

Key takeaways Queue = linear, FIFO: enqueue at the rear, dequeue from the front. Overflow = add to a full queue; underflow = remove from an empty queue. Array-based: circular array with p, size, count, front, rear; MOD size wraps indexes; count distinguishes full from empty. Linked: front and rear pointers, no capacity limit; when the last node is dequeued set both to null. Applications: process scheduling, printer spooling, network traffic.
