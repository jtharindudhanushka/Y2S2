1. Warm-up: recursion

Almost every tree algorithm is recursive, so first a quick look. A recursive algorithm solves a problem by calling itself on a smaller version of the problem, and it needs a base case where it stops calling itself. The alternative is iteration (a loop).

Iteration (loop)Recursion
ALGORITHM countdown(VAL n INTEGER)
1  LOOP (n > 0)
2     PRINT n
3     n ← n - 1
4  END LOOP
END countdown
ALGORITHM countdown(VAL n INTEGER)
1  IF (n > 0)
2     PRINT n
3     countdown(n - 1)
4  ELSE
5     RETURN
6  END IF
END countdown

Both print n, n−1, ..., 1. The recursive version's base case is n ≤ 0 (do nothing and return).

Sum of 1 to n recursively (the function should accept any positive integer and return the summation):

ALGORITHM sum(VAL n INTEGER)
1  IF (n > 0)
2     RETURN n + sum(n - 1)
3  ELSE
4     RETURN 0
5  END IF
END sum

sum(3) = 3 + sum(2) = 3 + (2 + sum(1)) = 3 + (2 + (1 + sum(0))) = 3 + 2 + 1 + 0 = 6. Each pending call waits on the call stack (Lesson 2) until the one below it returns. A tree is a recursive structure too: a tree is a root plus smaller trees (its subtrees), which is why recursion fits so well.

2. What is a tree?

DefinitionA tree is a set of nodes that holds atomic or composite data. Nodes are connected to other nodes with edges.
TermMeaning
NodeOne item of the tree (holds data).
EdgeA connection between two nodes.
RootThe top node; the only node with no parent.
LeafA node with no children (bottom of the tree).
Parent / childA node directly above / below another node.
SubtreeA node together with everything below it; itself a tree.
OrderThe maximum number of children a node can have. (The example above has order 3.)

Unlike stacks and queues (linear), a tree is a hierarchy: one parent can lead to several children.

3. Binary tree

DefinitionA tree with an order of two (each node has at most 2 children). It is a finite set of elements partitioned into three subsets: the root, the left subtree and the right subtree, each of which is again a binary tree.

4. Binary tree traversal

Traversal means visiting each node of a binary tree once and only once, in a predetermined sequence, without missing any node. "Visit" means do something with the node (here: print its data). There are three standard orders. In each, "in xorder" on a subtree means: repeat the same rule on that subtree.

TraversalStepsRemember
Preorder1. Visit the root · 2. Traverse the left subtree in preorder · 3. Traverse the right subtree in preorderEach node is visited when it is first reached (root first).
Inorder1. Traverse the left subtree in inorder · 2. Visit the root · 3. Traverse the right subtree in inorderA node is not visited until its left subtree is done (root in the middle).
Postorder1. Traverse the left subtree in postorder · 2. Traverse the right subtree in postorder · 3. Visit the rootA node is not visited until both subtrees are done (root last).

Example tree: root a; a's children b (left) and e (right); b's children c and d; e has one child f on its right.

Preorder walk-through: visit a. Go left to b: visit b. Go left to c: visit c (no children, go back up). Back at b, go right to d: visit d. Back at a, go right to e: visit e, then its left (none), then right f: visit f. Result: a b c d e f.

Inorder: from a, keep going left until you cannot (the first step is always the left traversal): the leftmost node c is the first output. Then its parent b, then b's right subtree d, then root a, then e's left (none), e, and f. Result: c b d a e f.

Postorder: c and d are output before their parent b; b's subtree is complete before we go right; f is output before e; the root a comes last. Result: c d b f e a.

5. Binary search tree (BST)

DefinitionA binary tree in which (1) data in any node of the left subtree is less than that of the root, (2) data in any node of the right subtree is greater than or equal to that of the root, and (3) each subtree is itself a binary search tree.

Duplicates (equal values) go to the right. Inorder traversal of a BST visits the values in sorted order: 20, 30, 40, 50, 60, 70, 80. So a BST gives a sorting algorithm.

Sorting with a BST

FOR each incoming data item:
   IF tree is empty
      create a node and insert incoming data item
   ELSE
      start at the root
      label:
      IF incoming item < item stored in current node
         visit left child node of current node
         IF there is no left child
            insert incoming item as left child node
         ELSE
            go to label
      ELSE
         visit right child node of current node
         IF there is no right child
            insert incoming item as right child node
         ELSE
            go to label
traverse tree in inorder          -> the data come out sorted

The same rule written recursively (from the lecture's prototype question 3): insert(number, node): if node is empty store number in it; else if number < value in node insert into the left child; else insert into the right child.

Worked example (prototype question 3): insert 70, 50, 30, 80, 60, 40, 20.

InsertPathResult

30< 70 left; < 50 leftleft child of 50
80≥ 70: rightright child of 70
60< 70 left; 60 ≥ 50 rightright child of 50
40< 70, < 50, 40 ≥ 30 rightright child of 30

This gives the tree drawn above. Preorder: 70, 50, 30, 20, 40, 60, 80. Inorder: 20, 30, 40, 50, 60, 70, 80. Postorder: 20, 40, 30, 60, 50, 80, 70.

6. Array-based tree

Store the tree in an array using index arithmetic instead of pointers:

  • The root is at index 1 (index 0 is unused).
  • A node at index n has its left child at 2n and its right child at 2n + 1 (so n is the parent of 2n and 2n + 1).
  • The value 0 means "empty slot", so 0 cannot be stored as data.

Check: 70 at n = 1; its children at 2 (50) and 3 (80); 50's children at 4 (30) and 5 (60); 30's children at 8 (20) and 9 (40). Cells 6, 7, 10, 11 stay 0 (empty).

Pseudocode

global variables
   p POINTER to DATATYPE, size INTEGER

ALGORITHM create(VAL s INTEGER)
1  size ← s
2  p ← ALLOCATE MEMORY DATATYPE[size]
3  i ← 0
4  LOOP (i < size)
5     p[i] ← 0
6     i ← i + 1
7  END LOOP
END create

ALGORITHM destroy()
1  RELEASE MEMORY[] p
END destroy

ALGORITHM insert(VAL d DATATYPE, VAL n INTEGER ← 1)
1  IF (n < size)
2     IF (p[n] = 0)
3        p[n] ← d
4        RETURN true
5     ELSE
6        IF (d < p[n])
7           RETURN insert(d, 2n)
8        ELSE
9           RETURN insert(d, 2n + 1)
10       END IF
11    END IF
12 ELSE
13    RETURN false
14 END IF
END insert

n ← 1 in the header is a default value: calling insert(d) starts at the root. How insert works: if the slot is empty store there; otherwise go left (2n) when d is smaller, right (2n + 1) otherwise; if the index runs off the end of the array (n ≥ size) return false (the tree is "full" in that direction).

Trace for 70, 50, 80, 30, 20, 40, 60 (size 12):

CallStepsStored
insert(70, 1)1 < size, p[1] = 0: emptyp[1] = 70
insert(50, 1)p[1] ≠ 0; 50 < 70 → insert(50, 2); p[2] = 0p[2] = 50
insert(80, 1)80 < 70 false → insert(80, 3); emptyp[3] = 80
insert(30, 1)< 70 → (30, 2); < 50 → (30, 4); emptyp[4] = 30
insert(20, 1)(20, 2) → (20, 4) → 20 < 30 → (20, 8); emptyp[8] = 20
insert(40, 1)(40, 2) → (40, 4): 40 < 30 false → (40, 9); emptyp[9] = 40
insert(60, 1)(60, 2): 60 < 50 false → (60, 5); emptyp[5] = 60

Traversals

ALGORITHM traversePreorder(VAL n INTEGER ← 1)
1  IF (n < size)
2     IF (p[n] ≠ 0)
3        PRINT(p[n])
4        traversePreorder(2n)
5        traversePreorder(2n + 1)
6     END IF
7  END IF
END traversePreorder

ALGORITHM traverseInorder(VAL n INTEGER ← 1)
1  IF (n < size)
2     IF (p[n] ≠ 0)
3        traverseInorder(2n)
4        PRINT(p[n])
5        traverseInorder(2n + 1)
6     END IF
7  END IF
END traverseInorder

ALGORITHM traversePostorder(VAL n INTEGER ← 1)
1  IF (n < size)
2     IF (p[n] ≠ 0)
3        traversePostorder(2n)
4        traversePostorder(2n + 1)
5        PRINT(p[n])
6     END IF
7  END IF
END traversePostorder

The only difference between the three is where the PRINT line sits: before the two recursive calls (pre), between them (in) or after them (post). The checks n < size and p[n] ≠ 0 are the base cases: past the end of the array, or an empty slot, means "no node here": return without doing anything.

Inorder trace (size 12, tree above): traverseInorder(1) → (2) → (4) → (8): its children 16 and 17 are beyond the array (return); print 20; back at 4 print 30, then (9): print 40; back at 2 print 50, then (5): print 60; back at 1 print 70, then (3): left (6) is empty, print 80, right (7) empty. Output: 20, 30, 40, 50, 60, 70, 80.

Test algorithm

ALGORITHM test()
1  create(treeSize)
2  READ(data)
3  LOOP (data ≠ 0 AND insert(data))
4     READ(data)
5  END LOOP
6  traverseInorder()
7  destroy()
END test

Reads numbers until 0 (the end marker, which is why 0 cannot be data) or until an insert fails, then prints them sorted.

C++ implementation

//ArrayTree.h
#include <iostream>
class tree
{
    public:
        tree(int);                       // create()
        ~tree();                         // destroy()
        int insert(int, int = 1);        // second parameter has default value 1
        void traversePreorder(int = 1);
        void traverseInorder(int = 1);
        void traversePostorder(int = 1);
    private:
        int size;
        int *p;
};

tree::tree(int s)
{
    size = s;
    p = new int[size];                   // allocates memory
    for (int i = 0; i < size; i++)
        p[i] = 0;
}
tree::~tree() { delete[] p; }            // releases memory

int tree::insert(int d, int n)
{
    if (n < size)
        if (p[n] == 0)
        {
            p[n] = d;
            return 1;
        }
        else
            if (d < p[n])
                return insert(d, 2 * n);
            else
                return insert(d, 2 * n + 1);
    else
        return 0;
}

void tree::traversePreorder(int n)
{
    if (n < size)
        if (p[n] != 0)
        {
            std::cout << p[n] << endl;
            traversePreorder(2 * n);
            traversePreorder(2 * n + 1);
        }
}
void tree::traverseInorder(int n)
{
    if (n < size)
        if (p[n] != 0)
        {
            traverseInorder(2 * n);
            std::cout << p[n] << endl;
            traverseInorder(2 * n + 1);
        }
}
void tree::traversePostorder(int n)
{
    if (n < size)
        if (p[n] != 0)
        {
            traversePostorder(2 * n);
            traversePostorder(2 * n + 1);
            std::cout << p[n] << endl;
        }
}
//TestArrayTree.cpp
#include <iostream>
#include "ArrayTree.h"
int main()
{
    const int treeSize = 10;
    tree t(treeSize);
    int data;
    std::cin >> data;
    while (data != 0 && t.insert(data))
        std::cin >> data;
    std::cout << endl;
    t.traverseInorder();
    return 0;
}

The declaration insert(int, int = 1) gives the second parameter a default argument (Lesson 1): t.insert(data) means t.insert(data, 1). The default is written only in the header (declaration), not again in the definition.

The problem with array-based trees

Height hNodes on the last levelTotal nodes (full tree)
011 = 21 − 1
121 + 2 = 3 = 22 − 1
241 + 2 + 4 = 7 = 23 − 1
381 + 2 + 4 + 8 = 15 = 24 − 1

A tree of height h can hold up to 2h+1 − 1 nodes, so the array must have 2h+1 elements (index 0 unused). Example: 4 levels need 16 array elements for 15 nodes.

  • If the tree is unbalanced and its height grows, the wasted memory grows dramatically. For example a chain where each node is the right child of the previous one occupies indexes 1, 3, 7, 15, 31: five nodes need an array of 32 elements.
  • Disadvantages: it cannot grow, it cannot shrink, and the waste can be dramatic.
  • It remains a valid choice when the tree is balanced, or when its maximum height is known and does not change.
  • Solution: a linked list-based tree: it can grow and shrink. If you do not know the height, or the tree is not balanced, use the linked version.

7. Linked list-based tree

Each node stores its data and the addresses of its two children (null when a child is missing). A single pointer root holds the address of the top node. This is flexible and memory efficient.

Pseudocode

TYPE node
   data DATATYPE
   left POINTER to node
   right POINTER to node
END node
global variables
   root POINTER to node

ALGORITHM create()
1  root ← null
END create

ALGORITHM destroy()
1  removeNode(root)
END destroy

ALGORITHM removeNode(VAL p POINTER to node)
1  IF (p ≠ null)
2     removeNode(p->left)
3     removeNode(p->right)
4     RELEASE MEMORY p
5  END IF
END removeNode

ALGORITHM insert(VAL d DATATYPE)
1  addNode(root, d)
END insert

ALGORITHM addNode(REF p POINTER to node, VAL d DATATYPE)
1  IF (p = null)
2     p ← ALLOCATE MEMORY node
3     p->data ← d
4     p->left ← null
5     p->right ← null
6  ELSE
7     IF (d < p->data)
8        addNode(p->left, d)
9     ELSE
10       addNode(p->right, d)
11    END IF
12 END IF
END addNode
  • addNode walks down: if the current link is null, create the node here; otherwise go left for smaller values, right otherwise. p is a REF parameter, so when addNode creates a node and assigns it to p the assignment changes the actual pointer in the tree (the root, or some node's left/right).
  • removeNode frees the children before the node itself (otherwise their addresses would be lost): a postorder-style deletion. destroy calls it on the root.

Trace of inserting 70, 50, 80, 30, 20, 40, 60: addNode(root, 70): root is null, so a node holding 70 is created and root points to it. addNode(root, 50): root not null; 50 < 70, addNode(left of 70, 50): null, create. 80: 80 ≥ 70, right, create. 30: left to 50, 30 < 50, left of 50, create. 20: 70 → 50 → 30 → left of 30, create. 40: 70 → 50 → 30, 40 ≥ 30 so right of 30, create. 60: 70 → 50, 60 ≥ 50 so right of 50, create. The result is the same BST as before (70; 50 and 80; 30 and 60; 20 and 40), now built from linked nodes.

Traversals

ALGORITHM traverse(VAL n INTEGER)
1  IF (n = 1)
2     traversePreorder(root)
3  ELSE
4     IF (n = 2)
5        traverseInorder(root)
6     ELSE
7        IF (n = 3)
8           traversePostorder(root)
9        END IF
10    END IF
11 END IF
END traverse

ALGORITHM traversePreorder(VAL p POINTER to node)
1  IF (p ≠ null)
2     PRINT(p->data)
3     traversePreorder(p->left)
4     traversePreorder(p->right)
5  END IF
END traversePreorder

ALGORITHM traverseInorder(VAL p POINTER to node)
1  IF (p ≠ null)
2     traverseInorder(p->left)
3     PRINT(p->data)
4     traverseInorder(p->right)
5  END IF
END traverseInorder

ALGORITHM traversePostorder(VAL p POINTER to node)
1  IF (p ≠ null)
2     traversePostorder(p->left)
3     traversePostorder(p->right)
4     PRINT(p->data)
5  END IF
END traversePostorder

traverse(n) is a menu: 1 = preorder, 2 = inorder, 3 = postorder. The base case is p = null (no node: do nothing). Same pattern as the array version, but "go left / go right" follows pointers instead of computing 2n and 2n + 1.

ALGORITHM test()
1  create()
2  READ(data)
3  LOOP (data ≠ 0)
4     insert(data)
5     READ(data)
6  END LOOP
7  traverse(2)
8  destroy()
END test

C++ implementation

//LinkedListTree.h
#include <iostream>
struct node
{
    int data;
    node *left;
    node *right;
};
class tree
{
    public:
        tree();                          // create()
        ~tree();                         // destroy()
        void insert(int);
        void traverse(int);
    private:
        void removeNode(node *);
        void addNode(node *&, int);      // reference to a pointer
        void traversePreorder(node *);
        void traverseInorder(node *);
        void traversePostorder(node *);
        node *root;
};

tree::tree() { root = 0; }               // sets to null
tree::~tree() { removeNode(root); }
void tree::removeNode(node *p)
{
    if (p)
    {
        removeNode(p->left);
        removeNode(p->right);
        delete p;
    }
}
void tree::insert(int d) { addNode(root, d); }
void tree::addNode(node *&p, int d)
{
    if (p == 0)
    {
        p = new node;
        p->data = d;
        p->left = 0;
        p->right = 0;
    }
    else
        if (d < p->data)
            addNode(p->left, d);
        else
            addNode(p->right, d);
}
void tree::traverse(int n)
{
    switch (n)
    {
        case 1: traversePreorder(root);  break;
        case 2: traverseInorder(root);   break;
        case 3: traversePostorder(root); break;
    }
}
void tree::traversePreorder(node *p)
{
    if (p != 0)
    {
        std::cout << p->data << endl;
        traversePreorder(p->left);
        traversePreorder(p->right);
    }
}
void tree::traverseInorder(node *p)
{
    if (p != 0)
    {
        traverseInorder(p->left);
        std::cout << p->data << endl;
        traverseInorder(p->right);
    }
}
void tree::traversePostorder(node *p)
{
    if (p != 0)
    {
        traversePostorder(p->left);
        traversePostorder(p->right);
        std::cout << p->data << endl;
    }
}
CodeMeaning
node *&pA reference to a pointer (read right to left: p is a reference to a node pointer). The function can change the caller's pointer, so p = new node; really attaches the new node to the tree. This is the REF of the pseudocode.
if (p) / if (p != 0)Non-null test: a pointer is "true" when it is not 0.
switch (n) { case 1: ... break; }Choose the branch matching n; break stops execution falling into the next case.

Array-based vs linked list-based tree

Array-basedLinked list-based
Child lookupComputed: 2n and 2n + 1Follow the left / right pointer
MemoryNeeds 2h+1 slots; wastes a lot if unbalancedOnly the nodes that exist (plus two pointers each)
Grow / shrinkNoYes
Empty marker0 in the slot (so 0 cannot be stored)null pointer
Good whenBalanced tree, known maximum heightUnknown height or unbalanced; data inserted and removed often

Cost of insert / search in a BST: proportional to the tree's height: about log n if the tree is balanced, up to n if it degenerates into a chain.

8. Tree applications

ApplicationExplanation
Represent hierarchically related dataFor example maintaining folders and files; a land registry.
Represent mathematical expressionsCalled expression trees: every expression divides into operands and an operator. The parent node is the operator and the child nodes are operands (leaves are operands).
Support data compression and encodingCodes can be organised as paths in a tree.
Efficiently search large dynamic sets of dataSee below.

In 3 + 5 × 2 the multiplication sits below the addition because it is done first. Connection with Lesson 6: traversing an expression tree gives the three notations. For the right-hand tree: inorder 3 + 5 × 2 (the usual infix form), preorder + 3 × 5 2 (prefix), postorder 3 5 2 × + (postfix, which the stack evaluator of Lesson 6 can compute: 5 × 2 = 10, 3 + 10 = 13).

Why trees search dynamic data efficiently

  • Binary search on an array needs the array to be sorted. If data is frequently inserted or deleted, every change forces shifting many elements to keep the array sorted: not efficient.
  • In a linked list, insertion and deletion are efficient (only a few addresses change), but searching a linked list is not (you must walk it node by node).
  • A linked list-based binary search tree gets both: inserting or removing data only means changing addresses (very efficient), and searching is quick because each comparison discards a whole subtree. In arrays all elements have to shift for very small changes.
Key takeaways Tree = nodes joined by edges; root, leaves, subtrees; order = max children. Binary tree: order 2. Traversals differ only in where the root is visited: pre (root, L, R), in (L, root, R), post (L, R, root). BST: left < root ≤ right, every subtree a BST; inorder gives sorted data. Array tree: root at 1, children 2n and 2n + 1, 0 = empty, wastes memory if unbalanced. Linked tree: node with data, left, right; root pointer; recursive addNode with a REF pointer.
