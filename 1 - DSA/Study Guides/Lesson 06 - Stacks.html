Stacks

Covers: the stack data structure (LIFO), push / pop and the overflow / underflow errors, the array-based and linked list-based implementations (pseudocode and C++), their trade-offs, and applications: reversing data, converting numbers, parsing brackets, evaluating postfix expressions and backtracking. No prior lecture attendance needed.

Learning outcomes

  • Define the stack data structure
  • Identify the access rule, operations and error conditions of a stack
  • Declare array-based and linked list-based stacks
  • Implement array-based and linked list-based stacks
  • Use stacks to solve real-world problems

1. What is a stack?

DefinitionA linear data structure in which all data additions (push) and removals (pop) are restricted to one end, called the top. The rule is Last In, First Out (LIFO): the item pushed most recently is the first one popped.

The lecture's pictures are a stack of coins, a stack of books and a stack inside a computer, each with the Top marked. Think of a pile of plates: you put a plate on top and take a plate from the top; you never pull one from the middle or bottom.

Operations

OperationWhat it does
push(d)Add item d on the top of the stack.
pop(d)Remove the top item and hand it back.
isFull()Is there no room left? Check before a push (array-based).
isEmpty()Is the stack empty? Check before a pop.
create() / destroy()Set the stack up / release its memory.

Error conditions

ErrorHappens when
OverflowTrying to push an item onto a full stack.
UnderflowAttempting to pop an item from an empty stack.

2. Array-based stack

The stack lives in an array. Conceptually it is a vertical pile; physically it is a row of cells with a top index that tracks the most recent item.

Three variables describe the stack: p (pointer to the array), size (capacity) and top (index of the top item; −1 when empty). The conceptual stack of the slide (a at the bottom, f at the top) is the same data seen vertically.

Pseudocode

global variables
   p POINTER to DATATYPE, size INTEGER, top INTEGER

ALGORITHM create(VAL s INTEGER)
1  size ← s
2  top ← -1
3  p ← ALLOCATE MEMORY DATATYPE[size]
END create

ALGORITHM destroy()
1  RELEASE MEMORY[] p
END destroy

ALGORITHM isFull()
1  IF (top = size - 1)
2     RETURN true
3  ELSE
4     RETURN false
5  END IF
END isFull

ALGORITHM isEmpty()
1  IF (top = -1)
2     RETURN true
3  ELSE
4     RETURN false
5  END IF
END isEmpty

ALGORITHM push(VAL d DATATYPE)
1  IF (isFull())
2     RETURN false           // overflow
3  ELSE
4     top ← top + 1
5     p[top] ← d
6     RETURN true
7  END IF
END push

ALGORITHM pop(REF d DATATYPE)
1  IF (isEmpty())
2     RETURN false           // underflow
3  ELSE
4     d ← p[top]
5     top ← top - 1
6     RETURN true
7  END IF
END pop
  • push: move top up one, then store. pop: read the item, then move top down.
  • Both return true/false so the caller knows whether the operation succeeded (false = overflow / underflow).
  • pop does not erase the cell; the cell is simply considered free again and is overwritten by the next push.

Test algorithm

ALGORITHM test()
1  create(stackSize)
2  READ(data)
3  LOOP (data ≠ endOfData AND push(data))
4     READ(data)
5  END LOOP
6  LOOP (pop(data))
7     PRINT(data)
8  END LOOP
9  destroy()
END test

It reads data and pushes it until the end marker is read or the stack is full (push returned false), then pops and prints everything. The output is the input in reverse order.

C++ implementation

Header file ArrayStack.h: the class bundles the data (size, top, p) with the operations. public members can be used by any program; private ones (isEmpty, isFull and the data) are hidden inside the class.

//ArrayStack.h
class stack
{
    public:
        stack(int);        // constructor: the create() operation
        ~stack();          // destructor:  the destroy() operation
        int push(char);
        int pop(char &);   // reference parameter: pop can hand the item back
    private:
        int isEmpty();
        int isFull();
        int size, top;
        char *p;
};

Source file: the member functions (stack:: says "this function belongs to class stack").

stack::stack(int s)
{
    size = s; top = -1;
    p = new char[size];          // allocates memory
}
stack::~stack()
{
    delete[] p;                  // releases memory
}
int stack::isFull()  { return (top == size - 1) ? 1 : 0; }
int stack::isEmpty() { return (top == -1) ? 1 : 0; }

int stack::push(char d)          int stack::pop(char &d)
{                                {
    if (isFull())                    if (isEmpty())
        return 0;                        return 0;
    else                             else
    {                                {
        p[++top] = d;                    d = p[top--];
        return 1;                        return 1;
    }                                }
}                                }
CodeMeaning
p[++top] = d;Pre-increment: add 1 to top first, then store at the new top. Same as top = top + 1; p[top] = d;.
d = p[top--];Post-decrement: use the current top, then subtract 1. Same as d = p[top]; top = top - 1;.
int pop(char &d)d is a reference parameter, so assigning to it changes the caller's variable (the REF of the pseudocode).
constructor / destructorRun automatically when the stack object is created / goes out of scope.

Test program TestArrayStack.cpp:

#include <iostream>
#include "ArrayStack.h"
int main()
{
    const int stackSize = 10;
    stack s(stackSize);
    char data;
    std::cin >> data;
    while (data != '.' && s.push(data))
        std::cin >> data;
    std::cout << std::endl;
    while (s.pop(data))
        std::cout << data;
    return 0;
}

Typing abc. prints cba. Because && is short-circuit, s.push(data) is only evaluated when data is not '.'.

Drawback of the array-based stackIt needs a predefined maximum capacity, even if the whole capacity is not used. With static arrays the capacity is fixed at compile time; with dynamic arrays memory is allocated at run time but the capacity is still fixed after allocation. This wastes memory in most cases. The waste can be avoided with a linked list that grows and shrinks during run time.

3. Linked list-based stack

Each item lives in its own node that holds the data and a pointer to the node below it. A single pointer top points at the head node; the bottom node's next is null.

No size or full check is needed: a node is allocated whenever an item is pushed and released when it is popped, so the stack is as big as the data it holds.

Pseudocode

TYPE node
   data DATATYPE
   next POINTER to node
END node
global variables
   top POINTER to node

ALGORITHM create()
1  top ← null
END create

ALGORITHM destroy()
1  LOOP (top ≠ null)
2     p ← top
3     top ← top->next
4     RELEASE MEMORY p
5  END LOOP
END destroy

ALGORITHM isEmpty()
1  IF (top = null)
2     RETURN true
3  ELSE
4     RETURN false
5  END IF
END isEmpty

ALGORITHM push(VAL d DATATYPE)
1  p ← top
2  top ← ALLOCATE MEMORY node
3  top->data ← d
4  top->next ← p
END push

ALGORITHM pop(REF d DATATYPE)
1  IF (isEmpty())
2     RETURN false
3  ELSE
4     d ← top->data
5     p ← top
6     top ← top->next
7     RELEASE MEMORY p
8     RETURN true
9  END IF
END pop

top->data means "go to the node top points to and take its data" (same as (*top).data).

How push and pop move the pointers

In the lecture's picture of the six-item stack (a at the bottom, f on top), top points at f after f has been pushed. After one pop it points at e again, and f's node has been released. The bottom node a holds a null (0) in its next.

Push order matters: save the old top first (p ← top), then create the new node, then link it. If you moved top before saving it you would lose the rest of the stack.

Test algorithm

ALGORITHM test()
1  create()
2  READ(data)
3  LOOP (data ≠ endOfData)
4     push(data)
5     READ(data)
6  END LOOP
7  LOOP (pop(data))
8     PRINT(data)
9  END LOOP
10 destroy()
END test

Here push never fails (there is no capacity limit), so the loop only checks the end marker.

C++ implementation

//LinkedListStack.h
struct node
{
    char data;
    node *next;
};
class stack
{
    public:
        stack();            // create()
        ~stack();           // destroy()
        void push(char);
        int pop(char &);
    private:
        int isEmpty();
        node *top;
};

stack::stack()  { top = 0; }              // sets to null
stack::~stack()
{
    while (top)
    {
        node *p = top;
        top = top->next;
        delete p;                          // releases memory
    }
}
int stack::isEmpty() { return (top == 0) ? 1 : 0; }

void stack::push(char d)
{
    node *p = top;
    top = new node;                        // allocates memory
    top->data = d;
    top->next = p;
}
int stack::pop(char &d)
{
    if (isEmpty())
        return 0;
    else
    {
        d = top->data;
        node *p = top;
        top = top->next;
        delete p;
        return 1;
    }
}
//TestLinkedListStack.cpp
#include <iostream>
#include "LinkedListStack.h"
int main()
{
    stack s;
    char data;
    std::cin >> data;
    while (data != '.')
    {
        s.push(data);
        std::cin >> data;
    }
    std::cout << std::endl;
    while (s.pop(data))
        std::cout << data;
    return 0;
}

4. Stack applications

ApplicationWhy a stack fits
Reversing dataPush everything, pop everything: it comes out backwards.
Converting numbersDigits are produced in reverse order; popping puts them right.
Parsing dataMatch the most recent opening symbol with each closing symbol.
Converting mathematical expressionsHold operators until their operands are done.
Evaluating mathematical expressionsHold operands until an operator needs them.

4.1 Reversing data

Problem: accept a null-terminated string (text) and print it in reverse order. (In C++ a char array's last element is automatically the null character '\0'.)

ALGORITHM reverseText(REF text[] CHAR)
1  s ← stack()
2  i ← 0
3  ch ← text[i]
4  LOOP (ch ≠ '\0' AND s.push(ch))
5     i ← i + 1
6     ch ← text[i]
7  END LOOP
8  LOOP (s.pop(ch))
9     PRINT ch
10 END LOOP
END reverseText

Using s.push(ch) inside the loop condition is much safer than a plain LOOP (ch ≠ '\0') with a separate push, because push reports failure when the stack is full. Trace for "CAT": push C, A, T; pop T, A, C; prints TAC.

Real uses of reversing: the undo feature of editors, and the back button in a browser. These are implemented with a stack.

4.2 Converting numbers (decimal to binary)

Problem: accept a decimal number, convert it to binary, print the binary number. Repeatedly divide by 2; the remainders are the bits, but they come out last bit first, so push them and pop to print in the correct order.

ALGORITHM dtob(n INTEGER)
1  s ← stack()
2  LOOP (n > 0)
3     bit ← n MOD 2
4     s.push(bit)
5     n ← n / 2
6  END LOOP
7  LOOP (s.pop(bit))
8     PRINT bit
9  END LOOP
10 s.destroy()
END dtob
nn MOD 2 (pushed)n / 2

1206

Pushed: 1, 0, 0, 1, 1 (the last 1 is on top). Popping prints 11001, which is 25 in binary.

4.3 Parsing data (bracket matching)

Problem: accept a mathematical expression and check whether there is any bracket mismatch. Example: (a+b)×c= stored in a char array that ends with =.

ALGORITHM isBracketOk(REF exp[] CHAR)
1  s ← stack()
2  i ← 0
3  ch ← exp[i]
4  LOOP (ch ≠ '=')
5     IF (ch = '(')
6        s.push(ch)
7     ELSE
8        IF (ch = ')')
9           IF (NOT s.pop(ch))
10             RETURN false
11          END IF
12       END IF
13    END IF
14    i ← i + 1
15    ch ← exp[i]
16 END LOOP
17 IF (s.pop(ch))
18    RETURN false
19 ELSE
20    RETURN true
21 END IF
END isBracketOk

Idea: push every opening bracket; on a closing bracket pop one (if the pop fails there is a closing bracket with no opener: mismatch); at the end the stack must be empty (a leftover opener means mismatch). A first draft of the same idea: read data; if opening bracket push; if closing bracket pop; at the end print "No mismatch" if the stack is empty, else "Mismatch".

ExpressionResultWhy
(a+b)*c=OKpush, then pop on ')': empty at the end
(a+b*c=Mismatchstack still holds '(' at the end
a+b)*c=Mismatchpop on ')' with an empty stack fails

4.4 Evaluating mathematical expressions (postfix)

In postfix form the operators appear after their operands: 1 2 + means 1 + 2 = 3. There are no brackets and no precedence rules to apply. Problem (lecture prototype question 1): read a postfix expression and print its result when the user enters the equality operator =; for example 12+34+*= prints 21.

  • Suitable data structure: an integer stack.
  • Assumptions: operands are single digits (0–9); operators are + − * /; the expression is valid.
ALGORITHM evaluatePostfix()
1  create an empty integer Stack
2  READ character
3  LOOP (character not equals to =)
4     IF (character is an operator)
5        operand2 ← POP from Stack
6        operand1 ← POP from Stack
7        result ← operand1 operator operand2
8        PUSH result onto Stack
9     ELSE
10       convert character to integer
11       push integer into stack
12    END IF
13    READ character
14 END LOOP
15 evaluatedResult ← POP from Stack
16 PRINT evaluatedResult
END evaluatePostfix

Note the order: the first pop is operand2, the second is operand1 (matters for − and /). Trace for 12+34+*= (that is (1 + 2) × (3 + 4)):

ReadActionStack (bottom → top)
1push 11
2push 21 2
+operand2 = 2, operand1 = 1, push 1 + 23
3push 33 3
4push 43 3 4
+operand2 = 4, operand1 = 3, push 3 + 43 7
*operand2 = 7, operand1 = 3, push 3 × 721
=pop and print(empty): prints 21

4.5 Converting mathematical expressions (infix to postfix)

People write infix (operator between operands: 3 + 5 * 2); the postfix evaluator above needs postfix (3 5 2 * +). The lecture lists this conversion as a stack application but gives no algorithm; the standard idea is:

  • Operands go straight to the output.
  • Operators wait on a stack; before pushing an operator, pop (to the output) any operator on top that has higher or equal precedence.
  • An opening bracket is pushed; a closing bracket pops operators to the output until the opening bracket.
  • At the end pop everything left to the output.

Example: 3 + 5 * 2 → output 3; push +; output 5; * has higher precedence than +, so push it; output 2; pop * then +: 3 5 2 * +. Evaluate: 5 × 2 = 10, 3 + 10 = 13.

4.6 Backtracking

When searching for a solution (a path through a maze, a move in a game) you keep going forward and push each decision on a stack. At a dead end you pop the last decision and try the next alternative. The stack remembers exactly the path taken, in the order needed to retrace it. The undo feature and the browser back button work the same way.

Key takeaways A stack is a linear structure with LIFO access at the top: push adds, pop removes. Overflow = push on a full stack; underflow = pop on an empty stack. Array-based: p, size, top (−1 = empty), fixed capacity. Linked: nodes with data and next, only top, no fixed capacity. Applications: reverse, convert numbers, parse brackets, evaluate and convert expressions, backtrack.

Recommended reading from the slides: Gilberg and Forouzan, Data Structures: A Pseudocode Approach with C, Chapter 3, pp. 102–125; Deitel and Deitel, C++ How to Program, Chapter 21, pp. 1038–1039.

Written questions

W1. Define a stack and state its access rule, operations and error conditions.

A stack is a linear data structure in which all data additions (push) and removals (pop) are restricted to one end, the top. Access rule: Last In First Out (LIFO). Operations: push() and pop() (plus create, destroy, isEmpty and, array-based, isFull). Error conditions: overflow (pushing onto a full stack) and underflow (popping from an empty stack).

W2. Write the pseudocode for create, push and pop of an array-based stack. 
ALGORITHM create(VAL s INTEGER)
1 size ← s
2 top ← -1
3 p ← ALLOCATE MEMORY DATATYPE[size]
END create

ALGORITHM push(VAL d DATATYPE)
1 IF (isFull())
2    RETURN false
3 ELSE
4    top ← top + 1
5    p[top] ← d
6    RETURN true
7 END IF
END push

ALGORITHM pop(REF d DATATYPE)
1 IF (isEmpty())
2    RETURN false
3 ELSE
4    d ← p[top]
5    top ← top - 1
6    RETURN true
7 END IF
END pop

isFull: top = size − 1. isEmpty: top = −1.

W3. Write the push and pop algorithms of a linked list-based stack and explain why no isFull is needed. 
ALGORITHM push(VAL d DATATYPE)
1 p ← top
2 top ← ALLOCATE MEMORY node
3 top->data ← d
4 top->next ← p
END push

ALGORITHM pop(REF d DATATYPE)
1 IF (isEmpty())
2    RETURN false
3 ELSE
4    d ← top->data
5    p ← top
6    top ← top->next
7    RELEASE MEMORY p
8    RETURN true
9 END IF
END pop

No isFull is needed because each push allocates a new node, so the stack has no fixed capacity.

W4. Compare array-based and linked list-based stacks.

The array-based stack needs a predefined maximum capacity (fixed at compile time for static arrays; fixed after allocation for dynamic arrays) even if the whole capacity is not used, so it wastes memory in most cases and can overflow. The linked list-based stack grows and shrinks dynamically at run time, using memory only for the items present (plus one pointer per node). Both give O(1) push and pop.

W5. Write an algorithm that reads a postfix expression ended by '=' and prints its value. Evaluate 12+34+*=.

Use an integer stack. Read characters until '='. If the character is an operator: operand2 ← pop, operand1 ← pop, push (operand1 operator operand2). Otherwise convert the digit to an integer and push it. At '=' pop and print the result (assuming single-digit operands and a valid expression).

12+34+*=: push 1, 2; '+' gives 3; push 3, 4; '+' gives 7; '*' pops 7 and 3 and pushes 21; prints 21.

W6. Write an algorithm using a stack to check an expression for bracket mismatch.

Push each '(' ; on ')' try to pop: if the pop fails (empty stack) return false; at the end of the expression, if the stack still holds an item (a pop succeeds) return false, otherwise true. See the isBracketOk pseudocode in the lesson.

W7. Explain with an algorithm how a stack converts a decimal number to binary. Show 25.

Repeat: bit ← n MOD 2; push bit; n ← n / 2 until n = 0. Then pop and print each bit. The bits are generated least-significant first and the stack reverses them. For 25: pushed 1, 0, 0, 1, 1; popped output 11001.
