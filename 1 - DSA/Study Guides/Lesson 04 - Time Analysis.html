Time Analysis

Covers: best, average and worst case; linear, logarithmic, n log n, quadratic, polynomial, exponential and factorial growth; asymptotic notation and Big-O (with worked proofs); and the analysis of sequential search, binary search, selection sort and bubble sort. No prior lecture attendance needed.

Learning outcomes

  • Describe the best, average and worst case running times of an algorithm
  • Explain linear, logarithmic, linear logarithmic, quadratic, polynomial, exponential and factorial time functions
  • Express a running time in asymptotic notation
  • Express the worst case running time in Big-O notation
  • Analyse classical searching and sorting algorithms

1. Best, worst and average case

For the same n an algorithm can take different amounts of time depending on the data. We therefore talk about three running times.

CaseMeaningT(n) is
Best caseTime taken when the best possible thing happens.the minimum over the instance characteristic n
Worst caseTime taken when the worst possible thing happens.the maximum over n
Average caseTime taken for some probability distribution of the instance characteristic n.the average over n (more complicated to analyse)

Example: in a sequential search, the best case is finding the target at the first position; the worst case is finding it last (or not at all).

2. Functions of time complexity

  • The time complexity of an algorithm is a function of n.
  • n is the instance characteristic, so always n ≥ 0.
  • Time cannot be negative, so T(n) ≥ 0 for all n.
  • Why do we care? We want to know whether the algorithm becomes reasonably or incredibly slow when the problem grows.

Below, the right-hand column counts how many times each line runs (loop tests run one more time than the body).

Linear (example 1)

                         times
1  i ← 1                 1
2  LOOP (i <= n)          n + 1
3     i ← i + 1          n
4  END LOOP
        T(n) = 2n + 2      (like y = mx + c: a straight line)

The loop counter grows by adding 1, so the body runs n times.

Logarithmic (example 2)

                         times
1  i ← 1                 1
2  LOOP (i <= n)       log2(n) + 1
3     instruction 1     log2(n)
4     instruction 2     log2(n)
5     instruction 3     log2(n)
6     instruction 4     log2(n)
7     i ← i * 2        log2(n)
8  END LOOP
        T(n) = 6 log2(n) + 2

Here the counter is multiplied by 2, so i takes the values 1, 2, 4, 8, ... After k passes i = 2k. The loop stops when 2k exceeds n, i.e. at the terminating point 2maxIterations = n, so maxIterations = log2(n). Doubling the input adds only one more pass.

Recall: logx(m) = y means xy = m. Binary search (below) behaves like this.

Two nested loops that both run n times: n × n = n2.

3. Asymptotic notation

Asymptotic notation expresses an algorithm's running time as its growth rate by dropping the less significant terms and the constant coefficients. The growth rate says how fast the function grows with the input size. We do this to make the equations simple so that algorithms can be compared easily.

Why dropping terms is safe: T(n) = 3n2 + 50n + 200

For n ≥ 20 the 3n2 term is the more significant one. Now compare n2 alone with 50n + 200:

For n > 53, n2 dominates, so the constant coefficient 3 can be ignored. Also (50n + 200) / (3n2) → 0 as n → ∞: the smaller terms become irrelevant. So this T(n) grows like n2.

4. Big-O notation

Big-O is the asymptotic notation for the worst case running time of an algorithm: an upper bound on growth.

DefinitionFor T(n) ≥ 0 and f(n) ≥ 0, T(n) is said to be O(f(n)) ("big oh of f of n") if there exist positive constants c and n0 such that T(n) ≤ c · f(n) for all n ≥ n0.

How to prove T(n) = O(f(n)): replace each lower term by something bigger that contains the leading term, then find c and n0.

Example 1: T(n) = 3n + 2

3n + 2 ≤ 3n + n = 4n        for n ≥ 2     (since 2 ≤ n)
So T(n) ≤ 4n = c · f(n) with c = 4, n₀ = 2        ⇒ T(n) = O(n)
nT(n) = 3n + 24nT ≤ 4n ?
154no (so n₀ is not 1)

Example 2: T(n) = 10n2 + 4n + 2

10n² + 4n + 2 ≤ 10n² + 5n     for n ≥ 2   (since 2 ≤ n)
                  ≤ 10n² + n²     for n ≥ 5   (since 5n ≤ n²)
                   = 11n²
c = 11, n₀ = 5                                        ⇒ T(n) = O(n²)

Example 3: T(n) = 4n3 + 2n2

4n³ + 2n² ≤ 4n³ + n³ = 5n³    for n ≥ 2   (since 2n² ≤ n³)
c = 5, n₀ = 2                                        ⇒ T(n) = O(n³)

Example 4: T(n) = ½(n + 1)

½(n + 1) ≤ ½(n + n) = n               for n ≥ 1
c = 1, n₀ = 1                                        ⇒ T(n) = O(n)

(This is the average-case count of a sequential search.)

ShortcutKeep only the fastest-growing term and drop its coefficient: 3n + 2 → O(n); 10n² + 4n + 2 → O(n²); 4n³ + 2n² → O(n³); 6 log n + 2 → O(log n); 2n log n + 4n + 2 → O(n log n). The proofs above show why this is allowed. Ranking: O(log n) is best, O(n) better, O(n²) worst of these three.

5. Searching algorithms

Sequential (linear) search

ALGORITHM Search(REF list[] INTEGER, size INTEGER, target INTEGER)
   Searches target in unordered list and returns location if found, else -1
1  location ← -1
2  i ← 0
3  LOOP (i < size AND target ≠ list[i])
4     i ← i + 1
5  END LOOP
6  IF (i ≠ size)
7     location ← i
8  END IF
9  RETURN location
END Search

Works on an unordered list: examine each element from the start until the target is found or the list ends. Key operation: the comparison target ≠ list[i].

CaseComparisonsBig-O
Best (target at index 0)1O(1)
Worst (last element or absent)nO(n)
Average (present, equally likely anywhere)(n + 1) / 2O(n)

Binary search

ALGORITHM Search(REF list[] INTEGER, size INTEGER, target INTEGER)
   Searches target in ordered list and returns location if found, else -1
1  first ← 0
2  last ← size - 1
3  LOOP (first ≤ last)
4     mid ← (first + last) / 2
5     IF (target > list[mid])
6        first ← mid + 1
7     ELSE IF (target < list[mid])
8        last ← mid - 1
9     ELSE
10       first ← last + 1
11    END IF
12 END LOOP
13 IF (target ≠ list[mid])
14    mid ← -1
15 END IF
16 RETURN mid
END Search

Requirement: the list must be sorted. Idea: look at the middle element. If the target is bigger, it can only be in the right half; if smaller, in the left half; if equal, done. Each step throws away half of what is left. (Integer division: (first + last) / 2 drops the fraction. Line 10 forces the loop to end once the target is found. Lines 13–14 turn "not found" into −1.)

Trace: list = {2, 5, 8, 12, 16, 23, 38}, target = 23 (indexes 0 to 6)

firstlastmidlist[mid]Decision
0631223 > 12: first ← 4
46523equal: stop, return 5

Not found: target = 10 in the same list: mid = 3 (12): 10 < 12, last ← 2; mid = 1 (5): 10 > 5, first ← 2; mid = 2 (8): 10 > 8, first ← 3; now first > last, the loop ends; list[mid] = 8 ≠ 10 so return −1.

CaseIterationsBig-O
Best (target is the first middle)1O(1)
Worst (absent, or found last)the range halves each time: about log2(n) + 1O(log n)

For 1,000,000 elements binary search needs about 20 steps; sequential search up to 1,000,000. Binary search is more efficient than sequential search, but only on a sorted list. If data is inserted or deleted often, keeping an array sorted means shifting elements (see Trees in Lesson 8).

6. Sorting algorithms

Selection sort

ALGORITHM Sort(REF list[] INTEGER, size INTEGER)
   Sorts integers in array
1  i ← 0
2  LOOP (i < size - 1)
3     smallest ← i
4     j ← i + 1
5     LOOP (j < size)
6        IF (list[j] < list[smallest])
7           smallest ← j
8        END IF
9        j ← j + 1
10    END LOOP
11    Swap(list[smallest], list[i])
12    i ← i + 1
13 END LOOP
END Sort

Idea: for each position i, find the smallest element in the unsorted part (positions i..end) and swap it into position i. The sorted part grows from the left.

Trace {64, 25, 12, 22, 11}:

iSmallest found in positions i..4Array after swap
011 (index 4)11, 25, 12, 22, 64
112 (index 2)11, 12, 25, 22, 64
222 (index 3)11, 12, 22, 25, 64
325 (already in place)11, 12, 22, 25, 64

Analysis. Key operation: the comparison list[j] < list[smallest]. For each i the inner loop makes (n − 1 − i) comparisons, so the total is (n−1) + (n−2) + ... + 1 = n(n − 1)/2, whatever the data (it cannot stop early). That is (n² − n)/2, so O(n²) in best, average and worst cases. It does exactly n − 1 swaps.

Bubble sort

ALGORITHM Sort(REF list[] INTEGER, size INTEGER)
   Sorts integers in array
1  i ← 1
2  LOOP (i < size)
3     j ← 0
4     LOOP (j < size - i)
5        IF (list[j] > list[j + 1])
6           Swap(list[j], list[j + 1])
7        END IF
8        j ← j + 1
9     END LOOP
10    i ← i + 1
11 END LOOP
END Sort

Idea: repeatedly compare neighbouring elements and swap them if they are in the wrong order. After each pass the largest remaining value has "bubbled" to the end, so the inner loop gets one shorter each time.

Trace {5, 1, 4, 2, 8}:

Pass (i)Comparisons (j)Array after the pass
1(5,1) swap; (5,4) swap; (5,2) swap; (5,8) no1, 4, 2, 5, 8
2(1,4) no; (4,2) swap; (4,5) no1, 2, 4, 5, 8
3(1,2) no; (2,4) no1, 2, 4, 5, 8
4(1,2) no1, 2, 4, 5, 8

Analysis. Key operation: the comparison list[j] > list[j+1]. Pass i makes (n − i) comparisons, for i = 1 to n − 1: (n−1) + (n−2) + ... + 1 = n(n − 1)/2 comparisons, always (this version has no early exit; the trace above shows 4 + 3 + 2 + 1 = 10 for n = 5). The number of swaps varies: 0 if already sorted, up to n(n−1)/2 if in reverse order. Overall O(n²).

Key takeaways (1) Count how many times lines run, as a function of n. (2) Keep the dominant term, drop constants: that is asymptotic notation. (3) Big-O is the worst-case upper bound T(n) ≤ c f(n) for n ≥ n0. (4) Single loop adding → n; loop doubling → log n; nested loops → n2 or n log n.

Written questions

W1. Explain best case, worst case and average case running times.

Best case: the time taken when the best possible thing happens; T(n) is the minimum over n. Worst case: the time when the worst possible thing happens; T(n) is the maximum over n. Average case: the time for some probability distribution of the instance characteristic; T(n) is the average over n. Example: sequential search is 1 comparison at best, n at worst and (n + 1)/2 on average.

W2. Determine T(n) for a loop i ← 1; LOOP (i <= n) ... i ← i * 2 whose body has 4 instructions, and say which function type it is.

The counter doubles: after k passes i = 2k, so the loop runs log2(n) times (2maxIterations = n). Lines: 1 (init) + (log n + 1) (test) + 4 log n (instructions) + log n (i ← i * 2) = 6 log2(n) + 2. It is a logarithmic function.

W3. Define asymptotic notation and show that 3n2 + 50n + 200 grows like n2.

Asymptotic notation expresses running time as a growth rate by dropping the less significant terms and constant coefficients. For n ≥ 20, 3n2 ≥ 50n + 200 (n = 20: 1200 = 1200), and for n ≥ 54, n2 ≥ 50n + 200 (n = 54: 2916 ≥ 2900). Also (50n + 200)/(3n2) → 0 as n → ∞. So the lower terms and the coefficient do not matter: growth rate n2.

W4. State the definition of Big-O and prove that T(n) = 10n2 + 4n + 2 is O(n2).

Definition: for T(n) ≥ 0 and f(n) ≥ 0, T(n) = O(f(n)) if there exist positive constants c and n0 such that T(n) ≤ c f(n) for all n ≥ n0.

Proof: 10n2 + 4n + 2 ≤ 10n2 + 5n for n ≥ 2 (since 2 ≤ n); 10n2 + 5n ≤ 10n2 + n2 = 11n2 for n ≥ 5 (since 5n ≤ n2). So T(n) ≤ 11n2 with c = 11, n0 = 5, hence T(n) = O(n2).

W5. Compare sequential search and binary search (requirements, worst case, trace for finding 23 in {2, 5, 8, 12, 16, 23, 38}).

Sequential search works on an unordered list and checks elements one by one: worst case n comparisons, O(n). Binary search needs a sorted list and halves the range each time: worst case about log2(n) + 1 iterations, O(log n). Trace for 23: first = 0, last = 6, mid = 3 (12): 23 > 12 so first = 4; mid = 5 (23): found, return 5.

W6. Trace selection sort on {64, 25, 12, 22, 11} and give its time complexity.

i = 0: smallest 11, swap → 11, 25, 12, 22, 64. i = 1: smallest 12, swap → 11, 12, 25, 22, 64. i = 2: smallest 22, swap → 11, 12, 22, 25, 64. i = 3: 25 already in place. Comparisons: (n − 1) + ... + 1 = n(n − 1)/2 = 10 for n = 5, always: O(n2) in all cases; n − 1 swaps.

W7. Trace bubble sort on {5, 1, 4, 2, 8} and give its time complexity.

Pass 1: (5,1) swap, (5,4) swap, (5,2) swap, (5,8) no → 1, 4, 2, 5, 8. Pass 2: (1,4) no, (4,2) swap, (4,5) no → 1, 2, 4, 5, 8. Pass 3: no swaps. Pass 4: no swaps. Comparisons 4 + 3 + 2 + 1 = 10 = n(n − 1)/2, so O(n2).
