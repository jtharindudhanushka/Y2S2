Time Complexity

Covers: what time complexity is, why it matters, what it depends on, T(n) = c + TA(n), and the two ways to work it out: operation count and step count (plus programming instrumentation). No prior lecture attendance needed.

Learning outcomes

  • Define the time complexity of an algorithm
  • Explain why analysing time complexity is important
  • Identify the factors time complexity depends on
  • Determine time complexity with the operation count and step count approaches
  • Analyse the time complexity of a given algorithm

1. What is time complexity?

Time complexity is the amount of time that a program written with a particular algorithm needs to run to completion. Like space complexity (Lesson 2) it is part of performance analysis.

Not secondsTime complexity does not measure actual seconds. It counts how much work the algorithm does as a function of the input size, so the answer does not change from one computer to another.

Why are we interested?

ReasonMeaning
Real-time responseSome problems need an answer in real time; some systems must respond instantly.
Pick the faster oneWhen several algorithms solve the same problem, prefer the program that runs fast.
Avoid time-outGuarantee users that the program will run to completion without timing out, especially for large data.

2. What does it depend on?

Time complexity depends on the same factors as space complexity, and like space complexity some factors are sensitive to the problem being solved (for example, a program that sorts an array of n integers). It is therefore a function of n, the instance characteristic (the size of the problem).

FactorNote
Input size nThe main factor. More data means more work.
Hardware and softwareWhy raw seconds are unreliable; counting steps avoids this.
Types of operationsArithmetic, comparison, assignment... cost differs.

3. The formula

T(n) = c + TA(n)

  • c = insensitive (constant) time contribution: does not depend on the input size.
  • TA(n) = sensitive time contribution of algorithm A: does depend on the instance characteristic n.

This is the same shape as S(n) = c + SA(n) from Lesson 2.

5. Operation count approach

A key operation is the most time-consuming operation; other operations are ignored. Typical choices: comparisons, additions, multiplications. We estimate T(n) by counting how many times the key operation runs.

Example 1: max

ALGORITHM max(REF a[] INTEGER, n INTEGER)
   locates max integer in array and returns index
1  i ← 0
2  c ← 1
3  LOOP (c < n)
4     IF (a[i] < a[c])
5        i ← c
6     END IF
7     c ← c + 1
8  END LOOP
9  RETURN i
END max

Trace with a = {16, 11, 2, 19, 6}, n = 5. i remembers the index of the biggest value so far; c is the index being examined.

ca[i] < a[c] ?Resulti after
116 < 11no0

316 < 19yes: i ← 33
419 < 6no3

The function returns 3 (index of 19).

Choosing the key operation. The comparison a[i] < a[c] is the key operation: to perform it the computer fetches i, c, a[i] and a[c] from memory and compares them, which costs more than the other lines. How many times does it run? c takes the values 1, 2, ..., n−1, so

T(n) = n − 1, regardless of the data (best, worst and average are all the same).

Example 2: find

ALGORITHM find(REF a[] INTEGER, n INTEGER, x INTEGER)
   finds x in array and returns index if found, else -1
1  i ← -1
2  c ← 0
3  LOOP (c < n AND x ≠ a[c])
4     c ← c + 1
5  END LOOP
6  IF (c ≠ n)
7     i ← c
8  END IF
9  RETURN i
END find

It scans from the start and stops as soon as x = a[c] or the end is reached. If the loop stopped before the end (c ≠ n), x was found at index c.

Key operation: the comparison x ≠ a[c]. Its count depends on where x is, so now the best, worst and average cases differ (this is studied in depth in Lesson 4):

CaseWhenComparisons
Bestx is at index 01
Worstx is at the last index, or not in the arrayn
Averagex is present and equally likely at any position: (1 + 2 + ... + n) / n(n + 1) / 2

The average works out as (1/n) · n(n+1)/2 = (n+1)/2, using 1 + 2 + ... + n = n(n+1)/2.

6. Step count approach

T(n) is estimated by accounting for the time spent on all program steps, that is, the number of steps the program takes to complete. We count how many times each numbered line executes and add them up.

Counting rule for loopsA LOOP (c < n) line is evaluated n + 1 times if the body runs n times: it is true n times and false once (the exit test). Example n = 3: 0<3, 1<3, 2<3 true, 3<3 false: 4 evaluations. The body lines run n times each.

Algorithm 1: iterative sum

ALGORITHM sum(REF a[] INTEGER, n INTEGER)
   returns sum of n integers in array
                              times
1  s ← 0                      1
2  c ← 0                      1
3  LOOP (c < n)                 n + 1
4     s ← s + a[c]            n
5     c ← c + 1               n
6  END LOOP                    (not counted)
7  RETURN s                      1
END sum
                  T(n) = 3n + 4

Check with num = {3, 6, 1}, n = 3: s goes 0 → 3 → 9 → 10 and c goes 1, 2, 3 (three body executions), so T(3) = 3×3 + 4 = 13.

Algorithm 2: recursive sum

ALGORITHM sum(REF a[] INTEGER, n INTEGER)
   returns sum of n integers in array
                                    times
1  IF (n > 0)                        n + 1
2     RETURN a[n-1] + sum(a, n-1)     n
3  END IF
4  RETURN 0                            1
END sum
                  T(n) = 2n + 2

The IF is tested for n, n−1, ..., 1 (true, n times) and finally 0 (false): n + 1 tests. The recursive line runs n times; the base-case RETURN 0 runs once.

7. Programming instrumentation

Programming instrumentation means modifying a program by adding extra code to collect information about its execution. To check a step count, add a global counter g and increment it wherever a step executes. After the run, g equals T(n).

Program 1 (instrumented iterative sum)

int g = 0;                 // global step counter
int sum(int a[], int n)
{
    int s = 0;
    g++;                   // declaration and initialisation of s
    int c = 0;
    g++;                   // declaration and initialisation of c
    while (c < n)
    {
        g++;               // evaluation of c < n  (true)
        s += a[c];
        g++;               // addition and assignment s += a[c]
        c++;
        g++;               // increment c++
    }
    g++;                   // last evaluation of c < n  (false)
    g++;                   // return s
    return s;
}

Total g = 1 + 1 + n + n + n + 1 + 1 = 3n + 4, matching the step count.

Program 2 (instrumented recursive sum)

int g = 0;
int sum(int a[], int n)
{
    g++;                   // if condition evaluation
    if (n > 0)
    {
        g++;               // addition, recursive call and return
        return a[n-1] + sum(a, n-1);
    }
    g++;                   // return statement
    return 0;
}

The condition is evaluated n + 1 times, the true branch runs n times and the base return once: g = 2n + 2, matching the step count.

Key takeaways Operation count: pick the costly operation, count it (max: T(n) = n − 1). Step count: count every statement (iterative sum: 3n + 4; recursive sum: 2n + 2). Both give a function of n, not seconds. The next lesson turns such functions into growth rates (Big-O).

Written questions

W1. Define time complexity and give three reasons for being interested in it.

Time complexity is the amount of time a program written with a particular algorithm needs to run to completion. Reasons: some problems require a real-time response; we prefer the program that runs fast when several algorithms solve a problem; we must guarantee users that the program completes without time-out.

W2. Explain the two approaches to determining time complexity.

Operation count: identify one or more key operations (those contributing most to time) and count how many times they are performed. Its weaknesses: it does not measure actual execution time and choosing the key operation may be difficult. Step count: estimate T(n) by accounting for the time spent on all program steps, i.e. the number of steps the program takes to complete.

W3. Using the operation count approach, find T(n) for the max algorithm (loop c from 1 to n-1 with IF a[i] < a[c]).

Key operation: the comparison a[i] < a[c], which needs memory fetches of i, c, a[i], a[c] and a comparison. The loop variable c takes the values 1 to n−1, so the comparison is executed n − 1 times: T(n) = n − 1 for all inputs.

W4. Find the step count of the iterative sum algorithm and verify it for n = 3.

Lines: s ← 0 (1), c ← 0 (1), loop test (n + 1), s ← s + a[c] (n), c ← c + 1 (n), RETURN s (1). T(n) = 3n + 4. For n = 3: 13. Check by trace: tests 0<3, 1<3, 2<3, 3<3 = 4; body lines 3 + 3; plus 3 single lines = 13.

W5. Find the step count of the recursive sum algorithm.

IF (n > 0) is evaluated n + 1 times; the recursive RETURN line runs n times; RETURN 0 runs once. T(n) = (n + 1) + n + 1 = 2n + 2.

W6. What is programming instrumentation? Show how it would count steps in a loop.

Modifying a program by adding extra code to collect information about its execution. Declare a global counter g = 0 and write g++ beside each step (declarations, each loop test, the loop body statements, the final failing test, the return). At the end g holds the step count, e.g. 3n + 4 for the iterative sum.
