Introduction to Algorithms

Covers: what an algorithm is, what a program is, pseudocode, and the two ways of judging how efficient an algorithm is. No prior lecture attendance needed.

Learning outcomes

After this lesson you should be able to:

  • Define an algorithm and list the properties of a good one
  • Define a program and list the properties of a good one
  • Write algorithms in pseudocode
  • Explain what "efficiency" means for an algorithm
  • Distinguish performance measurement from performance analysis

1. What is an algorithm?

An algorithm is a finite, well-defined sequence of steps for solving a problem. The lecture's analogy is a recipe: it lists exact steps, in order, that turn inputs (ingredients) into an output (the dish).

Important: one problem can have many algorithms. For example, finding a name in a list can be done by checking every entry from the start, or (if the list is sorted) by repeatedly halving it. Both are correct, but one is much faster. Choosing between them is the whole reason we study efficiency.

Properties of a good algorithm

PropertyMeaningExample of breaking it
CorrectGives the right answer for every valid inputA "find maximum" routine that fails when the max is the first element
Finite, well-defined stepsMade of a limited number of steps, each precise and unambiguous"Add some salt" (how much?) or an infinite list of steps
Produces outputReturns/prints a result, otherwise nothing was solvedA routine that computes a sum but never returns or prints it
TerminatesStops after a finite amount of timeLOOP (true) with no exit condition
EfficientUses as little time and memory as reasonably possibleCorrect, but takes hours where a better method takes milliseconds
Memory aidCorrect, Finite well-defined steps, Output, Terminates, Efficient.

2. What is a program?

A program is an implementation of an algorithm in a programming language (C, Java, Python and so on). The algorithm is the idea; the program is that idea written so a computer can run it.

Properties of a good program

PropertyMeaning
Executes correctlyDoes what the algorithm intends, with no bugs on valid input
Executes efficientlyRuns within the resource constraints (available time, memory, CPU)
Easy to read and understandClear names, layout and comments so others can follow it
Easy to maintainCan be fixed or extended later without breaking everything

3. Pseudocode

Pseudocode means "fake code". It is structured English used to write down an algorithm before (or instead of) coding it.

  • Cannot be compiled or executed
  • No strict syntax rules, so exact wording does not matter as long as the meaning is clear
  • Easy to read and understand
  • Independent of any programming language
  • Designed for humans, not machines

The style used in this course

ElementMeaning
ALGORITHM name (params) ... END nameHeader and footer of the algorithm
REFParameter passed by reference: changes made inside are visible to the caller (used for outputs like index)
PREPrecondition: conditions on the input; what must be true before the algorithm runs
POSTPostcondition: conditions on the output; what is guaranteed to be true after it runs
RETURNDescribes the return value in the header; inside the body it gives the value back and exits
←Assignment, e.g. index ← 0 means "set index to 0"
=Comparison for equality, e.g. target = list[index]
LOOP (condition) ... END LOOPRepeat while the condition is true
IF (condition) ... END IFDo the steps only when the condition is true
Purpose lineOne descriptive line under the header saying what the algorithm does (e.g. "finds target in unordered list")
IndentationStatements are numbered and indented for clarity (bodies of LOOP / IF are indented)
Line numbersEach statement is numbered so it can be referenced and counted later (used in time analysis)

Worked example: linear search

ALGORITHM search (REF list[] INTEGER, size INTEGER,
                  target INTEGER, REF index INTEGER)
   finds target in unordered list
   PRE   list is an array with at least one element
         size is number of elements in list
         target contains integer to find
   POST  if found, index gives matching index
   RETURN true if found, otherwise false
1  index ← 0
2  LOOP (index < size)
3     IF (target = list[index])
4        RETURN true
5     END IF
6     index ← index + 1
7  END LOOP
8  RETURN false
END search

How it works: start at position 0, compare each element to the target, and move one position at a time. If a match is found, return true immediately (and index holds where it was). If the loop runs out of elements, return false.

Trace with list = [7, 3, 9, 5], size = 4, target = 9:

indexindex < size?list[index]= target?Action
0yes7noindex ← 1
1yes3noindex ← 2
2yes9yesRETURN true (index = 2)

With target = 4 nothing matches, index reaches 4, the loop condition fails, and line 8 returns false.

Check against the good-algorithm properties Correct (finds the target if present) · finite steps (at most size iterations) · produces output (true/false plus index) · terminates (index grows every pass) · fine for small lists, though it checks every element in the worst case.

4. Efficiency of an algorithm

Efficiency is the amount of memory and time needed to run a program built on a particular algorithm. We care because when several algorithms solve the same problem, efficiency lets us pick the most appropriate one.

There are two approaches to determining it (performance analysis is the preferred one):

Performance measurementPerformance analysis
IdeaActually run the program and measure time and memory usedWork it out on paper by counting the steps and memory the algorithm needs
Also calledEmpirical / experimentalTheoretical
WhenAfter the program is writtenBefore coding, from the algorithm itself
Depends on machine, language, input?Yes, results differ between computers and runsNo, machine independent, expressed as a function of input size n
ProsGives real, concrete numbersFast, no program needed, fair comparison of algorithms
ConsNeeds a working program; unfair if machines or inputs differGives growth trends, not exact seconds
Where this leadsPerformance analysis has two parts, covered in the next lessons: space complexity (memory, Part 02) and time complexity (running time, Parts 03 and 04).

1. Getting started

C++ source is a text file (test.cpp) that a compiler turns into an executable (test.exe). When you run it, the operating system calls the function main.

#include <iostream>        // bring in input/output tools
using namespace std;        // so we can write cout instead of std::cout

int main() {                // program starts here
    cout << "Hello" << endl;  // print to the screen
    return 0;               // exit status: 0 = success
}
PartMeaning
#includePreprocessor line that pulls in a library (<iostream> for input/output, <cmath> for maths like sqrt).
cout / <<cout = "character out" (the screen). << is the stream insertion operator: it pushes the value on its right into the stream.
cin / >>cin reads from the keyboard: cin >> r; stores what the user types in r.
;Every statement ends with a semicolon.
// and /* */Comments (ignored by the compiler).

Exit status: why main returns a number

The number returned by main goes back to the operating system. 0 means success; any other value means failure. Other programs or scripts use it to decide what to do next.

On Windows, echo %ERRORLEVEL% shows the last exit status. A crash from division by zero shows up as a non-zero status (136 in the notes).

Namespaces

A namespace is a labelled container for names, so two libraries can both define print() without clashing.

namespace A { void print(); }
namespace B { void print(); }
A::print();   // calls A's version
B::print();   // calls B's version
// Two print() in the same scope with no namespace = compile error

2. Variables, types and operators

A variable is a named box in memory that holds a value of one type.

TypeHoldsSize (typical 32/64-bit PC)
charOne character, e.g. 'A'1 byte
booltrue / false1 byte
shortSmall whole number2 bytes
intWhole number4 bytes
longBigger whole number4 bytes (32-bit), 8 bytes (64-bit)
floatDecimal number4 bytes
doubleMore precise decimal8 bytes
pointer (int * etc.)A memory address2 / 4 / 8 bytes on 16 / 32 / 64-bit machines

These types (char, int, double, ...) are atomic / primitive types: they cannot be split into smaller parts.

Initialisation: giving a variable a first value

Variable kindWhere declaredInitialised automatically?
LocalInside a functionNo. You must set it.
GlobalOutside all functionsYes (to 0)
staticLocal with the word staticYes (once), and it keeps its value between calls

An uninitialised local holds a garbage value: whatever random bits were left in that memory by earlier code. Using it gives unpredictable results.

void counter() {
    static int count;     // starts at 0 once, then remembers
    count++;
    cout << count << "\n";
}
counter(); counter(); counter();   // prints 1, 2, 3
// With a plain "int count;" you would see random leftover values instead.

Constants

Variables can be changed anywhere, so you might overwrite a fixed value by accident. Use a constant for fixed values.

const float pi = 3.14;#define PI 3.14

Operators worth knowing

OperatorMeaning
+ - * / %Arithmetic; % is the remainder (25 % 2 = 1).
== != < > <= >=Comparison. Note == compares; a single = assigns.
&& || !Logical AND / OR / NOT. Short circuit: in a && b if a is false, b is never evaluated.
& | ~Bitwise AND / OR / NOT: work bit by bit, both sides always evaluated. 10101010 | 00000001 = 10101011 (set the last bit without touching the others).

Ternary pros: shorter code and handy for simple assignments. Do not nest it for complex logic.

3. Control flow

if (x > 0) { ... } else { ... }
for (int i = 0; i < n; i++) { ... }    // counted loop
while (cond) { ... }                    // loop while true
StatementWhat it doesExample
continueSkip the rest of this iteration and start the next one. Less nesting, more readable.
// print sqrt of non-negative numbers only
for (int i = 0; i < 5; i++) {
  if (num[i] < 0) continue;   // skip -4 and -25
  cout << num[i] << " " << sqrt(num[i]);
}
// without the check negatives print -nan
breakLeave the loop immediately. Stops unnecessary work; useful for validation (stop once a PIN matches). In nested loops it exits only the inner loop.
for (int i = 0; i < 5; i++) {
  if (pins[i] == 5678) {
     cout << "PIN is valid";
     break;                    // stop searching
  }
}
returnLeaves the whole function (so it also escapes every nested loop in it). In main it ends the program.if (n < 0) return; in a void function
exit(0)Ends the whole program from anywhere. Valid, but not recommended: resources may not be released properly.

To break out of all nested loops: use return, or put the loops inside a function and return from it.

4. Functions

int power(int num, int expo = 2) {    // expo has a default value
    int result = 1;
    for (int i = 0; i < expo; i++) result = result * num;
    return result;
}
cout << power(2, 3);   // 8
cout << power(2);      // 4  (uses the default expo = 2)
  • A function has a return type (void if it returns nothing), a name and parameters.
  • Defaults go on the right-most parameters: greet(string name, string role = "guest"). greet("pipuni","admin") → admin; greet("pipuni") → guest.
  • Each call gets its own local variables on the stack (see section 5).

5. How memory is organised

When your program runs, the operating system gives it memory split into four segments:

StackHeap
Compiler manages it automaticallyYou allocate with new and release with delete
Fast, but limited sizeLarge, but slower
Lives as long as the function callLives until you delete it (or the program ends)
Local variables, parameters, return addressesDynamic variables and dynamic arrays

Garbage collection

A garbage collector automatically frees memory that is no longer used. C++ does not have one; you must free heap memory yourself. Pros of GC: prevents leaks, safer, easier, more productive. Cons: slower, uses more memory, less control, unpredictable pauses.

6. Pointers

A pointer is a variable that holds a memory address instead of an ordinary value.

int *p = 0;      // 1. null pointer: holds 0, points nowhere
int n = 5;       // 2. an ordinary variable
p = &n;          // 3. & = "address of". p now holds n's address
cout << n;       // 5
cout << &n;      // 0xDEADBA11   (n's address)
cout << p;       // 0xDEADBA11   (same: p holds that address)
cout << *p;      // 5            (* = "value at": follow the pointer)
SymbolRead asExample
&n"address of n"p = &n;
*p"value at the address p holds" (dereference)*p = 10; changes n to 10
int *p (in a declaration)"p is a pointer to an int"The type matters: the compiler must know how to read the data at that address.

Why use pointers?

  • Modify variables that belong to another function.
  • Dynamic memory allocation (new), where size is decided at run time.
  • Work efficiently with arrays (no copying).
  • Build linked data structures (linked lists, trees): each node holds the address of the next.

Wild pointers: always initialise

int *p;          // never set: wild pointer, holds a garbage address like 0x0BADDD11
*p = 999;        // writes into a random place in memory: crash or silent corruption

Rule: initialise every pointer, at least to 0 (null).

Dynamic memory on the heap

int *p = new int;        // ask the heap for one int; p holds its address
*p = 999;
cout << *p;              // 999

int *q = new int(999);   // allocate AND initialise
delete q;                // give it back

int size;
cin >> size;
int *arr = new int[size];   // dynamic array: size decided while running
delete [] arr;              // arrays are freed with delete[]
Memory leakMemory is allocated with new but never released with delete. The block stays reserved but nothing can reach it any more, so a long-running program slowly uses up all memory. Every new needs a matching delete (new[] needs delete[]).
void leakMemory() {
    int *p = new int(999);
    cout << *p;
    delete p;      // without this line: leak
}

sizeof(p) gives the size of the pointer, which depends on the machine (8 bytes on a 64-bit PC for every pointer type: char*, int*, float* all print 8). It does not depend on what they point to.

Pointer arithmetic and arrays

Adding to a pointer moves the address, in steps of the pointed-to type's size. For an int*, p+1 is 4 bytes further on (example: ...f4, ...f8, ...f0 for p, p+1, p-1).

  • The array name holds the address of its first element: arr == &arr[0], and *arr == arr[0].
  • int *p = arr; then arr[i] and *(p+i) mean the same thing.
  • Never read or write beyond the array's last element.

7. Passing parameters

KindDeclaration / callWhat happens
By valuevoid f(int x) / f(a)A copy is passed. The caller's variable is not changed. Copying a big array is slow and uses extra memory.
By referencevoid f(int &x) / f(a)x is an alias (another name) for the caller's variable; changes are visible to the caller. No copy.
By pointervoid f(int *p) / f(&a)The address is passed; use *p inside. Needed when the argument may be null (a reference cannot be null).
Arraysint f(int arr[]) or int f(int *arr) / f(arr)Only the address of the first element is passed (no copy).

The classic swap: value vs pointer

void swap(int a, int b) {        // BY VALUE: swaps copies only
    int t = a; a = b; b = t;
}
int main() { int x = 3, y = 5; swap(x, y); cout << x << " " << y; }   // 3 5  (unchanged!)

void swap(int *a, int *b) {      // BY POINTER: swaps the originals
    int t = *a; *a = *b; *b = t;
}
int main() { int x = 3, y = 5; swap(&x, &y); cout << x << " " << y; }  // 5 3

By reference gives the same result as the pointer version with simpler syntax: void swap(int &a, int &b) called as swap(x, y).

Why have all three?Value is safest (the function cannot damage your data). Reference avoids copying and lets a function modify the caller's variable. Pointer does the same but also works when the argument might be null, and is how linked structures are built.

8. Composite types: struct

An atomic type cannot be broken down. A composite type is built from other types and can be decomposed. A struct groups related variables (its members) under one name. Members may have different types (heterogeneous).

struct Day    { int year; int month; int date; };
struct Person { char name[30]; int weight; Day dob; };   // contains another struct

Person he;                 // he.name, he.weight, he.dob.year / .month / .date
he.weight = 57;            // set a member
cout << he.dob.year;       // get a member
Person *p = &he;
p->weight = 60;            // p->weight is the same as (*p).weight

A data structure is a structure that holds a set of atomic or composite data, with operations on it. A simple one is an array of structs:

int num[] = {3, 2, 1};              // homogeneous (all int)
cout << num[0];  num[2] = 5;        // get / set

Person employee[2];                 // heterogeneous elements (name + weight + dob)
cout << employee[0].name;           // get
employee[1].weight = 57;            // set

Arrays and structs are linear structures: the elements sit one after another.

Answers
  1. Failure (0 is success).
  2. Only local variables.
  3. p = the address of n, *p = 5, &n = the same address as p.

  5. An array must be freed with delete [] a;.

Written questions

W1. Define an algorithm and list five properties of a good algorithm.

An algorithm is a finite, well-defined set of steps for solving a problem. A good algorithm is: (1) correct, (2) composed of a finite number of well-defined steps, (3) produces output, (4) terminates in finite time, (5) efficient.

W2. State the differences between an algorithm and a program.

An algorithm is the method/idea, written in plain language or pseudocode and independent of any machine. A program is an implementation of an algorithm in a specific programming language, which must also be readable and maintainable and run within resource limits.

W3. Write pseudocode for an algorithm that returns the largest value in an integer array list of size elements (size ≥ 1). 
ALGORITHM findMax (list[] INTEGER, size INTEGER)
   PRE   list has at least one element
   RETURN the largest value in list
1  max ← list[0]
2  i ← 1
3  LOOP (i < size)
4     IF (list[i] > max)
5        max ← list[i]
6     END IF
7     i ← i + 1
8  END LOOP
9  RETURN max
END findMax

Terminates because i increases each pass; correct because max always holds the largest value seen so far.

W4. Explain the two approaches to determining algorithm efficiency. Why is performance analysis preferred when choosing between algorithms?

Performance measurement runs the program and records actual time/memory, so results depend on the computer, language, compiler and input. Performance analysis counts the steps and memory needed from the algorithm itself, independent of hardware, and expresses them as a function of input size. Analysis is preferred because it works before coding and gives a fair comparison between algorithms.

W5. Why is this not a valid algorithm? 1 x ← 1   2 LOOP (x > 0)   3 x ← x + 1   4 END LOOP

It never terminates (x only grows, so x > 0 is always true) and it produces no output. It violates two required properties.
