Short note: revision sheet

Definition & characteristics
Independent computers that appear as one coherent system; no shared memory; message passing; no global clock; no shared state.
6 characteristicsResource sharing, Scalability, Concurrency, Fault tolerance, No global clock, Transparency
6 advantagesScalability, Fault tolerance, Performance, Resource efficiency, Geographic reach, Cost-effective growth
6 challengesComplexity, Partial failures, Consistency, Synchronization, Security, Network reliability
TransparencyAccess, Location, Migration, Replication, Concurrency, Failure
AlsoOpenness (standard interfaces), Heterogeneity (different HW/OS/lang), Middleware hides it
ScalingUp = vertical = bigger box; Out = horizontal = more boxes (preferred)
Real-world
GoogleServer farms, GFS (chunks, replicated), MapReduce (map → shuffle → reduce)
AWSRegions + AZs, EC2 elastic compute, S3 replicated storage
BanksStrong consistency, distributed transactions (both commit or neither), high availability
CAP theorem
CEvery node sees the same data at the same time
AEvery request gets a response, even if nodes are down
PKeeps working despite network failures between nodes
RuleOnly 2 of 3. Partitions happen ⇒ choose C or A
CPRefuse during partition — banking
APAnswer with stale data, converge later — social feed
Fundamental models
ArchitectureClient-server (central, SPOF) · P2P (equal peers, churn) · Microservices (small independent services)
InteractionSync = block & wait (bounds known) · Async = continue (no bounds)
FailureCrash < Omission < Timing < Byzantine (arbitrary/malicious)
SecurityEavesdrop, MITM, spoof, tamper, replay, DoS; defend with authentication, authorization, TLS

Common mistakes

MistakeCorrect idea
"A distributed system is many computers sharing memory."Nodes do not share physical memory; they cooperate only by messages.
"CAP: just pick any two you like, e.g. CA for big systems."Partitions always happen in a real network, so P is required; the real choice is C or A during a partition. CA only fits a single site.
Confusing consistency (CAP) with ACID consistencyCAP consistency = all nodes see the same latest data. ACID consistency = a transaction keeps the database rules valid.
"Availability means the system never fails."It means every request gets a (non-error) response, possibly with old data.
Scale up = adding machinesScale up = bigger machine (vertical); scale out = more machines (horizontal).
"No global clock" means nodes have no clocksEvery node has a clock; they are not perfectly synchronized, so there is no single shared time.
Writing "transparency = security" or "= visibility"Transparency = hiding distribution from the user.
Thinking P2P has serversEvery peer is both client and server.
