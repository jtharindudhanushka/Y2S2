Lab 01 — Create a VM, install LiteLinux, configure a static IP

Objectives: connect to VMware ESXi · create a VM · install LiteLinux 7 · configure a static IP · verify connectivity. Requirements: VMware ESXi, vSphere Client, LiteLinux ISO, 2 vCPU, 4 GB RAM, 40 GB disk.

#Lab stepWhat it means
1Log in to the ESXi web clientOpen the ESXi host's address in a browser; ESXi is a Type 1 hypervisor
2–3Create/Register VM; name LiteLinux-Lab01Start the new-VM wizard
4Guest OS: Linux → RHEL 8 or Other Linux (64-bit)Tells ESXi which virtual hardware and drivers suit the guest
5Select datastoreWhere the VM's files (virtual disk, config) will live
62 vCPU, 4 GB RAM, 40 GB disk, VM Network, attach the LiteLinux ISOAllocate virtual resources (Lesson 5: CPU time-slicing, mapped RAM, virtual disk file); connect the vNIC to the "VM Network" port group; the ISO acts as a virtual DVD to install from
7–8Power on, install LiteLinux, create a root password and a student userNormal OS installation inside the VM
9nmcli device statusNetworkManager CLI: list network devices and find the interface name (here ens160, the VMware virtual NIC)
10Configure the static IP (below)Fix the address instead of getting one from DHCP
11sudo nmcli connection down ens160 then up ens160Restart the connection so the new settings apply
12ip addr, ip route, ping -c 4 8.8.8.8, ping -c 4 www.google.comVerify (table below)
sudo nmcli connection modify ens160 \
     ipv4.addresses 192.168.8.X/24 \
     ipv4.gateway 192.168.8.1 \
     ipv4.dns "8.8.8.8 1.1.1.1" \
     ipv4.method manual
PartMeaning
ipv4.addresses 192.168.8.X/24The VM's own IP. /24 = subnet mask 255.255.255.0: the first 24 bits (192.168.8) are the network, the last number X (1–254) is the host. Each student uses a different X. (The lab sheet prints "192.1681. X/24", a typo; it must be in the same network as the gateway 192.168.8.1.)
ipv4.gateway 192.168.8.1The router used to reach other networks/the Internet
ipv4.dns "8.8.8.8 1.1.1.1"DNS servers (Google, Cloudflare) that turn names like www.google.com into IP addresses
ipv4.method manualUse these static settings instead of DHCP (automatic)
VerificationExpected resultIf it fails
ip addrens160 shows inet 192.168.8.X/24Address not applied: re-check modify, restart connection
ip routedefault via 192.168.8.1 dev ens160Gateway missing or wrong
ping -c 4 8.8.8.84 replies (Internet reachable by IP)Gateway/VM network/port group problem
ping -c 4 www.google.comName resolves and 4 repliesIf IP ping works but this fails: DNS problem

Why a static IP for servers? Clients and other servers must always find the server at the same address; a DHCP address could change after a reboot.
