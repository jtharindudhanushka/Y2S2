1. Timer and counter

  • A timer increments on each clock pulse when the oscillator is connected. Because the frequency is known, the pulse count tells the elapsed time.
  • When an external pulse source (a switch or sensor on the Tn pin) is connected instead, it counts events and operates as a counter.
  • What is the need? The same thing can be done in software, but software timing and counting ties up the CPU. A microcontroller has a very small CPU, so the work is given to a peripheral device (the timer) and the CPU is left for computation.

Every timer has its own registers named with the timer number n (TCCR0B, TCNT0, TIFR0, TIMSK0 for Timer 0; TCCR1B, TCNT1, ... for Timer 1).

How an 8-bit timer works

Oscillator → (optional prescaler) → TCNTn register. At each clock pulse TCNTn increments from 0 to 255, then overflows back to 0. When it overflows the hardware sets the TOVn flag in TIFRn, telling the CPU that the timer overflowed.

2. Time formulas

Elapsed timeWithout a prescaler: elapsed time = (B − A) / f, where A is the start count in TCNT, B the stop count and f the oscillator frequency. With a prescaler 1/N: elapsed time = N × (B − A) / f.

Time of one timer pulsetime = 1 / (F_CPU / prescale) = prescale / F_CPU
Pulses n for a required delaydelay = (prescale / F_CPU) × n, so n = (F_CPU / prescale) × delay

3. Timer registers

TCCRnB: clock select

Bits CSn2, CSn1, CSn0 (bits 2 to 0 of TCCRnB) select the clock source and prescale. 000 stops the timer.

TCNTn, TIFRn, TIMSKn

  • TCNTn: the count. Increments at every clock pulse, counts up to maximum, overflows to 0 and starts again. Software uses it to set the start count and to read the end count.
  • TIFRn (Timer Interrupt Flag Register): bit 0 = TOVn, set by hardware when TCNTn overflows from its maximum to 0. (Bits OCFnA, OCFnB are for compare matches, lesson 7.)
  • TIMSKn (Timer Interrupt MaSK): bit 0 = TOIEn, Timer Overflow Interrupt Enable. With sei() it makes the overflow call ISR(TIMERn_OVF_vect) (vectors TIMER0_OVF_vect, TIMER1_OVF_vect, TIMER2_OVF_vect).

Write one to clear (W1C)

A flag in TIFRn is cleared by writing a 1 to it, not a 0. Why? The flag is set by hardware, and TIFRn holds several flags. If clearing needed a 0, software would have to read the register, change one bit and write it back, a read-modify-write that could wrongly clear another flag that was set in between. With W1C, writing a mask with a single 1 clears just that flag and writing 0s leaves the others untouched. In code: TIFR0 = (1<<TOV0); (the lecture also uses TIFR0 = TIFR0 | 0b00000001;, which works for TOV0 but also writes back 1s to any other flag that is set, so prefer the plain mask).

4. Counting events: Systems 10, 11, 12

Task: count 5 button presses, then toggle an LED. Hardware: LED on PB5 (with 220 Ω); the pushbutton on PD4 = T0 to GND with the internal pull-up and a debounce capacitor (100 nF) across it.

System 10: count by polling TCNT0

#include <avr/io.h>
int main(void)
{
    DDRB  = DDRB | 0b00100000;       // PB5 output
    DDRD  = DDRD & 0b11101111;       // PD4 (T0) input
    PORTD = PORTD | 0b00010000;      // pull-up on PD4
    TCCR0B = TCCR0B | 0b00000110;    // CS02:0 = 110: external clock T0, falling edge
    TCNT0 = 0;                       // counter = 0
    while (1)
    {
        if (TCNT0 >= 5)              // 5 presses counted
        {
            PORTB = PORTB ^ 0b00100000;   // toggle PB5
            TCNT0 = 0;                    // reset the counter
        }
    }
    return 0;
}

System 11: alternate approach using the overflow flag

Preload the counter with 251. The 5th falling edge takes it 251 → 252 → 253 → 254 → 255 → overflow to 0, which sets TOV0. Then no comparison with a number is needed.

    TCCR0B = TCCR0B | 0b00000110;    // external clock on T0, falling edge
    TCNT0 = 251;                     // 5 counts to overflow
    while (1)
    {
        if (TIFR0 & 0b00000001)      // TOV0 set: 5 presses
        {
            PORTB = PORTB ^ 0b00100000;   // toggle PB5
            TCNT0 = 251;                  // reload
            TIFR0 = TIFR0 | 0b00000001;   // clear TOV0 (write 1)
        }
    }

System 12: using the overflow interrupt

#include <avr/io.h>
#include <avr/interrupt.h>
int main(void)
{
    DDRB  |=  (1<<DDB5);
    DDRD  &= ~(1<<DDD4);
    PORTD |=  (1<<PORTD4);
    TCCR0B |= (1<<CS02) | (1<<CS01);    // external clock on T0, falling edge
    TCNT0 = 251;
    TIMSK0 |= (1<<TOIE0);               // enable timer overflow interrupt
    sei();                               // enable global interrupts
    while (1) { /* can be used to perform another task */ }
}
ISR(TIMER0_OVF_vect)                     // 5 presses counted
{
    PORTB ^= (1<<PORTB5);                // toggle the LED
    TCNT0 = 251;                         // reload (the flag clears itself on ISR entry)
}

When the overflow interrupt is serviced the hardware clears TOVn automatically, so the ISR does not clear it.

5. Timing: Systems 13 and 14 (200 ms blinker)

Task: blink an LED on PB5 every 200 ms using Timer1 (16-bit), prescale 64, initial value 15 536 (see the worked example).

// System 13: polling the overflow flag
#include <avr/io.h>
int main(void)
{
    DDRB   |= (1<<DDB5);
    TCCR1B |= (1<<CS11) | (1<<CS10);      // F_CPU/64
    TCNT1 = 15536;                          // 50 000 pulses to overflow
    while (1)
    {
        if (TIFR1 & (1<<TOV1))             // timer overflowed: 200 ms passed
        {
            PORTB ^= (1<<PORTB5);           // toggle LED
            TCNT1 = 15536;                  // reset timer
            TIFR1 |= (1<<TOV1);             // clear TOV1 (write 1)
        }
    }
}

// System 14: using interrupts
    TCCR1B |= (1<<CS11) | (1<<CS10);
    TCNT1 = 15536;
    TIMSK1 |= (1<<TOIE1);
    sei();
    while (1) { /* another task */ }
ISR(TIMER1_OVF_vect) { PORTB ^= (1<<PORTB5); TCNT1 = 15536; }
Timer vs software delayA timer keeps the CPU free for other work (and with the interrupt version the delay costs nothing), is more accurate than a counted loop, and is not affected by other code, whereas _delay_ms() blocks the CPU. Remember to reload TCNT in the loop or ISR, otherwise the next period is a full 65 536 counts.

6. Random numbers on the AVR

  • #include <stdlib.h>: rand() returns a pseudo-random integer from 0 to RAND_MAX; srand(seed) seeds it with an unsigned int.
  • The same seed gives the same sequence after every reset, so the program needs a fairly random seed. Sources: the value of a free-running timer when the user presses a button (the press time is unpredictable), or the ADC reading of a floating (unconnected) analog pin, which picks up noise.
  • A number in a range: 1 + rand() % 10 gives 1 to 10. Arduino: randomSeed(analogRead(A5)), random(1000, 10001).

Q2: the timer value

16 MHz, prescale 1024: tick 64 µs, n = 15 625, initial value 49 911 makes the 16-bit timer overflow in exactly one second (65 535 − 15 625 + 1). The firmware counts overflows in a numeric variable: waiting time = random whole seconds from 1 to 10, reaction time = number of whole seconds elapsed.

Q3: C firmware (seed from Timer0)

#include <avr/io.h>
#include <stdlib.h>

#define ONE_SECOND 49911u

static void waitOneSecond(void)
{
    TCNT1 = ONE_SECOND;
    TIFR1 |= (1<<TOV1);                   // clear the flag (write 1)
    while (!(TIFR1 & (1<<TOV1)));         // wait for the overflow
}

int main(void)
{
    DDRB  |= 0x0F;                          // PB0..PB3 outputs
    DDRD  &= ~((1<<DDD2) | (1<<DDD3));    // buttons inputs
    PORTD |= (1<<PORTD2) | (1<<PORTD3);    // pull-ups
    TCCR0B = (1<<CS02) | (1<<CS00);        // Timer0 free-running, F_CPU/1024
    TCCR1B = (1<<CS12) | (1<<CS10);        // Timer1 F_CPU/1024

    while (1)
    {
        while (PIND & (1<<PIND2));          // wait until "ready" is pressed (low)
        srand(TCNT0);                       // timer value at the moment of the press: random seed
        PORTB &= ~0x0F;                     // all LEDs off
        unsigned char wait = 1 + rand() % 10;    // 1..10 s
        while (wait--) waitOneSecond();          // waiting time
        PORTB |= (1<<PORTB0);               // blue LED: signal

        unsigned char seconds = 0;
        TCNT1 = ONE_SECOND;
        TIFR1 |= (1<<TOV1);
        while (PIND & (1<<PIND3))           // until "react" is pressed
        {
            if (TIFR1 & (1<<TOV1))           // another whole second passed
            {
                TIFR1 |= (1<<TOV1);
                TCNT1 = ONE_SECOND;
                if (seconds < 255) seconds++;
            }
        }
        PORTB &= ~(1<<PORTB0);              // blue off
        if      (seconds == 0) PORTB |= (1<<PORTB1);   // < 1 s: green
        else if (seconds == 1) PORTB |= (1<<PORTB2);   // 1 s to < 2 s: orange
        else                   PORTB |= (1<<PORTB3);   // >= 2 s: red
    }
}

1. Why hardware timers and counters?

A microcontroller is a single-chip computer: one CPU plus peripherals on the same chip. You already used two peripherals: the ports (Lesson 3) and the ADC (Lesson 5). The timer/counter is a third one. It is a separate piece of hardware that counts pulses by itself, while the CPU does something else.

Two jobs come up again and again:

  • Timing: measure the time between two events, or wait a precise time (blink every 200 ms).
  • Counting: count events, for example items passing on a conveyor belt, or people crossing an infrared beam at a door.

Both can be done in software, which is what you did so far:

// software timing: 1 minute
int i = 0;
while (1) {
    _delay_ms(1000);   // CPU spins 1 s
    i++;
    if (i == 60) { /* 1 minute */ }
}
// software counting: people
int count = 0;
while (1) {
    if (beam sensor is LOW)
        count++;       // CPU watches
}

The problem: a delay loop is a busy wait. The CPU runs an empty loop just to burn time, so it cannot do anything else. The ATmega328P has one core, so that time is completely wasted. (On a PC you don't notice this, because a multi-core processor runs other work on the other cores.)

2. Timer or counter? Same hardware, different clock source

Inside, a timer is just a register that adds 1 on every pulse it receives. Where the pulses come from decides its name:

  • Pulses from the internal oscillator (the 16 MHz crystal, optionally slowed by the prescaler): the pulses arrive at a known rate, so the count tells you time. It works as a timer.
  • Pulses from an external source on the Tn pin (a button, an IR beam sensor, a door switch): each pulse is one event, so the count tells you how many events. It works as a counter.

The choice is made by the three clock select (CS) bits in TCCRnB. The n is the timer number: 0, 1 or 2.

Figure 1. One timer/counter. The CS bits choose where the pulses come from; TCNTn counts them; on overflow the TOV flag is raised.

3. How the count register works: count, overflow, TOV

TCNTn (Timer/CouNTer register) goes up by 1 on every pulse. It has a fixed size:

  • Timer0 and Timer2 are 8-bit: TCNT0 counts 0, 1, 2 … 255, then the next pulse makes it overflow back to 0.
  • Timer1 is 16-bit: TCNT1 counts 0 … 65 535 (216 − 1), then overflows to 0.

At the moment of the overflow the hardware sets the TOV (Timer OVerflow) flag, bit 0 of TIFRn (Timer Interrupt Flag Register). The flag says: "I counted up to my maximum and started again from 0."

Figure 2. TCNT0 climbs 0→255, overflows to 0 and starts again. Each overflow raises the TOV flag. (TCNT1 does the same up to 65 535.)
The flag rule: write 1 to clear [very important] A flag bit is set by the hardware, never by you. You can only clear it, and you clear it by writing a 1 to it (writing 0 does nothing). If you poll the flag you must clear it after each overflow, otherwise it stays 1 and the hardware cannot raise it again for the next overflow. 
TIFR0 = TIFR0 | 0b00000001;   // write 1 to TOV0 = CLEAR it (slide style)
TIFR0 = (1 << TOV0);          // same effect, touches only TOV0
When you use the overflow interrupt instead, the hardware clears TOV automatically when the ISR runs, so the ISR does not clear it.

4. Measuring elapsed time

The oscillator gives f pulses per second. If TCNT started at A and you stop the timer when it shows B, then B − A pulses passed, each lasting 1/f second:

Elapsed time without prescaler:   t = (B − A) / f      with prescaler N:   t = N × (B − A) / f
If it overflowed k times in between, add k × 256 (8-bit) or k × 65 536 (16-bit) pulses. You keep k in a variable.

Example: f = 1 Hz, A = 0, B = 60 → t = 60 s. With f = 10 Hz and prescaler 10, the timer gets 1 pulse per second, so again A = 0, B = 60 gives 10 × 60 / 10 = 60 s.

Why the prescaler? At 16 MHz an 8-bit timer fills up in 256 / 16 000 000 = 16 µs. That is far too fast. The prescaler divides the clock by N so the register climbs slowly enough to measure useful times. External pulses (buttons, sensors) are already slow, so there is no prescaler on the Tn pin.

Stopping the timer: set the CS bits to 000. That disconnects every clock source, TCNT freezes, and you can read it.

6. The preload formula (for counts and for delays)

The flag is raised only on the overflow. To get the flag after exactly n pulses, start the register n pulses before the overflow:

Initial value initial = max − n + 1    (max = 255 for 8-bit, 65 535 for 16-bit; the +1 is the step from max to 0, the overflow itself)
Figure 3. Count 5 with Timer0: 255 − 5 + 1 = 251. The 5th pulse causes the overflow and raises TOV.

For a delay, first find how many timer pulses n the delay needs:

Delay calculation one tick = prescale / F_CPU   ⇒   delay = (prescale / F_CPU) × n   ⇒   n = (F_CPU / prescale) × delay   (delay in seconds)
then initial = max − n + 1. n must be ≤ 256 (8-bit) or ≤ 65 536 (16-bit).

7. Counting events: Systems 10–12 (button on T0 counts 5 presses, LED toggles)

Hardware (same for all three): pushbutton from D4 (PD4 = T0) to GND, internal pull-up ON, a 100 nF capacitor across the button to debounce it (each bounce would otherwise be counted as a press), and the on-board LED on D13 (PB5).

System 10 — poll the count

#include <avr/io.h>

int main(void)
{
    DDRB = DDRB | 0b00100000;        // PB5 output (LED)
    DDRD = DDRD & 0b11101111;        // PD4 (T0) input (already 0 by default)
    PORTD = PORTD | 0b00010000;      // pull-up on PD4
    TCCR0B = TCCR0B | 0b00000110;    // CS = 110: clock = T0 pin, falling edge -> COUNTER
    TCNT0 = 0;                       // start count (already 0 by default)
    while (1)
    {
        if (TCNT0 >= 5)              // 5 presses counted by HARDWARE
        {
            PORTB = PORTB ^ 0b00100000;   // toggle LED
            TCNT0 = 0;                    // restart count
        }
    }
}

Why >= 5 and not == 5? If two pulses arrive between two checks (a spike the capacitor missed, or a very fast double press), TCNT0 jumps from 4 to 6. With == the LED would then need 250 more presses (round to 255, overflow, back to 5). >= still catches it.

System 11 — exactly 5 presses: preload 251 and poll TOV

    TCNT0 = 251;                         // 255 - 5 + 1
    while (1)
    {
        if (TIFR0 & 0b00000001)          // TOV0 set? (5th press caused overflow)
        {
            PORTB = PORTB ^ 0b00100000;  // toggle LED
            TCNT0 = 251;                 // reload (NOT 0)
            TIFR0 = TIFR0 | 0b00000001;  // clear TOV0 by writing 1
        }
    }

How the if works: AND with 0b00000001 forces bits 7–1 to 0 and keeps bit 0 as it is. The result is 1 (true) only when TOV0 = 1.

System 12 — exactly 5 presses with the overflow interrupt

#include <avr/io.h>
#include <avr/interrupt.h>

int main(void)
{
    DDRB = DDRB | 0b00100000;        // PB5 output
    DDRD = DDRD & 0b11101111;        // PD4 input
    PORTD = PORTD | 0b00010000;      // pull-up PD4
    TCCR0B = TCCR0B | 0b00000110;    // clock = T0, falling edge

    sei();                           // enable global interrupts
    while (1)
    {
        // CPU is free for another task
    }
}

9. Build example: Exercise 5 — the reaction timer

Task: press READY → all LEDs off, wait a random 1–10 s → blue LED on → user presses REACT as fast as possible → blue off, show the reaction time: green < 1 s, orange 1 s to < 2 s, red ≥ 2 s.

Figure 4. Reaction timer. Buttons to GND with internal pull-ups (pressed = LOW). Each LED: pin → 220 Ω → anode (long leg), cathode (flat side) → GND.
PartPinWhy this choice
READY buttonD2 / PD2any input; pull-up so no resistor needed

LEDs blue, green, orange, redD8–D11 / PB0–PB3all on port B, so one register controls them
Timer0 (8-bit)–runs freely at 16 MHz; its value when READY is pressed is the random seed (human timing is random)
Timer1 (16-bit)–/1024 ⇒ 1 tick = 64 µs. Preload 49 911 = 1-s overflows for the wait; from 0 it measures up to 4.19 s for the reaction
#include <avr/io.h>
#include <stdlib.h>                    // srand(), rand()

int main(void)
{
    DDRB = DDRB | 0b00001111;           // PB0-PB3 outputs: blue, green, orange, red
    DDRD = DDRD & 0b11110011;           // PD2 READY, PD3 REACT inputs
    PORTD = PORTD | 0b00001100;         // pull-ups on PD2, PD3
    TCCR0B = TCCR0B | 0b00000001;       // Timer0 free-running at F_CPU/1 (seed source)
    TCCR1B = TCCR1B | 0b00000101;       // Timer1 at F_CPU/1024: 1 tick = 64 us

    while (1)
    {
        while (PIND & 0b00000100) { }   // wait until READY pressed (PD2 LOW)
        srand(TCNT0);                     // fairly random seed
        while (!(PIND & 0b00000100)) { }  // wait until READY released
        PORTB = PORTB & 0b11110000;       // all LEDs off

        unsigned char waitSec = rand() % 10 + 1;   // 1..10 s
        unsigned char sec = 0;
        TCNT1 = 49911;                    // 65535 - 15625 + 1: overflow after 1 s
        TIFR1 = TIFR1 | 0b00000001;       // clear old TOV1
        while (sec < waitSec)             // count 1-s overflows
        {
            if (TIFR1 & 0b00000001)
            {
                sec++;
                TCNT1 = 49911;
                TIFR1 = TIFR1 | 0b00000001;
            }
        }

        PORTB = PORTB | 0b00000001;       // blue ON: react now
        TCNT1 = 0;                        // start measuring
        TIFR1 = TIFR1 | 0b00000001;
        while ((PIND & 0b00001000) && !(TIFR1 & 0b00000001)) { }  // wait for REACT or 4.19 s
        unsigned int ticks = TCNT1;       // 1 tick = 64 us
        PORTB = PORTB & 0b11111110;       // blue OFF

        if ((TIFR1 & 0b00000001) || ticks >= 31250)
            PORTB = PORTB | 0b00001000;   // red: 2 s or more (31250 x 64 us = 2 s)
        else if (ticks >= 15625)
            PORTB = PORTB | 0b00000100;   // orange: 1 s to < 2 s
        else
            PORTB = PORTB | 0b00000010;   // green: under 1 s
    }
}
Q4: seed from a floating analog input Leave A0 unconnected. Its reading drifts randomly (noise). Read it once with the ADC (Lesson 5: ADMUX = AVcc ref, channel 0; ADCSRA enable + start; wait for ADSC = 0) and use srand(ADCW); instead of srand(TCNT0);. Then Timer0 is no longer needed.

L. What the lecturer explained in the lectures (2020 recordings)

From the two timing-and-counting recordings (folders 20–21 in Embedded Systems Lectures). [EXAM] marks things he tied to the exam.

L1. Why he wants the internals [EXAM] "Many people know how to use timers, but if you ask them to explain the internal working, they don't know." As university students you are expected to explain how a timer works (Figure 1 and Figure 2), not just call it. He also said some written questions are set to check whether you think beyond what was taught, which is why the module has a reputation for being hard.

L2. Where timers fit

  • So far: inputs (digital via ports, analog via ADC) and driving digital actuators (directly, or via BJT / MOSFET / relay). Analog actuators come next with PWM.
  • A microcontroller is a "single-chip computer": processor + peripherals. Ports and ADC are peripherals; the timer is another.
  • Small chips (ATtiny) have 1–2 timers named T0, T1…; ATmega has 3–5; XMega even more. "Large" means capability, not size: many big microcontrollers are tiny SMD (surface-mount) packages that are not breadboard friendly.

L3. Software vs hardware timing, in his words

  • A delay loop is a busy wait: "we tie up the CPU to run a loop but doing nothing", just to consume time. That CPU time could have been used for something else.
  • On PCs you never feel this because of multi-core processors; the microcontroller has one core, so it matters.
  • "This is the first time you are going to use a hardware timer." Two advantages: CPU is free during the delay, and hardware timing is highly precise. "If the system is a critical system which depends on time measurements, you better use hardware timers."
  • The same applies to counting: a software counter (if (sensor LOW) i++;) ties up the CPU.

L4. Timer becomes counter

  • Internal clock connected = timer. "The timer becomes a counter when an external pulse source is connected."
  • His examples of external pulses: an IR beam across a lecture-hall entrance (beam present = HIGH, person crossing = LOW, so people produce a square wave); items on a conveyor belt; and the cheapest one, a push button between a door and its frame with an automatic door closer. Count 5 openings, then drive a solenoid through a transistor to lock the door: "we allowed only five people". He said this is the kind of thing that could be a practical exam question.
  • Elapsed time worked example: f = 1 Hz, count 100 ⇒ 100 s. Fast oscillator + small register ⇒ fills too quickly ⇒ use the prescaler.
  • Student asked: is there a prescaler for the external source? No: external sources are always slow compared with the CPU.

L5. Flag bits [EXAM]

  • "Flag bit means: if something happens, you raise the flag to indicate", like a white flag to surrender.
  • "To clear a flag bit, set it." Writing 1 makes it 0; writing 0 does nothing. The hardware sets flags, you only clear them. This is standard on many architectures, not only AVR (he named Intel and Motorola, now NXP).
  • To know whether a bit is a flag bit, check the datasheet.
  • When you use the overflow ISR, the flag is cleared by hardware automatically; only when polling must you clear it yourself.

L6. Details from Systems 10–12

  • Pins: T0 = PD4 (Arduino 4), T1 = PD5 (Arduino 5). Timer2's TOSC pins (PB6/PB7) already have the 16 MHz crystal, "so we cannot use Timer2" for an external clock.
  • The on-board LED uses a 1 kΩ resistor because an SMD LED needs very little current. The 100 nF capacitor in parallel with the button debounces the input. Place buttons diagonally on the breadboard.
  • DDRD &= ... for PD4 and TCNT0 = 0 are not necessary (both are 0 after reset), but "make your algorithm more clear". The cost is one extra clock cycle each.
  • Why >= not == [EXAM-style reasoning]: a spike the capacitor misses, or a very fast double press, can take the count from 4 straight to 6. With == you'd have to press until 255, overflow and come back to 5. The chance is slim, but "as programmers you have to consider all possible situations", especially in mission-critical, safety-critical, medical, military or aerospace systems.
  • If the client requires exactly 5 presses, use the preload 251 + TOV method (System 11). Formula: max − count + 1; "plus 1 to account for the overflow". Reset means reload 251, not 0.
  • Polling TOV still wastes the CPU, so the best approach is the overflow interrupt (System 12). "This is the most efficient way of using counters."
  • Arduino platform: no direct access to timers and no wrapper for timer interrupts (attachInterrupt is only for external interrupts). Some Arduino libraries use timers internally, but you can't. This is another reason for C.
  • A student asked whether Exercise 3 could use counters. Yes, but he expected Exercise 3 to be done without them.

L7. Delays with Timer1 (System 13)

  • Derivation: f = 1/t, so one tick = 1 / (F_CPU / prescale) = prescale / F_CPU. Then delay = tick × n, so n = F_CPU / prescale × delay. Give the delay in seconds (200 ms = 200 × 10−3).
  • 200 ms at /64 ⇒ n = 50 000: "can you put it into an 8-bit timer? No." So use Timer1 (16-bit). Initial = 65 535 − 50 000 + 1 = 15 536.
  • 400 ms needs 100 000 counts, too many even for 16 bits. Three fixes he listed: (1) a bigger prescaler (256, 1024; but even 1024 has a limit), (2) a variable counting overflows, (3) in your own hardware, a slower crystal (8 or 4 MHz).
  • "Is /64 the optimal prescale?" No optimal value: "I just use 64, because I like 64." The prescaler scales the CPU clock down to suit the job (the ADC needs it too).
  • He explained if (TIFR1 & 0b00000001) bit by bit: x AND 0 = 0 for bits 7–1; x AND 1 = x for bit 0, so the condition is true only when TOV1 = 1.
L8. Marks and the practical exam [EXAM] 50% practical, 50% written (most other modules are about 70 / 25 / 25). In the practical, within 3 hours you design the hardware, assemble it, design and implement the firmware, run it and show it. If you score only 25/50 in the practical, you need 45/50 (90%) in the written paper for an A, which is very hard. "I know all the theories about swimming, but I can't swim": practise with your own kit. When doing exercises, also try other ways of solving the same exercise.

Written questions

W1. Explain why timers and counters are implemented as peripherals, and describe how an 8-bit timer measures time and how it counts events.

Doing timing and counting in software ties up the small CPU. A timer peripheral increments its TCNT register on each clock pulse from the oscillator (optionally through a prescaler), counts 0 to 255 and overflows to 0, setting TOV in TIFR. Because the clock frequency is known, elapsed time = N×(B−A)/f. If a pulse source such as a button or sensor is connected to the Tn pin (CS bits 110 or 111) the same hardware counts events.

W2. Calculate the initial value of a 16-bit timer to overflow every 100 ms with F_CPU = 16 MHz, and write the code to toggle PB5 using the overflow interrupt.

Choose prescale 64: tick 4 µs, n = 0.1/4 µs = 25 000, initial = 65 535 − 25 000 + 1 = 40 536.

W3. Describe the reaction timer design and explain how the random waiting time and the reaction time are obtained.

Ready and react buttons (pull-ups) on PD2 and PD3, blue, green, orange and red LEDs on PB0 to PB3. While waiting for ready, Timer0 free-runs; srand(TCNT0) at the press gives a fairly random seed (or the ADC of a floating pin). Timer1 with prescale 1024 and initial value 49 911 overflows every second; the firmware waits 1 + rand() % 10 overflows, lights the blue LED, then counts overflows until react is pressed. 0 s → green, 1 s → orange, 2 s or more → red.

W4. What is the W1C flag clearing convention and why is it used?

Write one to clear: a flag such as TOVn is cleared by writing a 1 to its bit. Writing a mask that has a single 1 clears only that flag and leaves other flags (which also live in TIFRn) untouched; a read-modify-write to clear by writing 0 could clear flags set in between.

W5. [2020 recording] A push button is fixed between a door and its frame. Design a system that lets exactly five people in and then locks the door with a solenoid. Explain why a hardware counter is used and give the key register settings.

Button on T0 = PD4 (D4) to GND, pull-up ON, 100 nF across it for debouncing. TCCR0B CS = 110 (T0 falling edge), so Timer0 becomes a counter. Preload TCNT0 = 255 − 5 + 1 = 251; the 5th opening overflows TCNT0 and sets TOV0. Enable TOIE0 + sei(); in ISR(TIMER0_OVF_vect) switch the solenoid ON through a transistor (with a flyback diode) to lock the door. The hardware counter counts by itself, so the CPU is free and no opening is missed by slow polling.

W6. [2020 recording] Explain the flag-bit convention and state when you must clear TOV yourself.

A flag is set by the hardware when an event happens (TOV on overflow). Software can only clear it, and it is cleared by writing 1 to it; writing 0 has no effect. This is common across architectures (AVR, Intel, Motorola/NXP). When polling TOV you must clear it after each overflow, otherwise the condition stays true and the next overflow cannot be seen. When using the overflow ISR, the hardware clears it automatically.

Practical question: "Wheel speed alarm" (exam style)

Original practice question modelled on systems 10 to 14 and the reaction timer: one timer as a counter, another as a time base.

ScenarioA bicycle wheel carries a magnet. A Hall sensor (AH1815, active low open drain) gives one pulse per wheel turn. A "speed alarm" counts the pulses for exactly one second. If more than 8 turns per second were counted, a red LED turns on; otherwise it is off. The measurement repeats continuously. The processor must remain free for other work, so the one-second time base must come from a timer interrupt, not a delay loop.
  1. Choose the timer for counting and the timer for the time base. Justify the choice and calculate all register values.
  2. Give the connection list.
  3. Write the firmware in C.
  4. Describe how you would do it in Arduino and why this is harder with the wrapper functions only.
Solution

1. Timers

  • Counter: Timer1 (16-bit) with its external clock input T1 = PD5 (CS12:0 = 110, falling edge). 16 bits are plenty for 8 turns per second and give headroom.
  • Time base: Timer0 (8-bit) with prescale 1024: tick = 64 µs. For about 10 ms: n = 0.01 / 64 µs = 156.25, use 156 (9.984 ms), initial value = 255 − 156 + 1 = 100. 100 overflow interrupts give 0.9984 s (0.16 % short; acceptable, say so in the answer). For an exact second use Timer1 in compare mode or a correction every 625 ticks.
  • Timer0 clock bits: CS02 = 1, CS01 = 0, CS00 = 1 (/1024). TIMSK0: TOIE0 = 1.

3. C firmware

#include <avr/io.h>
#include <avr/interrupt.h>

volatile unsigned char ticks = 0;      // 10 ms ticks
volatile unsigned char secondElapsed = 0;

int main(void)
{
    DDRB  |=  (1<<DDB0);                       // LED output
    DDRD  &= ~(1<<DDD5);                       // PD5 (T1) input
    PORTD |=  (1<<PORTD5);                      // pull-up for the open-drain sensor

    TCCR1B = (1<<CS12) | (1<<CS11);            // Timer1: external clock T1, falling edge (counter)
    TCNT1  = 0;

    TCNT0  = 100;                               // Timer0: 156 counts to overflow = 9.984 ms
    TCCR0B = (1<<CS02) | (1<<CS00);            // F_CPU/1024
    TIMSK0 |= (1<<TOIE0);                      // overflow interrupt
    sei();

    while (1)
    {
        if (secondElapsed)
        {
            secondElapsed = 0;
            unsigned int turns = TCNT1;         // turns counted in the last second
            TCNT1 = 0;
            if (turns > 8) PORTB |=  (1<<PORTB0);
            else           PORTB &= ~(1<<PORTB0);
        }
        /* other tasks can run here */
    }
}

ISR(TIMER0_OVF_vect)
{
    TCNT0 = 100;                                // reload for the next 9.984 ms
    if (++ticks == 100) { ticks = 0; secondElapsed = 1; }
}

4. Arduino

The wrapper functions have no function to use Timer1 as an external-clock counter, so the usual approach is to count pulses in an interrupt (attachInterrupt(digitalPinToInterrupt(2), pulse, FALLING) with the sensor on pin 2) and compare millis() against the last report time. Using the timer registers directly (as above, even inside an Arduino sketch) gives hardware counting with no interrupt per pulse.

volatile unsigned int pulses = 0;
unsigned long last = 0;
void pulse() { pulses++; }
void setup() {
  pinMode(2, INPUT_PULLUP); pinMode(8, OUTPUT);
  attachInterrupt(digitalPinToInterrupt(2), pulse, FALLING);
}
void loop() {
  if (millis() - last >= 1000) {
    last += 1000;
    noInterrupts(); unsigned int n = pulses; pulses = 0; interrupts();
    digitalWrite(8, n > 8);
  }
}
