1. What is PWM?

  • A technique for getting an analog-like output by digital means.
  • The digital output is toggled fast enough that the attached device reacts not to the individual pulses but to the percentage of time that the output is high in one cycle.
  • How fast? Much faster than the device can respond: an LED must run above about 100 Hz to avoid visible flicker; a motor, whose inertia and inductance smooth the current, works well at hundreds of Hz to several kHz.
  • Why needed: a pin can only be 0 V or 5 V, but we want a dimmed LED or a motor at half speed.

Duty cycle and average voltage

Duty cycle = thigh / (thigh + tlow) × 100 % = thigh / period × 100 % = pulse width / period × 100 %.
Average voltage = duty cycle × Vhigh. Example: 5 V pulses with a 50 % duty cycle average 2.5 V; 0 % gives 0 V and 100 % gives 5 V (the multimeter in the lecture reads 0.00 V, 2.50 V, 5.00 V).

Frequency = 1 / period; for a given frequency, a larger duty cycle means more energy to the load (brighter LED, faster motor).

2. How a timer generates PWM (8-bit timer)

  1. The oscillator (through the prescaler) increments the TCNTn register from BOTTOM (0) to TOP.
  2. A comparator continuously compares TCNTn with the Output Compare Register OCRnX (X = A or B), a value that software writes (the pulse width).
  3. On a compare match the waveform generator changes the OCnX pin (and sets the flag OCFnX in TIFRn).
  4. The waveform generator generates one PWM cycle per timer cycle; software only changes OCRnX to change the duty cycle, with no CPU involvement for the waveform itself.
Mode of the outputBehaviour
Non-inverted (COMnX1:0 = 10)Clears OCnX on the compare match and sets it when the timer comes to BOTTOM. High from 0 until the match, low from the match to TOP: larger OCR means higher duty.
Inverted (COMnX1:0 = 11)Sets OCnX on the compare match and clears it at BOTTOM. Larger OCR means lower duty.

The OCnX output pins: OC0A = PD6 (Arduino 6), OC0B = PD5 (5), OC1A = PB1 (9), OC1B = PB2 (10), OC2A = PB3 (11), OC2B = PD3 (3). The pin must be configured as an output in DDR.

PWM frequency

F_Timer = F_CPU / prescale
FPWM = F_Timer / (TOP + 1) = F_CPU / ((TOP + 1) × prescale) (fast PWM and the generic form in the lecture). TOP = 28 − 1 = 255 for 8-bit timers and 216 − 1 = 65 535 for 16-bit timers. Choose the prescale that gives the required frequency.

For the 8-bit Timer0 at 16 MHz: prescale 1: 62.5 kHz; 8: 7.81 kHz; 64: 976.6 Hz ≈ 1 kHz; 256: 244 Hz; 1024: 61 Hz (too low for LEDs).

3. Timer modes

The mode decides how the timer behaves. It is selected with WGMn2 (TCCRnB bit 3) and WGMn1, WGMn0 (TCCRnA bits 1, 0):

WGMn2WGMn1WGMn0ModeTOP
000Normal255 (0xFF)
001Phase Correct PWM255
010CTC (Clear Timer on Compare)OCRnA
011Fast PWM255

Normal mode

  • TCNTn increments from 0 to TOP, overflows to 0 and starts again; sets TOVn in TIFRn when it overflows; interrupts on overflow if enabled (lesson 6). No PWM support.

CTC mode

  • TOP is programmable: TCNTn counts from 0 to OCRnA, then is cleared to 0 and starts again.
  • Sets OCFnX in TIFRn when TCNTn equals OCRnX (a compare match); interrupts on the compare match if the output compare interrupt is enabled (OCIEnA / OCIEnB in TIMSKn; vector TIMERn_COMPA_vect). No PWM support.
  • Use: exact periodic events. Period = (OCRnA + 1) × prescale / F_CPU. Example: 1 ms with prescale 64: OCR0A = 16 MHz/64/1000 − 1 = 249.

Fast PWM mode

  • TCNTn increments from 0 to TOP, overflows to 0 and starts again (a sawtooth). OCnX is cleared at the compare match during the increment and set when TCNTn becomes 0 (non-inverted).
  • Duty cycle = (OCR + 1) / (TOP + 1) × 100 % (note the +1: OCR = 0 still gives a 1/256 pulse).
  • FPWM = F_CPU / (256 × prescale) for an 8-bit timer.

Phase correct PWM mode

  • TCNTn increments from 0 to TOP and then decrements from TOP to 0 and repeats (a triangle). OCnX is cleared at the compare match while counting up and set at the compare match while counting down (non-inverted), so the pulse is symmetric about the centre of the cycle.
  • Duty cycle ≈ OCR / TOP × 100 %. FPWM = F_CPU / (2 × TOP × prescale) = F_CPU / (510 × prescale) for 8 bits, which is half the frequency of fast PWM at the same prescale.

Arduino's analogWrite() uses fast PWM on pins 5 and 6 (about 977 Hz) and phase correct PWM on pins 3, 9, 10, 11 (about 490 Hz), all with prescale 64, and analogWrite(pin, value) sets the duty cycle value / 255.

Timer2's prescaler table differs (011 = /32, 100 = /64, 101 = /128, 110 = /256) and Timer1 selects its mode with WGM13:0, so for the lecture and the exam use Timer0 (pins 5 and 6) unless the question gives the table.

Steps to generate PWM with Timer0 (fast, non-inverted, about 1 kHz, on OC0A = PD6)1) DDRD |= (1<<DDD6) output. 2) Mode: WGM02 = 0, WGM01 = WGM00 = 1. 3) COM0A1 = 1, COM0A0 = 0. 4) Prescale 64: CS02 = 0, CS01 = 1, CS00 = 1. 5) Write the pulse width to OCR0A (0 to 255).

5. System 15: fader (fade an LED again and again)

Hardware: LED with a 220 Ω resistor on PD6 (OC0A, Arduino 6), cathode to GND.

Algorithm: configure PD6 as output; WGM = fast PWM; COM = non-inverted; PWM frequency about 1 kHz; loop: pulse width = 255; while pulse width ≥ 0: set OCR0A = pulse width, delay 30 ms, decrement by 5.

#include <avr/io.h>                       // IO definitions
#define F_CPU 16000000UL                   // CPU clock for delay.h
#include <util/delay.h>

int main(void)
{
    DDRD  = DDRD | 0b01000000;                              // PD6 (OC0A) output
    TCCR0B = TCCR0B & 0b11110111;                           // WGM02 = 0
    TCCR0A = TCCR0A | 0b00000011;                           // WGM01 = WGM00 = 1: fast PWM
    TCCR0A = (TCCR0A & 0b10111111) | 0b10000000;            // COM0A1 = 1, COM0A0 = 0: non-inverted
    TCCR0B = (TCCR0B & 0b11111011) | 0b00000011;            // CS02 = 0, CS01 = CS00 = 1: /64, about 1 kHz
    while (1)
    {
        for (int pulseWidth = 255; pulseWidth >= 0; pulseWidth -= 5)
        {
            OCR0A = pulseWidth;                             // set output compare value
            _delay_ms(30);
        }
    }
    return 0;
}

The same with labelled constants: DDRD |= (1<<DDD6); TCCR0B &= ~(1<<WGM02); TCCR0A |= (1<<WGM01)|(1<<WGM00); TCCR0A = (TCCR0A & ~(1<<COM0A0)) | (1<<COM0A1); TCCR0B = (TCCR0B & ~(1<<CS02)) | (1<<CS01) | (1<<CS00);

// Arduino wrapper version
int ledPin = 6;                              // PWM pin
void setup() { pinMode(ledPin, OUTPUT); }
void loop() {
  for (int pulseWidth = 255; pulseWidth >= 0; pulseWidth -= 5) {
    analogWrite(ledPin, pulseWidth);         // output pulses of the given width
    delay(30);
  }
}

The brightness falls from 100 % to about 0 % in 52 steps of 30 ms (about 1.6 s) and then repeats. Note OCR = 0 still outputs a 1/256 duty pulse in fast PWM; to get a true 0 % disconnect the pin (COM0A1 = 0) and write the pin low.

6. True analog output

PWM only approximates an analog output. Three options for a real analog voltage: (1) switch to a microcontroller with a built-in DAC (for example Arduino Due); (2) add a DAC breakout board; (3) pass the PWM signal through an RC low-pass filter, which averages the pulses into a smooth voltage (the cut-off must be well below the PWM frequency).

7. Exercise 6: auto fan (worked)

Specification: drive the 3 to 6 V DC motor of a fan from the room temperature sensed by an LM35: full speed at 35 °C or higher, off at 25 °C or lower, and a smooth increase or decrease in between. This demonstrates: physical phenomenon → analog voltage (LM35) → discrete number (ADC) → processed → analog-like output (PWM) → actuator.

Design

PartConnection

For a 3 to 6 V motor drawing about 100 mA: BC547 with RB = (5 − 0.7)/(100 mA/10) = 430 Ω, so 470 Ω. (A 2N7000 is the better choice for PWM.) Use a separate supply if the fan draws more than the Arduino 5 V rail can give.

Mapping

Temperature T (°C) = ADCW × 1.1 / 1024 × 100 with the internal 1.1 V reference (finer 0.107 °C steps). Duty: T ≤ 25 °C → 0; T ≥ 35 °C → 255; otherwise pulseWidth = (T − 25) / (35 − 25) × 255 (linear). Example: 30 °C gives 127 (about 50 %).

// Q2: Arduino wrapper functions
const int motorPin = 6;
void setup() {
  analogReference(INTERNAL);                 // 1.1 V
  pinMode(motorPin, OUTPUT);
}
void loop() {
  float t = analogRead(A0) * 1.1 / 1024 * 100;      // temperature in Celsius
  int duty;
  if      (t <= 25) duty = 0;
  else if (t >= 35) duty = 255;
  else                duty = (int)((t - 25) * 255 / 10);
  analogWrite(motorPin, duty);
  delay(200);
}
// Q3: C in the Arduino IDE without any wrapper functions
#include <avr/io.h>
int main(void)
{
    DDRD  |= (1<<DDD6);                                  // PD6 = OC0A output
    TCCR0A = (1<<COM0A1) | (1<<WGM01) | (1<<WGM00);       // fast PWM, non-inverted
    TCCR0B = (1<<CS01) | (1<<CS00);                     // /64, about 977 Hz
    ADMUX  = (1<<REFS1) | (1<<REFS0);                    // 1.1 V reference, channel ADC0
    ADCSRA = (1<<ADEN) | (1<<ADPS2) | (1<<ADPS1) | (1<<ADPS0);  // enable, F_CPU/128
    while (1)
    {
        ADCSRA |= (1<<ADSC);
        while (ADCSRA & (1<<ADSC));
        float t = ADCW * 1.1 / 1024 * 100;
        if (t <= 25)
        {
            TCCR0A &= ~(1<<COM0A1);                    // disconnect OC0A
            PORTD  &= ~(1<<PORTD6);                    // pin low: motor really off
        }
        else
        {
            TCCR0A |= (1<<COM0A1);                     // connect OC0A
            OCR0A = (t >= 35) ? 255 : (unsigned char)((t - 25) * 255 / 10);
        }
    }
}
Common mistakes1) PWM pin not set as output. 2) Using a non-PWM pin with analogWrite (only 3, 5, 6, 9, 10, 11). 3) Driving the motor directly from the pin; no flyback diode. 4) Timer0 changes also affect delay()/millis() in Arduino (they use Timer0). 5) Forgetting that fast PWM has a minimum 1/256 pulse at OCR = 0. 6) Using the wrong CS bits for the target frequency. 7) Integer division: write (t - 25) * 255 / 10 with floating t. 8) Mixing up inverted and non-inverted.
