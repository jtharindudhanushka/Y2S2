Short note: revision sheet

TopicRemember
PollingCPU checks devices repeatedly. Misses fast events, wastes CPU, no priority. Button tested with (PIND & (1<<PIND2)) == 0.
InterruptDevice interrupts CPU; return address pushed on stack; jump via vector table to ISR; RETI resumes. Priority by vector address (lower = higher).
C tools#include <avr/interrupt.h>; sei(), cli(); ISR(XXX_vect); volatile shared variables.
VectorsINT0_vect, INT1_vect, PCINT0/1/2_vect (B/C/D), TIMER0/1/2_OVF_vect, USART_RX_vect, USART_UDRE_vect, USART_TX_vect, ADC_vect.
External INTINT0 = PD2, INT1 = PD3. EICRA: ISCn1 ISCn0 = 00 low, 01 change, 10 falling, 11 rising. EIMSK bit INTn enables.
Pin changePCICR PCIE0/1/2 (B/C/D) + PCMSKn bit. PD2 = PCINT18 (PCMSK2). Fires on any change, so test the pin in the ISR.
ArduinoattachInterrupt(digitalPinToInterrupt(pin), isr, FALLING); modes LOW, CHANGE, RISING, FALLING; pins 2 and 3 only.
DebounceContact bounce = many edges. 100 nF across the switch.
ISR rulesShort, no delays, volatile, both enable levels set.
Click counter8 LEDs (0 to 255), 2 buttons on INT0 / INT1 with 100 nF, PD0/PD1 reserved, unsigned char count, display() maps bits to ports.
ExamPaper is set from the learning outcomes. Register names/bits are given; know which register does what.
MultitaskingOne CPU only seems to do tasks at once; true parallel = multi-core (multiprocessing). No OS, so it is the programmer's job.
Polling problems1) misses fast changes or long intervals, 2) no priority, 3) wastes CPU on checking.
ISR rulesNo return, no parameters (called by hardware at unknown time). Share data via volatile globals. Keep short. Interrupts off by default (power). Missing avr/interrupt.h = won't compile.
LabelsPin 2 = PD2 = INT0 = PCINT18; use the label that matches the use.
Capacitor104 = 100 nF; K = ±10%; 2E = 250 V; electrolytic is polarised. Debounce: 100 nF across the switch.
ArduinoattachInterrupt(digitalPinToInterrupt(2), f, FALLING); no official pin change interrupts.
