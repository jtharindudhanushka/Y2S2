1. What the practical exam looks like

The only past question available (a photo of the projected screen, an INTE practical exam from 2018) reads:

"Cogni tester"The diffuse axonal injury is a disorder that affects negatively one's cognitive skill to detect, process, and respond to a stimulus. The "cogni tester" is an embedded system used in healthcare to measure the response time of a patient suffering from this disorder accurately to the nearest millisecond.
On every start/restart of the "cogni tester", it waits for a random time period between 1 and 10 seconds. Upon the expiration of this waiting time, the "cogni tester" turns on an LED as a stimulus.
The patient is then supposed to press the "respond" pushbutton on the system as quickly as possible to respond to the stimulus. The "cogni tester" then turns off the LED used as stimulus and measures the time elapsed between the stimulus and the patient's response to the stimulus in milliseconds.
Finally, the "cogni tester" transmits the measured response time to a connected PC over USB using a serial to USB interface and displays the patient's response time to the stimulus on a text terminal in milliseconds.

2. The exam workflow (follow it every time)

  1. Read the whole question and underline every requirement (times, ranges, units, which LED colours, which messages). Note the accuracy required (for example "nearest millisecond").
  2. Plan the pins before touching the board: write a table (function, Arduino pin, port bit, connection). Keep PD0/PD1 (pins 0, 1) free when serial is used; use pins 2 and 3 for external interrupts, 4 and 5 for T0/T1 counters, 6, 5, 9, 10, 11, 3 for PWM, A0 to A5 for analog.
  3. Calculate resistors (R = (Vs − VL)/IL, round up), timer values (initial = max − n + 1), UBRR, ADC thresholds. Do the maths on paper with the working shown; examiners mark working.
  4. Assemble the circuit on the breadboard: power rails, common GND first; LED polarity (long leg to the resistor/pin, cathode to GND); buttons from pin to GND with internal pull-up; sensors to the right pin. Check it twice before powering up.
  5. Write the firmware in small steps: configure pins, test one LED, then the button, then the timer, then serial. Compile after each step.
  6. Upload: select the right board (Arduino Uno) and COM port. Disconnect anything from pins 0 and 1 while uploading.
  7. Test with the terminal (Serial Monitor at the same baud rate) and fix. Keep a working version before making improvements.

4.3 Firmware in C (registers, timer time base)

#include <avr/io.h>
#include <avr/interrupt.h>
#include <stdlib.h>                                   // rand, srand, ultoa

volatile unsigned long ms = 0;                         // milliseconds since the timer started

ISR(TIMER0_OVF_vect)                                   // every 1 ms
{
    TCNT0 = 6;                                         // 250 counts of 4 us = 1 ms
    ms++;
}

static unsigned long now(void)                         // atomic read of the 32-bit counter
{
    unsigned long t;
    cli(); t = ms; sei();
    return t;
}

static void txChar(char c)
{
    while (!(UCSR0A & (1<<UDRE0)));                   // wait for data register empty
    UDR0 = c;
}
static void txString(const char *s) { while (*s) txChar(*s++); }

int main(void)
{
    DDRB  |=  (1<<DDB0);                              // stimulus LED output
    DDRD  &= ~(1<<DDD2);                              // respond button input
    PORTD |=  (1<<PORTD2);                             // pull-up

    UBRR0  = 16000000UL / (16 * 9600UL) - 1;           // 9600 baud: 103
    UCSR0B &= ~(1<<UCSZ02);
    UCSR0C |= (1<<UCSZ01) | (1<<UCSZ00);              // 8 bit
    UCSR0B |= (1<<TXEN0);                              // transmitter on

    ADMUX  = (1<<REFS0) | (1<<MUX2) | (1<<MUX0);      // AVcc, channel ADC5 (floating pin)
    ADCSRA = (1<<ADEN) | (1<<ADPS2) | (1<<ADPS1) | (1<<ADPS0);
    ADCSRA |= (1<<ADSC);
    while (ADCSRA & (1<<ADSC));
    srand(ADCW);                                       // different seed on every start

    TCNT0   = 6;                                       // Timer0: 1 ms time base
    TCCR0B  = (1<<CS01) | (1<<CS00);                  // F_CPU/64
    TIMSK0 |= (1<<TOIE0);                             // overflow interrupt
    sei();

    unsigned long waitMs = 1000UL + (rand() % 9001);   // 1000..10000 ms
    unsigned long t0 = now();
    while (now() - t0 < waitMs);                       // random waiting time

    PORTB |= (1<<PORTB0);                              // stimulus: LED on
    unsigned long start = now();
    while (PIND & (1<<PIND2));                       // wait until "respond" is pressed (pin low)
    unsigned long response = now() - start;
    PORTB &= ~(1<<PORTB0);                             // LED off

    char buf[11];
    ultoa(response, buf, 10);                          // number to text
    txString("Response time: ");
    txString(buf);
    txString(" ms\r\n");
    while (1);                                         // done: wait for restart
}

4.4 Firmware with the Arduino wrapper functions

const int stimulusLed = 8, respondBtn = 2;

void setup() {
  Serial.begin(9600);
  pinMode(stimulusLed, OUTPUT);
  pinMode(respondBtn, INPUT_PULLUP);
  randomSeed(analogRead(A5));                    // floating pin: different seed each start
}

void loop() {
  digitalWrite(stimulusLed, LOW);
  delay(random(1000, 10001));                    // 1 to 10 s
  digitalWrite(stimulusLed, HIGH);               // stimulus
  unsigned long start = millis();
  while (digitalRead(respondBtn) == HIGH);       // wait for the response
  unsigned long response = millis() - start;     // elapsed time in ms
  digitalWrite(stimulusLed, LOW);
  Serial.print("Response time: ");
  Serial.print(response);
  Serial.println(" ms");
  while (true);                                  // stop until restart
}
Improvements that earn marks1) False start: if the button is already pressed when the stimulus is due (or during the wait), print "False start" instead of a time. 2) Debounce the button with a 100 nF capacitor. 3) Make the time base exact with CTC (OCR0A = 249 with prescale 64) if the examiner asks for better than 1 ms drift. 4) Mention that millis() has 1 ms resolution and uses Timer0.

4.5 Likely viva questions

  • Why does the seed need to change? (Same seed = same sequence after every reset.) Why a floating analog pin? (Noise gives an unpredictable value.)
  • How accurate is the measurement? (Timer tick 4 µs, 1 ms counter; loop latency small, so about ±1 ms.)
  • Why is the button wired to GND with the pull-up? (No external resistor; pressed = 0.)
  • Why must ms be volatile and read with interrupts disabled? (Shared with the ISR; a 32-bit read takes several instructions and could be interrupted mid-read.)
  • What happens at 115 200 baud? (−3.55 % error, unreliable.)

6. Rules of thumb for the practical

  • If it says "C using direct register access" do not use pinMode, digitalWrite, Serial and so on at all. If it says Arduino wrapper functions, use them.
  • In the Arduino IDE you may write int main(void) in C (as in Exercises 2, 6, 7) and then setup()/loop() are not used.
  • Pull-up on every button input. Resistor on every LED. Flyback diode on every motor/relay. Common ground everywhere.
  • Declare shared variables volatile; keep ISRs short; never _delay_ms in an ISR.
  • #define F_CPU 16000000UL before #include <util/delay.h>.
  • Use 5.0 / 1024 (floating point, 1024) for ADC to volts.
  • Always include a while(1) loop in bare C main().
  • Time budget: plan 15 %, build 25 %, code 35 %, test and fix 25 %. A working simple version beats an unfinished perfect one.
