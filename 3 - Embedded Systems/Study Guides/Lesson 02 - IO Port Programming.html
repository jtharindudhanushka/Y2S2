1. I/O ports and registers

I/O ports read the state of the physical world through sensors and drive actuators to change it. Each port (B, C, D on the ATmega328P) has three registers. The letter x stands for the port name (a, b, c, ...).

RegisterNamePurpose
DDRxData Direction RegisterBit = 1 makes the pin an output (set); bit = 0 makes it an input (clear)
PORTxPort output registerAs output: 1 = high (5 V, LED on), 0 = low. As input: 1 enables the internal pull-up resistor
PINxPort input registerRead the logic level actually present on the pins

Memory aid: Direction, Port (write), Pin (read). Data in = input, data out = output.

Example (slide)DDRx = 11110000 and PORTx = 10100000. The upper four pins are outputs: bit 7 = 1 (high, LED on), bit 6 = 0 (LED off), bit 5 = 1 (on), bit 4 = 0 (off). The lower four are inputs.

2. Electricity, resistors and diodes

  • Current is the flow of electrons; voltage is the pressure that pushes it (water analogy: more pressure, more flow). Ohm's law: V = I R.
  • An LED is a diode: current flows only from anode to cathode. The cathode is the flat edge on the body flange / the shorter leg. An LED must have a series resistor.
Series resistor for an LED R = (VS − VL) / IL.
Exercise 1(a): VS = 5 V, VL = 2 V, IL = 15 mA, so R = (5 − 2) / 0.015 = 200 Ω, use the next standard value 220 Ω (never a smaller one, which would exceed the current).

3. Hardware: ATmega328P pins and breadboard

  • PB0 to PB5 are Arduino pins 8 to 13; PD0 to PD7 are pins 0 to 7; PC0 to PC5 are A0 to A5 (see lesson 1).
  • On a breadboard the holes in each column of five (in the main area) are connected vertically; the power rails run horizontally.
  • Wiring (slide): Arduino pin → resistor → LED anode; LED cathode → GND.

Delay calculation (the part the exam loves)

  1. Clock cycle time t = 1 / f = 1 / (16 × 106) = 62.5 ns.
  2. Cycles needed for 0.5 s: n = d / t = 0.5 / 62.5 ns = 8 × 106.
  3. Innermost loop with counter 255 (8-bit register, maximum 255): the branch is taken 254 times (DEC 1 + BRNE 2 = 3 cycles) and falls through once (DEC 1 + BRNE 1 = 2 cycles).
    n3 = (1 + 2) × 254 + (1 + 1) × 1 = 764
  4. Two loops: add the LDI of the inner counter.
    n2 = (1 + n3 + 1 + 2) × 254 + (1 + n3 + 1 + 1) × 1 = (1+764+1+2)×254 + (1+764+1+1) = 195 839
  5. Three loops: outer counter 41 gives 8 × 106 / 195 839 = 40.8, so take 41 (the larger value).
    n1 = (1 + 195 839 + 1 + 2) × 40 + (1 + 195 839 + 1 + 1) × 1 = 8 029 562
  6. Add the first LDI R16: n = 1 + n1 = 8 029 563 cycles, so d = t × n = 62.5 ns × 8 029 563 = 0.50185 s ≈ 0.5 s.

General rule: a loop whose body (excluding its own DEC and BRNE) takes b cycles and which repeats N times costs (b + 1 + 2)(N − 1) + (b + 1 + 1).

Exact delays with the NOP trick (peer notes)With R16 = 72, R17 = 188, R18 = 196: n3 = 587, n2 = 111 107, n1 = 7 999 991, so n = 7 999 992 cycles. Only 8 cycles short of 8 000 000, so add 8 × NOP (1 cycle each) for exactly 0.5 s. Another exact pair of counters: 200 ms = 3 200 000 cycles with R16 = 241, R17 = 25, R18 = 176 (3 199 998) plus 2 NOP.

The call overhead (CALL 4 cycles, RET 4 cycles) is usually ignored in lecture answers; mention it if asked for precision.

Programming and uploading

  • Microchip Studio: create an assembler project, select the device (ATmega328P), build to get the HEX file.
  • Programming options: a commercial programmer from the manufacturer, aftermarket / home-made programmers (USB or serial), or self-programming with a bootloader and a host application such as AVRDUDE (the Arduino way).
  • AVRDUDE tool settings in Microchip Studio: Command = path to avrdude.exe; Arguments = -C "avrdude.conf" -v -v -p atmega328p -c arduino -P COMx -b 115200 -U flash:w:"$(TargetName).hex":i; Initial directory = $(TargetDir).
  • Hardwired alternatives (transistors, a timer IC like the 555) make the same blinker, but the circuit is fixed: changing the rate means changing components, it takes more parts, space and cost, and it cannot be extended with more behaviour. The software version changes by editing one number.

5. System 2: blinkerC (C, every 200 ms)

#include <avr/io.h>
#define F_CPU 16000000UL      // must be defined BEFORE util/delay.h
#include <util/delay.h>

int main(void)
{
    DDRB = DDRB | 0b00000001;     // configure PB0 as output
    while (1)
    {
        PORTB = PORTB | 0b00000001;   // PB0 high (set bit)
        _delay_ms(200);
        PORTB = PORTB & 0b11111110;   // PB0 low (clear bit)
        _delay_ms(200);
    }
    return 0;
}

Bitwise operators: change one bit, keep the others

GoalExpressionWhy
Set bit nPORTB |= (1<<n)x | 1 = 1 and x | 0 = x
Clear bit nPORTB &= ~(1<<n)x & 0 = 0 and x & 1 = x
Toggle bit nPORTB ^= (1<<n)x ^ 1 flips the bit, x ^ 0 keeps it
Test bit n of an inputif (PIND & (1<<n)) (high) or if (!(PIND & (1<<n))) (low)mask all other bits

Example: xxxx xxxx | 0000 0001 = xxxx xxx1 and xxxx xxxx & 1111 1110 = xxxx xxx0 (only the interesting bit changes).

Styles for the same operation (all equal): binary constant 0b00000001; hex 0x01; shift (1<<0); and the labelled constants defined in avr/io.h: DDRB |= (1<<DDB0), PORTB |= (1<<PORTB0), PIND & (1<<PIND2). The shift style with labels is the easiest to read and to get right.

6. System 3: blinker (Arduino wrapper functions)

int ledPin = 8;                    // PB0

{

  delay(200);

  delay(200);
}

Comparison (lecture):

ApproachProsCons
AssemblyHighly efficient (smallest, fastest)Difficult to code, not portable
CEfficient, easier to code, libraries available, portableData type misuse possible
Arduino wrappersMuch easier to code, libraries availableInefficient (larger, slower), not portable

Why is Arduino inefficient although it also uses GCC and AVRDUDE? Because the wrapper functions do extra work: pinMode/digitalWrite look up the port and bit from tables, check whether the pin has PWM that must be turned off, and the Arduino core adds start-up code (init() configures timers, the millis() interrupt, serial hooks). The generated HEX is therefore larger and slower than direct register code.

Measured sizes from Exercise 2 (code ROM)Program 1 (register code, DDRB=0x01; PORTB=0x01; PORTB=0x00;) = 142 bytes; Program 2 (pinMode / digitalWrite) = 743 bytes. Both just blink an LED on pin 8 (PB0) as fast as the CPU can, so the LED looks half-lit; the size difference is the wrapper overhead.

7. Reading an input: System 4 dualRateBlinker

Task: blink an LED every 500 ms with no input, every 200 ms while a pushbutton is pressed.

  • The micro pushbutton is normally open and connects two points when pressed.
  • Wire the button between the input pin and GND. Enable the internal pull-up by setting the PORT bit of the input pin. Then the pin reads 1 when released and 0 when pressed (active low). No external resistor is needed.
  • To read a pin use PIN, not PORT.
#include <avr/io.h>
#define F_CPU 16000000UL
#include <util/delay.h>

int main(void)
{
    DDRB |=  (1<<DDB0);        // PB0 output (LED)
    DDRD &= ~(1<<DDD2);       // PD2 input (button)
    PORTD |= (1<<PORTD2);      // pull-up on PD2
    while (1)
    {
        PORTB |= (1<<PORTB0);                 // LED on
        if ((PIND & (1<<PIND2)) == 0) _delay_ms(200);   // pressed
        else                            _delay_ms(500);   // released
        PORTB &= ~(1<<PORTB0);                // LED off
        if ((PIND & (1<<PIND2)) == 0) _delay_ms(200);
        else                            _delay_ms(500);
    }
}
// Arduino version
const int ledPin = 8, switchPin = 2;
void setup() {
  pinMode(ledPin, OUTPUT);
  pinMode(switchPin, INPUT_PULLUP);          // input with pull-up
}
void loop() {
  int d = (digitalRead(switchPin) == LOW) ? 200 : 500;
  digitalWrite(ledPin, HIGH); delay(d);
  digitalWrite(ledPin, LOW);  delay(d);
}

digitalRead returns the current state (HIGH/LOW) of the pin. digitalWrite(2, !digitalRead(2)) toggles pin 2.

Question 3: ten LEDs with at most seven I/O pins

Use multiplexing of the ground side. Wire LED k of set 1 and LED k of set 2 to the same anode line (five lines, PB0 to PB4, each through a 220 Ω resistor). Connect the cathodes of set 1 to the collector of transistor Q1 and the cathodes of set 2 to the collector of Q2 (both BC547 NPN, emitters to GND). The bases connect through 1 kΩ resistors to PD6 and PD7. That is 5 + 2 = 7 pins. An LED lights only when its anode line is high and its set's transistor is switched on.

int main(void) {
    DDRB |= 0x1F;                   // PB0..PB4 anode lines
    DDRD |= (1<<DDD6) | (1<<DDD7); // transistor bases
    while (1) {
        // positions 0..9 forward, then 8..1 back
        for (int p = 0; p < 18; p++) {
            int pos = (p < 10) ? p : 18 - p;
            int set = pos / 5, led = pos % 5;
            PORTB = (PORTB & ~0x1F) | (1<<led);
            PORTD = (PORTD & ~((1<<PORTD6)|(1<<PORTD7))) | (set ? (1<<PORTD7) : (1<<PORTD6));
            _delay_ms(100);
        }
    }
}

Q2 (a) intended functionality, (b) code ROM sizes

(a) Both programs set pin 8 (PB0) as an output and then turn it on and off continuously with no delay, so the LED flashes extremely fast and appears dim or constantly on. (b) Program 1 (142 bytes) uses direct register access and compiles to a few instructions plus minimal start-up code. Q3: delay of a subroutine

DELAY: LDI R16, 0x69      ; 105
LOOP1: LDI R17, 0xFD      ; 253
LOOP2: DEC R17
       BRNE LOOP2
       DEC R16
       NOP
       BRNE LOOP1
       RET
  1. Inner loop (R17 = 253): n2 = (1 + 2) × 252 + (1 + 1) = 758 cycles.
  2. Outer loop body: LDI (1) + 758 + DEC (1) + NOP (1) + BRNE. Taken (2): 763 cycles × (105 − 1) = 79 352. Last pass falls through (1): 762.
  3. n1 = 79 352 + 762 = 80 114. Add the first LDI R16: 80 115 cycles; with RET (4): 80 119.
  4. Delay = 80 115 × 62.5 ns = 5.007 ms (about 5.0074 ms including RET; call overhead extra).
Common mistakes1) F_CPU defined after #include <util/delay.h>. 2) Writing DDRB = 0x01 (destroys other bits) instead of |=. 3) Reading PORTx instead of PINx. 4) LED without a resistor, or LED reversed. 5) No pull-up on the button input (floating pin). 6) BRNE counts: forgetting that the last iteration costs 1 less cycle.

2. What is an I/O port?

The big idea An I/O port is an 8-bit register that is physically wired to 8 pins of the chip. One bit = one pin. Write a bit and the pin voltage changes. Read a bit and you learn the voltage on the pin. That is how software touches the real world.
Figure 2. One bit of the register is wired to one pin of the chip.

3. The three registers of every port (x = B, C or D)

DDRx — Data Direction Register Chooses the direction of each pin.
1 = output (the chip drives the pin)
0 = input (the chip listens)
Memory trick: Input comes before Output, just as 0 comes before 1.
PORTx — Port Output Register If the pin is an output: 1 = pin HIGH (5 V), 0 = pin LOW (0 V).
If the pin is an input: writing 1 switches on the internal pull-up resistor.
PINx — Port Input Register Read only. Each bit shows the actual voltage on the pin: 1 = HIGH, 0 = LOW. Use it to read buttons and digital sensors.

7. How the delay is calculated (this is exam material)

Step 1: how many clock cycles equal 0.5 s? Clock = 16 MHz, so one cycle takes t = 1 / 16,000,000 = 62.5 ns.
Cycles needed: n = 0.5 s / 62.5 ns = 8,000,000 cycles. So we make the CPU do pointless work that takes 8 million cycles.
Figure 6. Three loops inside each other. Each outer loop runs the inner one many times.
The pattern for ONE loop that runs N times cycles = (body + 2) × (N − 1) + (body + 1) × 1
The body includes the DEC and, for an outer loop, the LDI and everything inside. The branch costs 2 each time it jumps back (N − 1 times) and 1 the last time.
Step 2 and 3: finish the calculation Total cycles = 1 (the first LDI R16) + n1 = 1 + 8,029,562 = 8,029,563 cycles
Delay d = t × n = 62.5 ns × 8,029,563 = 0.50185 s ≈ 0.5 s
Why 41 for R16? Cycles for one run of LOOP2 = 195,839. We need 8,000,000 / 195,839 ≈ 40.85, which we round up to 41. If you want it exact, add NOP instructions (1 cycle each) to pad the missing cycles.
Why 255? A register is 8-bit (0 to 255). Counting down from 255 gives the longest loop one register can make.
Exercise 1 (slide 36) change: loading R16 with 16 instead of 41 gives about 196 ms ≈ the 200 ms blinker.

10. Reading an input: the pushbutton

A micro pushbutton is normally open: it connects its two sides only while pressed. We connect it between the pin and GND, and switch on the pin's internal pull-up (DDR bit = 0, PORT bit = 1). Now the pin always has a defined voltage.

Figure 7. Released = 1. Pressed = 0. The button pulls the pin down to GND against the weak pull-up.
Rule to remember With a pull-up, pressed = 0 (LOW). Released = 1 (HIGH). It feels backwards, but it is the standard way.
To read: PINx only. To enable the pull-up: DDRx bit = 0 and PORTx bit = 1. The same PORTx register that drives outputs, enables the pull-up on inputs.

11. System 4: dualRateBlinker

Task: LED on PB5 toggles every 500 ms normally, but every 200 ms while the button on PB0 (Uno pin 8) is pressed. LED on PB5 (pin 13), button from PB0 to GND.

#include <avr/io.h>
#define F_CPU 16000000UL
#include <util/delay.h>

{

    DDRB &= ~(1 << DDB0);          // PB0 = input  (button)

}

P. Building circuits by hand (for the practical exam)

In the practical you must build the circuit yourself from a description, with no help. These pages cover the four skills you need: using a breadboard, drawing the schematic, wiring it, and finding faults.

P1. How a breadboard is connected inside

Figure P1. Columns of 5 holes are joined. The long rails are joined along their length (on some long boards the rail is split in the middle; check with a jumper). Chips and buttons sit across the centre gap.
  • Two legs in the same column are connected. To put two parts in series (one after the other), they must share one column and no more.
  • Never put both legs of a resistor or LED in the same column: that shorts it out and it does nothing.
  • Use the top rail for GND (−) and the next for +5 V (+). Join the Uno's GND and 5V to them first.

P2. Drawing the schematic (exam questions ask for it)

Figure P2. Standard symbols. Draw the chip as a box with the pin names you use (e.g. PB0, PD2), then connect parts to it. Always label values (220 Ω, 1 kΩ, 100 nF) and show +5 V and GND.

Pick pins: inputs needing interrupts on PD2/PD3, PWM outputs on 3/5/6/9/10/11, analog on A0–A5, never PD0/PD1.  3. Draw the chip box with only those pins labelled.  4. Each LED: pin → 220 Ω → LED → GND. Each button: pin → button → GND (internal pull-up), plus 100 nF across it if it uses an interrupt.  5. P5. When it does not work: check in this order

  1. Power and ground: Uno GND joined to the − rail? Every part's GND reaches that rail? (Most faults are a missing GND.)
  2. Columns: each pair of parts that should connect share a column; no part has both legs in one column; nothing is accidentally across the centre gap.
  3. Direction: LED long leg towards the pin; diode stripe the right way; transistor C/B/E order.
  4. Pin numbers: code uses the same pin you wired (pin 13 = PB5, pin 8 = PB0, A0 = PC0).
  5. Code: DDR set for every output; pull-up for every button; F_CPU before delay.h; sei() if you use interrupts.
  6. Upload: right board (Arduino Uno) and port; nothing plugged into pins 0 and 1 while uploading.
  7. Divide and test: upload the plain Blink sketch to prove the LED wiring, or print values with Serial.println to see what the code thinks.
Writing plain C in the Arduino IDE You can write int main(void) with registers directly in a .ino file instead of setup()/loop(). The IDE compiles it as normal C (Exercise 6 asks for this). Do not use Serial, millis() or delay() in that case, because the Arduino init() no longer runs; use _delay_ms() instead.

14. Exercise 1, question 3: ten LEDs on seven pins

Problem: 10 LEDs but a limit of 7 pins. Idea (multiplexing): put the LEDs in two sets of five. The same 5 pins (PB0 – PB4) feed the anode resistors of both sets. Each set's cathodes go to ground through its own BC547 transistor, which acts as a switch. Turn one transistor on and only that set can light. 5 + 2 = 7 pins. The model answer uses PD2 and PD3 for the two transistor bases.

Figure 10. Two BC547 transistors switch the ground of each set of five LEDs.
How it works, in order
  1. PD2 HIGH makes a small current flow through the 1 kΩ into the base of Q1 (about (5 − 0.7) / 1000 = 4.3 mA). The transistor turns on and connects Set 1's cathodes to GND.
  2. PD3 stays LOW, so Q2 is off: Set 2 has no path to GND and stays dark, even though it shares the same anode pins.
  3. Raising one of PB0–PB4 now lights the matching LED in Set 1 only.
  4. To use Set 2, swap: PD2 LOW, PD3 HIGH.
Why the 1 kΩ base resistor? It limits the base current, protecting both the pin and the transistor.
Why PD2 and PD3 and not PB6 / PB7? PB6 and PB7 drive the crystal on the Uno, so they are not available. PB0 – PB4 are already used by the LEDs.

Firmware (C): the model answer, explained

#include <avr/io.h>
#define F_CPU 16000000UL
#include <util/delay.h>

void chaseRight(void)
{
    while (!(PORTB & 0b00010000))      // repeat until bit 4 is set
    {
        _delay_ms(200);
        PORTB <<= 1;                   // shift the lit bit 1 place left
    }
}
void chaseLeft(void)
{
    while (!(PORTB & 0b00000001))      // repeat until bit 0 is set
    {
        _delay_ms(200);
        PORTB >>= 1;                   // shift the lit bit 1 place right
    }
}
int main(void)
{
    DDRB = 0b00011111;                   // PB0-PB4 outputs (LED pins)
    DDRD = 0b00001100;                   // PD2, PD3 outputs (transistor bases)
    PORTD = 0b00000100;                  // Q1 on: first set enabled
    PORTB = 0b00000001;                  // LED 0 on
    while (1)
    {
        chaseRight();                    // LEDs 0 to 4 (set 1)
        _delay_ms(200);                  // keep the last LED lit
        PORTD = 0b00001000;              // Q2 on, Q1 off: second set
        PORTB = 0b00000001;              // LED 5 on
        chaseRight();                    // LEDs 5 to 9 (set 2)
        chaseLeft();                     // LEDs 9 back to 5
        _delay_ms(200);
        PORTD = 0b00000100;              // back to the first set
        PORTB = 0b00010000;              // LED 4 on
        chaseLeft();                     // LEDs 4 back to 0
    }
}

The shift trick: only one bit of PORTB is 1 at a time. PORTB <<= 1 moves that bit one place left (LED 0 → LED 1 → …), >>= 1 moves it right. The while loops stop when the lit bit reaches the end (bit 4 or bit 0). The result is 200 ms per LED across all ten, then back.

L3. The AVR family, clock and clock sources

  • ATtiny = small, very low power, few pins, slower. ATmega = mid-range (ours). ATxmega = high-end, hundreds of I/O pins, more power, expensive. Atmel was later bought by Microchip.
  • The Uno clocks the chip at 16 MHz; the manufacturer allows up to 20 MHz. Overclocking beyond that is possible but the chip heats up and needs cooling.
  • Accuracy ranking of clock sources: crystal (most accurate) > ceramic resonator (cheaper, smaller; the Uno's main clock) > internal RC oscillator (least accurate, but needs no parts). Without an external clock the chip can run on its internal RC oscillator, and PB6/PB7 become free I/O pins.

L4. Pin multiplexing (one pin, several jobs)

  • Port C has only 7 pins (PC0–PC6), not 8.
  • PC6 = RESET. The bar over RESET means active low: the chip resets while the pin is LOW. If you configure the chip not to use reset, PC6 becomes an I/O pin, but then you can only reset by unplugging power.
  • PC0–PC5 = analog inputs or digital I/O. PD0/PD1 = RX/TX. PB6/PB7 = external clock, or I/O if the internal clock is used.
  • AVCC (pin 20) and its GND (pin 22) are a separate supply for the ADC; AREF (pin 21) supplies the ADC's reference voltage (Lesson 5).
  • After reset DDRx and PORTx are 0x00: every pin starts as an input and every output bit as LOW.
  • The ~ (tilde) next to an Arduino pin number marks a PWM-capable pin (Lesson 8).

L5. Electricity details he added

  • Electrons actually flow from the negative terminal to the positive; by convention we say current flows from + to −.
  • Current = how much charge flows. Voltage = the "pressure" difference that makes it flow; no difference, no flow (same tank height, same pipe = same pressure; wider pipe = more current).
  • Resistor tolerance band (the separate 4th band): gold = ±5%, silver = ±10%. A 100 Ω silver may be 90–110 Ω. Precision resistors (1%, 0.5%) cost more. Example: red-yellow-green = 2, 4, ×100 k = 2.4 MΩ.
  • Standard values: 200 Ω is not sold; choose between 180 and 220 Ω. Always pick the higher one (220): slightly less current is safe; slightly more is not.
  • LED: about 2 V and 2–20 mA. Don't call it an "LED light" or "LED diode": LED already means Light Emitting Diode.
  • Diode application he highlighted: reverse polarity protection (a diode in series stops current if a battery is connected backwards).

L6. The reset pull-up: why the 10 kΩ [EXAM]

RESET is held HIGH through 10 kΩ to 5 V; the reset button pulls it to GND. Why not just a wire to 5 V? Then pressing the button connects 5 V directly to GND: a short circuit. With the resistor the current is only I = V/R = 5 / 10,000 = 0.5 mA; without it the current is huge and damages the switch or the supply. A small resistor (100 Ω) is not enough either. He once gave a partially completed schematic containing deliberate errors in the exam and asked students to complete and correct it, and this was the error. Schematic convention: a dot where wires cross means they are joined; no dot means they just cross.

After programming, a product needs only: the chip, the clock source, the LED + resistor (whatever the task uses), and optionally the 10 kΩ + reset button. The USB chip, regulator and indicator LEDs are only for programming and convenience. You can program the chip on the Uno, then move it to your own board.

L7. Breadboard, and why it's called that

Inside: the top two and bottom two rows are joined horizontally (power rails); the middle columns are joined vertically, with a break in the middle. "You must keep this pattern in your mind." Early engineers soldered every prototype, which was slow to change, so one used his mother's wooden bread board with nails to connect parts quickly; the name stuck. Stripboard / dotboard ("Vero" is a brand) is the next step: parts soldered on a board with copper strips or dots, before a PCB.

L8. Why embedded programs have no end [EXAM concept]

On a PC, when your program ends, control returns to the operating system. A microcontroller has no OS, and the CPU's fetch–execute cycle can never stop. So if the program reached its last line, execution would "fall out" into empty memory. Therefore: flowcharts have no END node, and an endless loop is a must (while(1), JMP START, Arduino's loop()). In PC programming an endless loop is a bug; here it is required. Like a washing machine that repeats its cycle until switched off.

L9. Delay loops, assembly and the tools

  • Assembly is not a separate language: it is the processor's own instruction set written as opcode + operands. The instruction set summary is at the end of the datasheet, with the clock cycles of each instruction. Most AVR instructions take 1 cycle (RISC).
  • A delay is just a loop that does nothing for a number of cycles. Even NOP takes a cycle: the CPU never stops.
  • One 8-bit loop is far too short: at most 256 iterations × 62.5 ns ≈ 16 µs, so nested loops are needed. Use letters (X, Y, Z) for the loop counts and the formula works for any values.
  • [EXAM] "For the last three years I gave a delay calculation in the exam." A calculator is allowed.
  • Real delay libraries compute the loop counts from the requested time with an algorithm; the nested-loop method shows the principle.
  • Microchip (Atmel) Studio: New Project → AVR Assembler (or GCC C Executable) → select the device ATmega328P. Selecting the device adds m328pdef.inc, which maps names like DDRB to their memory addresses. Build → Build Solution makes the .hex in the Output Files folder. Syntax errors are caught; logic errors are not.
  • Blinker sizes: assembly 38 bytes vs about 936 bytes in Arduino. An oscilloscope (voltage vs time on screen) is used to measure the real timing.

L12. Hardwired vs software-based (exam discussion question)

An LED can blink with two transistors (astable multivibrator) or a 555 IC; the rate is set by R and C. Software is better because it is: flexible (change one line, e.g. 41 → 16 for 200 ms); easy to modify, debug and maintain; updatable remotely (firmware updates, even over the internet, with no product recall); cheaper in the long run; and the same generic hardware can become different products. That is why industry moved from hardwired to software.

L13. C details he stressed

  • avr/io.h is like a dictionary: it tells the compiler that DDRB is a certain memory address.
  • Without F_CPU the delay library assumes 1 MHz, so on a 16 MHz chip every delay runs about 16 times too short and the timing is wrong. Define F_CPU 16000000UL before including delay.h. UL = unsigned long, because the compiler treats a plain number as int, which cannot hold 16 million.
  • A home-made delay loop for (long i = 0; i <= 95000; i++); does not work: compiler optimisation sees it does nothing and removes it. It works only with optimisation disabled. Optimisation also does things like replacing a never-changed variable with its constant value.
  • Choose the smallest data type: student marks (0–100) → unsigned char (0–255, 8 bits), not int (16 bits on AVR, 32 on a PC), float (32 bits) or a string. char is just an 8-bit number.
  • C gives the programmer full control and full responsibility: no array bounds checking, no automatic memory freeing (memory leaks). Powerful, but mistakes are yours.
  • C is portable: the same source compiles for AVR, PIC or a PC with the right compiler. Assembly and Arduino code are not.

L14. Arduino under the hood, and when to use it

  • Arduino is not a language: it is a hardware/software platform. The language is C/C++; the compiler is GCC; the uploader is AVRDUDE. It was designed for non-technical users (e.g. fashion-design students, hobbyists), so friendliness was chosen over efficiency.
  • Wrapper functions ("sugar-coated medicine") hide the registers. pinMode calls digitalPinToBitMask, digitalPinToPort, portModeRegister, portOutputRegister…; digitalWrite also checks and turns off PWM, because the same function must work on Uno, Mega, Due, NodeMCU and more. Source: ...\hardware\arduino\avr\cores\arduino\wiring_digital.c.
  • The hidden main.cpp calls init(), then setup(), then for(;;) loop(); forever.
  • digitalWrite(8, HIGH); can be replaced by one register line, PORTB |= (1<<0);.
  • Efficiency ranking: all assembly > all C > a mix of Arduino + C + inline assembly. But first make the algorithm efficient: bad assembly is still bad.
  • Practical route (e.g. a hackathon robot): prototype quickly in Arduino → replace slow wrapper calls with register C → rewrite the most frequently called functions in inline assembly (asm inside C) → improve the algorithm. Like the memory hierarchy: speed where it matters most, within the time available.
  • "Just buy faster hardware" (e.g. Due at 84 MHz instead of Uno at 16 MHz) is the Arduino fans' argument. His counter: efficient firmware lets you use cheaper hardware. A good driver doesn't need a Ferrari.
  • This course uses the middle path: C with direct register access.

L17. Bitwise points he made

  • Why shifts instead of binary strings? With 8 bits you can count them; with 32-bit registers (what industry uses) counting 32 ones and zeros is error-prone. (1<<n) avoids it.
  • Shift = fast maths: left shift by n = multiply by 2n; right shift by n = divide by 2n (8 >> 2 = 2). Shifting is much cheaper for hardware than a multiplier. Bits shifted past the end are lost: in 8 bits, 16 << 4 = 0 (overflow).
  • Label constants (DDB5, PORTB0, PINB0) are defined in iom328p.h, which io.h includes for you. DDB5 is just 5. They make code readable.
  • [EXAM] Know all three styles (binary strings, shifts with numbers, shifts with labels) because "in the exam I may ask you to explain a code segment" in any of them.
  • Three ways to toggle in Arduino: a boolean state = !state; an int state ^= 1; or digitalWrite(13, !digitalRead(13)).
  • In C, an if is false only when the expression is 0; any other value is true. So if (PINB & (1<<0)) works without == 1.

L18. Two small practical tips

  • Micro switch legs: legs A–C are always joined, and B–D are always joined. Use diagonal legs (A and D, or B and C) and you always get the switch action.
  • 10 LEDs on 7 pins (assignment hint): split into two groups of five on the same 5 pins; give each group its GND through its own BC547 (1 kΩ base resistor); turn on one transistor at a time (section 14).

Written questions

W1. Explain the roles of DDR, PORT and PIN registers and show how a pushbutton and an LED are connected and configured on ATmega328P pins.

DDRx sets direction (1 output, 0 input). PORTx drives output pins high/low and, for an input pin, enables the internal pull-up when set. PINx reads the logic level of the pins. LED: PB0 through a 220 Ω resistor to the LED anode, cathode to GND, DDRB |= (1<<DDB0). Button: PD2 to GND, DDRD &= ~(1<<DDD2); PORTD |= (1<<PORTD2); so the pin reads 1 released and 0 pressed; test with (PIND & (1<<PIND2)) == 0.

W2. Calculate the cycle count and delay produced by: LDI R16,50 / L1: LDI R17,200 / L2: DEC R17 / BRNE L2 / DEC R16 / BRNE L1 on a 16 MHz AVR.

Inner loop (R17 = 200): (1+2)×199 + (1+1) = 599. Outer body = LDI (1) + 599 + DEC (1) + BRNE. Taken (2): 603 × 49 = 29 547. Last pass (1): 602. Total loops = 30 149; plus the first LDI R16 = 30 150 cycles. Delay = 30 150 × 62.5 ns = 1.884 ms.

W3. Compare assembly, C and Arduino wrapper functions for firmware development. Why is the Arduino HEX file bigger?

Assembly: most efficient, difficult, not portable. C: efficient, easier, portable, libraries, but data-type misuse possible. Arduino: easiest with libraries, but inefficient and not portable. Although it also uses GCC and AVRDUDE, wrapper functions such as digitalWrite look up port and bit tables, handle PWM pins and the core adds initialisation (timers, millis interrupt), so more instructions are stored; the 5-LED chaser took 920 bytes with Arduino, 200 bytes in C and 172 bytes with further optimisation.

W4. Describe how ten LEDs can be controlled with seven pins and write the firmware to light them one at a time.

Five anode lines (PB0 to PB4, each with 220 Ω) are shared by two sets of five LEDs. Each set's cathodes go to the collector of a BC547 NPN transistor (emitter to GND) driven through a 1 kΩ base resistor from PD6 or PD7. Switching the correct transistor on and one anode line high lights one LED. Firmware: for each position choose set = pos/5 and led = pos%5; PORTB = (PORTB & ~0x1F) | (1<<led) and enable only that set's base pin.

W5. Explain how a bootloader programs the microcontroller and give two drawbacks.

A small program pre-burned (once, with a hardware programmer) into the bootloader section of flash runs first after every reset. It talks over serial to a host application on the PC (AVRDUDE). If a new HEX is offered, it writes it into the application section and jumps to it; otherwise it jumps to the existing application. Drawbacks: it uses part of the flash, and it adds a start-up delay at every power-up.

W6. Why must an embedded program contain an endless loop, and why do its flowcharts have no END node?

There is no operating system to return control to and the CPU's fetch-execute cycle cannot stop. If the program reached its last instruction, execution would fall out into unused memory. So the program repeats forever (while(1), JMP START, loop()).

const int led[] = {8, 9, 10, 11, 12, 13};

void setup() {
  for (int i = 0; i < 6; i++) pinMode(led[i], OUTPUT);
  pinMode(btn, INPUT_PULLUP);

void show(int i) {
  int d = (digitalRead(btn) == LOW) ? 50 : 150;   // pressed = fast
  digitalWrite(led[i], HIGH);
  delay(d);
  digitalWrite(led[i], LOW);
}

  for (int i = 4; i > 0; i--)  show(i);          // back, ends not repeated
}

4. C version

#include <avr/io.h>
#define F_CPU 16000000UL
#include <util/delay.h>

static void show(int i)
{
    PORTB = (1<<i);                                  // only LED i on
    if ((PIND & (1<<PIND2)) == 0) _delay_ms(50);    // fast
    else                            _delay_ms(150);
}

int main(void)
{
    DDRB  |= 0b00111111;            // PB0..PB5 outputs
    DDRD  &= ~(1<<DDD2);           // PD2 input
    PORTD |=  (1<<PORTD2);          // pull-up
    while (1)
    {
        for (int i = 0; i < 6; i++)  show(i);
        for (int i = 4; i > 0; i--)  show(i);
    }
}

Note: _delay_ms() needs a compile-time constant argument, which is why the two branches each call it with a literal.
