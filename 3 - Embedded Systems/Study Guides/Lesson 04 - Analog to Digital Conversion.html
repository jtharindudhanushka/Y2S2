1. The need for an ADC

In the physical world everything is analog; in computers everything is digital. Analog sensors transform physical quantities into analog voltages. The ADC converts an analog voltage into a discrete number that the CPU can process.

The ATmega328P ADC: 10-bit, successive approximation, 6 external channels ADC0 to ADC5 on PC0 to PC5 (Arduino A0 to A5) plus an internal temperature channel, sharing one converter through an input multiplexer.

2. Resolution, reference voltage and interval size

  • The ADC converts any voltage between 0 and Vref into a number between 0 and 2resolution − 1.
  • Resolution = number of bits (10 here). Total intervals = 2resolution = 1024.
  • Interval size ΔV = Vref / 2resolution = Vref / 1024. It is the smallest change in input voltage the ADC can distinguish.
  • Vin = ADCW × Vref / 1024 (analog voltage = number of intervals × interval size) and ADCW = floor(Vin / ΔV).
  • Default Vref on our board = 5 V (AVcc), so ΔV = 5 / 1024 = 4.883 mV and the number range is 0 to 1023.

Number line: 0 V ... Vref with codes 0, 1, 2, ..., 1022, 1023 each covering one interval of width ΔV.

ADC valueInput voltage range
00 ≤ Vin < ΔV
1ΔV ≤ Vin < 2ΔV
nnΔV ≤ Vin < (n+1)ΔV
10231023ΔV ≤ Vin < 1024ΔV = Vref

The peer notes list the first row as "ADC = 1: 0 ≤ Vin < ΔV"; with the standard convention above the first interval is code 0.

1023 or 1024? (supplementary article)The datasheet says ADC = Vin / Vref × 1024. The range 0 to Vref is divided into 1024 equal intervals (1024 codes), each of width Vref/1024; the largest code 1023 covers Vref − ΔV ≤ Vin < Vref, so Vref itself is never reached. So use analogRead(A0) * 5.0 / 1024. The difference to 1023 is under 0.1 %, but with lower resolutions it matters (8 bits: Vref/256, not /255). Analogy: a clock shows hours 0 to 23, and 23 is not the last moment of the day.

Improving accuracy: a smaller ΔV

A smaller interval means a more accurate reading. Two ways: (1) increase the resolution; (2) with the resolution fixed, reduce Vref.

Successive approximation (the workbook)

The ADC finds the 10 bits from the MSB down. A DAC generates a trial voltage; a comparator tells whether Vin is above it. At each step the range is halved, which is why Vref is divided by a power of two.

  • ADLAR = 0: result right justified (ADCH holds bits 9 and 8, ADCL bits 7 to 0). ADLAR = 1: left justified (ADCH holds the top 8 bits), handy for an 8-bit reading from ADCH alone.

For full 10-bit accuracy the ADC clock should be about 50 to 200 kHz (datasheet), so at 16 MHz use F_CPU/128 = 125 kHz (ADPS2..0 = 111). A conversion takes 13 ADC clock cycles, about 104 µs. Arduino's analogRead() sets exactly this.

Steps to read the ADC in C1) PC0 input (DDRC &= ~(1<<DDC0)). 2) Set Vref (REFS). 3) Select the channel (MUX). 4) Set the prescaler (ADPS). 5) Enable the ADC (ADEN). 6) Start (ADSC). 7) Wait until ADSC = 0 (or the ADC interrupt). 8) Read ADCW.

4. System 8: voltMeter (polling) in C

Measure any voltage from 0 to 5 V and show it on five LEDs (PB0 to PB4) from a potentiometer wiper on PC0 (ADC0): above 0 V one LED, above 1 V two, ..., above 4 V all five. Hardware: 10 kΩ potentiometer between +5 V and GND with the wiper to PC0, five 220 Ω resistors and LEDs.

#include <avr/io.h>
int main(void)
{
    DDRB  = DDRB | 0b00011111;                        // PB0..PB4 outputs
    DDRC  = DDRC & 0b11111110;                        // PC0 (ADC0) input
    ADMUX = (ADMUX & 0b01111111) | 0b01000000;        // REFS1 = 0, REFS0 = 1: Vref = AVcc (5 V)
    ADMUX = ADMUX & 0b11111000;                       // MUX2..0 = 000: channel ADC0
    ADCSRA = ADCSRA | 0b00000111;                     // ADPS2..0 = 111: F_CPU/128
    ADCSRA = ADCSRA | 0b10000000;                     // ADEN: enable ADC
    while (1)
    {
        ADCSRA = ADCSRA | 0b01000000;                 // ADSC: start conversion
        while (ADCSRA & 0b01000000);                  // poll until the conversion is over
        float vIn = ADCW * 5.0 / 1024;                // input voltage
        PORTB = PORTB & 0b11100000;                   // all LEDs off
        if      (vIn > 4) PORTB = PORTB | 0b00011111; // 5 LEDs
        else if (vIn > 3) PORTB = PORTB | 0b00001111; // 4
        else if (vIn > 2) PORTB = PORTB | 0b00000111; // 3
        else if (vIn > 1) PORTB = PORTB | 0b00000011; // 2
        else if (vIn > 0) PORTB = PORTB | 0b00000001; // 1
    }
    return 0;
}

Peer note: at least one operand must be floating point (5.0 / 1024) otherwise integer division gives 0.

// Arduino wrapper version (LEDs on pins 8 to 12)
void setup() {
  pinMode(A0, INPUT);                              // not necessary
  for (int pin = 8; pin <= 12; pin++) pinMode(pin, OUTPUT);
}

  int value = analogRead(A0);                      // 0..1023

  for (int pin = 8; pin <= 12; pin++) digitalWrite(pin, LOW);

  else if (vIn > 3) n = 11;
  else if (vIn > 2) n = 10;
  else if (vIn > 1) n = 9;
  else if (vIn > 0) n = 8;
  for (int pin = 8; pin <= n; pin++) digitalWrite(pin, HIGH);
}

5. System 9: voltMeterUsingInterrupts

The ADC raises ADC_vect when a conversion completes, so the CPU is free to do another task in main() instead of waiting.

#include <avr/io.h>
#include <avr/interrupt.h>
int main(void)
{
    DDRB  = DDRB | 0b00011111;
    DDRC  = DDRC & 0b11111110;
    ADMUX = (ADMUX & 0b01111111) | 0b01000000;     // Vref = AVcc
    ADMUX = ADMUX & 0b11111000;                    // ADC0
    ADCSRA = ADCSRA | 0b00000111;                  // F_CPU/128
    ADCSRA = ADCSRA | 0b10000000;                  // enable ADC
    ADCSRA = ADCSRA | 0b00001000;                  // ADIE: enable ADC complete interrupt
    sei();                                         // global interrupts
    ADCSRA = ADCSRA | 0b01000000;                  // start the first conversion
    while (1) { /* can be used to perform another task */ }
    return 0;
}

6. Sensors: LDR and LM35

Light dependent resistor (LDR)

  • Its resistance falls as light intensity rises (VT900 series: tens of kΩ at 10 lux, hundreds of kΩ to MΩ in the dark).
  • Used in a voltage divider to turn light intensity into a voltage: Vin = V × R2 / (R1 + R2). With the LDR as R1 (top, to +5 V) and a fixed resistor R2 (bottom, to GND), a bright room (small R1) gives a high Vin and darkness gives a low Vin. Swap the positions to invert.
  • Choose R2 close to the LDR's mid-range resistance (about 10 kΩ for the kit LDR) so the voltage swings usefully.

LM35 temperature sensor

  • Outputs a voltage linearly proportional to temperature: 10 mV per °C. Temperature = Vout × 100 (°C when Vout in volts).
  • Range −55 °C to +150 °C. Pins: +V, Vout, GND.
  • With Vref = 5 V one ADC step is 4.88 mV, i.e. 0.49 °C. Using the internal 1.1 V reference gives 1.07 mV per step, i.e. 0.107 °C per step, covering 0 to 110 °C. Example: 25 °C = 0.25 V gives ADCW = 51 (5 V) or 232 (1.1 V).
// LM35 on A0, internal 1.1 V reference
analogReference(INTERNAL);                      // in setup()
float tempC = analogRead(A0) * 1.1 / 1024 * 100;     // = ADC x 0.1074
// C: ADMUX |= (1<<REFS1)|(1<<REFS0);   float tempC = ADCW * 1.1 / 1024 * 100;

After switching the reference voltage, discard the first reading (the reference needs time to settle).

7. Exercise 4: auto light (worked)

Specification: an LED turns on automatically at nightfall and off in the morning light, using a transducer; this shows the chain physical phenomenon → analog voltage → discrete number → digital output.

Design

PartConnection
LDR (R1)+5 V to LDR to node A0
10 kΩ resistor (R2)node A0 to GND
LED + 220 ΩArduino pin 8 (PB0) → 220 Ω → LED anode, cathode to GND

Bright: LDR small, A0 high (for example 4 V = ADC 819). Night: LDR large, A0 low. Use two thresholds (hysteresis) so the LED does not flicker around dusk: on when ADC < 300, off when ADC > 400 (tune with the actual LDR).

// Arduino wrapper functions
const int ledPin = 8, ldrPin = A0;
void setup() { pinMode(ledPin, OUTPUT); }
void loop() {
  int v = analogRead(ldrPin);
  if      (v < 300) digitalWrite(ledPin, HIGH);    // dark: light on
  else if (v > 400) digitalWrite(ledPin, LOW);     // bright: light off
  delay(100);
}
// C
#include <avr/io.h>
int main(void)
{
    DDRB  |=  (1<<DDB0);                              // LED output
    DDRC  &= ~(1<<DDC0);                              // PC0 input
    ADMUX  = (ADMUX & ~(1<<REFS1)) | (1<<REFS0);      // Vref = AVcc
    ADMUX &= ~((1<<MUX3)|(1<<MUX2)|(1<<MUX1)|(1<<MUX0));  // channel ADC0
    ADCSRA |= (1<<ADPS2)|(1<<ADPS1)|(1<<ADPS0);      // F_CPU/128
    ADCSRA |= (1<<ADEN);                             // enable ADC
    while (1)
    {
        ADCSRA |= (1<<ADSC);                          // start
        while (ADCSRA & (1<<ADSC));                   // wait
        unsigned int v = ADCW;
        if      (v < 300) PORTB |=  (1<<PORTB0);       // dark: on
        else if (v > 400) PORTB &= ~(1<<PORTB0);       // bright: off
    }
}

Question 4: controlling a 230 V AC lamp

SafetyMains voltage can cause serious injury, shock, fire or death. Do not build or test it unless supervised by a qualified person, and never put mains on a breadboard or use exposed wiring. This is a design discussion only.

The pin cannot switch mains or a relay coil directly. Use a relay driven by a transistor, so the low-voltage side is isolated from the mains side by the relay contacts:

  • Arduino pin 8 → 1 kΩ base resistor → BC547 NPN base; emitter to GND.
  • Collector → relay coil → +5 V (a 5 V coil, for example a relay module).
  • Flyback diode (1N4001) across the coil, cathode to +5 V and anode to the collector, to absorb the voltage spike when the coil switches off.
  • Mains side: the relay's COM and NO contacts in series with the live conductor to the lamp (properly rated contacts, fuse, insulated enclosure, correct isolation).
  • Firmware is unchanged: HIGH on the pin energises the relay and lights the lamp.
Common mistakes1) Integer division 5/1024 (use 5.0). 2) Reading ADCW before ADSC clears. 3) Forgetting ADEN. 4) Wrong prescaler (too fast ADC clock lowers accuracy). 5) Dividing by 1023. 6) Using an analog pin as digital output. 7) LM35 read with 5 V reference when the signal is below 1 V (wasteful resolution). 8) Mixing up LDR/resistor positions so day and night are inverted.

1. Why an ADC? Analog vs digital

The physical world is analog: temperature, light and position change smoothly and can take any value. A sensor turns that quantity into a voltage that also changes smoothly. The CPU only understands numbers (digital). The Analog to Digital Converter measures the voltage on a pin and gives the CPU a whole number for it.

Figure 1. Converting means sampling and rounding. The size of a step is the ADC's resolution.

2. The key idea: 1024 intervals between 0 V and Vref

The two formulas (learn both directions) ADC = Vin × 1024 / Vref  (round down)      Vin = ADC × Vref / 1024
Examples (Vref = 5 V): Vin = 2.5 V → ADC = 2.5 × 1024 / 5 = 512.   ADC = 300 → Vin = 300 × 5 / 1024 = 1.465 V.   ADC = 1023 → 4.995 V (the top interval).
Why 1024? Each of the 1024 codes is an interval of width Vref/1024. Code 1023 is the last interval, just under Vref, the same way a clock's "23" hour is not the end of the day. Using 1023 is a small (0.1%) but real error.

Getting a more accurate reading

The real voltage can be anywhere inside its interval, so the reading is uncertain by up to ΔV. To make ΔV smaller: (1) use more bits (fixed at 10 on this chip), or (2) lower Vref to just above the largest voltage you expect.

3. Inside the ADC: how it finds the number

Figure 3. Successive approximation: the logic makes a guess, the DAC turns the guess into a voltage, the comparator says "Vin is higher" or "lower", and the logic improves the guess one bit at a time.

Like guessing a number 0–1023 with yes/no questions. Start at the middle (512): is Vin above it? Keep that bit, halve the step, ask again. 10 questions find the exact interval. Worked example with Vin = 3.2 V (should give 655):

Result 655 = 3.2 × 1024 / 5 = 655.36 rounded down. ✓

Why the ADC clock is F_CPU / 128 The ADC needs its own slower clock: 50–200 kHz for full 10-bit accuracy. The prescaler divides the CPU clock: 16 MHz / 128 = 125 kHz (in range). /64 would give 250 kHz, too fast. ADPS2:0 = 111 selects /128.
How long a conversion takes About 13 ADC clocks: 13 / 125 kHz ≈ 104 µs (the very first conversion after enabling takes 25 clocks). So about 9,600 readings per second, fast for buttons, too slow for audio.
Sample & hold The input voltage is copied onto a tiny capacitor at the start, then held steady while the 10 comparisons run, so a changing signal does not confuse the search.

5. System 8: voltMeter (polling)

Task: measure 0–5 V from a 10 kΩ potentiometer on PC0 / ADC0 (A0) and show it as a bar of 5 LEDs on PB0–PB4 (pins 8–12). Above 0 V: 1 LED, above 1 V: 2 LEDs … above 4 V: 5 LEDs.

Figure 4. A potentiometer is a voltage divider you can turn: the wiper picks a fraction of 5 V.

Voltage divider: two resistors in series between 5 V and GND. The voltage at the middle is Vout = Vs × R2 / (R1 + R2), where R2 is the resistor to GND. Turning the knob moves the wiper, changing R1 and R2 (they always add up to 10 kΩ), so Vin goes smoothly from 0 to 5 V. This is the standard way to turn a changing resistance (pot, LDR, thermistor) into a voltage the ADC can read.

Example: wiper at 30% from the bottom: R2 = 3 kΩ, R1 = 7 kΩ, Vin = 5 × 3 / 10 = 1.5 V, ADC = 307, LEDs: 2.

#include <avr/io.h>

int main(void)
{
    DDRB = DDRB | 0b00011111;                    // PB0-PB4 outputs (LEDs)
    DDRC = DDRC & 0b11111110;                    // PC0 (ADC0) input
    ADMUX = (ADMUX & 0b01111111) | 0b01000000;   // REFS1 = 0, REFS0 = 1: Vref = AVcc (5 V)
    ADMUX = ADMUX & 0b11111000;                  // MUX = 000: channel ADC0
    ADCSRA = ADCSRA | 0b00000111;                // ADPS = 111: ADC clock = F_CPU/128
    ADCSRA = ADCSRA | 0b10000000;                // ADEN = 1: enable the ADC
    while (1)
    {
        ADCSRA = ADCSRA | 0b01000000;            // ADSC = 1: start a conversion
        while (ADCSRA & 0b01000000);             // wait while ADSC is still 1
        float vIn = ADCW * 5.0 / 1024;           // number -> volts
        PORTB = PORTB & 0b11100000;              // all 5 LEDs off
        if      (vIn > 4) PORTB = PORTB | 0b00011111;   // 5 LEDs
        else if (vIn > 3) PORTB = PORTB | 0b00001111;   // 4 LEDs
        else if (vIn > 2) PORTB = PORTB | 0b00000111;   // 3 LEDs
        else if (vIn > 1) PORTB = PORTB | 0b00000011;   // 2 LEDs
        else if (vIn > 0) PORTB = PORTB | 0b00000001;   // 1 LED
    }
    return 0;
}
LineMeaning
(ADMUX & 0b01111111) | 0b01000000Clear bit 7 (REFS1) then set bit 6 (REFS0): REFS = 01 = AVcc. The other bits are kept.
ADMUX & 0b11111000Clear MUX2..0, so channel 000 = ADC0 = A0.
ADCSRA | 0b00000111Prescaler /128 → 125 kHz ADC clock.
ADCSRA | 0b10000000Turn the ADC on. Set up first, enable last.
ADCSRA | 0b01000000Start one conversion. It must be restarted for every reading.
while (ADCSRA & 0b01000000);Polling the ADC: the empty loop spins while ADSC is 1 (~104 µs), then falls through when the hardware clears it.
ADCW * 5.0 / 1024Vin = ADC × Vref / 1024. Write 5.0, not 5: at least one number must be floating point, or /1024 is integer division and throws the fraction away.
PORTB & 0b11100000Turn the 5 LEDs off before lighting the right number, otherwise LEDs from a higher reading would stay on.

Labelled constants version: ADMUX = (1<<REFS0); ADCSRA = (1<<ADEN) | (1<<ADPS2) | (1<<ADPS1) | (1<<ADPS0); then ADCSRA |= (1<<ADSC); while (ADCSRA & (1<<ADSC));. Hex: ADMUX = 0x40; ADCSRA = 0x87;.

6. System 9: voltMeterUsingInterrupts

Instead of waiting in a loop for ~104 µs every reading, let the ADC interrupt when the result is ready. Main is then free for another task.

#include <avr/io.h>
#include <avr/interrupt.h>

int main(void)
{
    DDRB |= 0b00011111;                  // LEDs
    DDRC &= 0b11111110;                  // ADC0 input
    ADMUX = (ADMUX & 0b01111111) | 0b01000000;   // Vref = AVcc
    ADMUX &= 0b11111000;                 // ADC0
    ADCSRA |= 0b00000111;                // /128
    ADCSRA |= 0b10000000;                // ADEN
    ADCSRA |= 0b00001000;                // ADIE: interrupt when a conversion completes
    sei();                               // global interrupts on
    ADCSRA |= 0b01000000;                // start the FIRST conversion
    while (1) { }                        // free for another task
}

ISR(ADC_vect)                            // a result is ready
{
    float vIn = ADCW * 5.0 / 1024;
    PORTB &= 0b11100000;
    if      (vIn > 4) PORTB |= 0b00011111;
    else if (vIn > 3) PORTB |= 0b00001111;
    else if (vIn > 2) PORTB |= 0b00000111;
    else if (vIn > 1) PORTB |= 0b00000011;
    else if (vIn > 0) PORTB |= 0b00000001;
    ADCSRA |= 0b01000000;                // start the NEXT conversion
}

The cycle: main starts conversion 1 → ~104 µs later ADIF is set → ISR(ADC_vect) runs (ADIF cleared automatically), uses the result and starts conversion 2 → and so on forever. Forget the last line and the ISR runs only once.

7. Analog sensors

LDR (light dependent resistor)

Its resistance falls as light increases: roughly a few hundred Ω to ~1 kΩ in bright light, 100 kΩ or more in the dark (check the VT900 datasheet). The ADC cannot measure resistance, so put the LDR in a voltage divider with a fixed 10 kΩ.

Figure 5. LDR on top: more light → LDR smaller → Vin higher.
LightLDR (R1)Vin = 5×10/(R1+10)ADC
bright1 kΩ4.55 V930
room10 kΩ2.50 V512
dark100 kΩ0.45 V93

Swap the LDR and the 10 kΩ and everything reverses (dark gives a high reading). Either is fine; just know which way your code expects.

LM35 temperature sensor

An IC with 3 legs: +Vs, Vout, GND (flat face towards you, left to right). It outputs a voltage linearly proportional to temperature: 10 mV per °C, from 0 V at 0 °C. Range −55 to +150 °C (negative temperatures need an extra circuit; with the basic connection it reads from about +2 °C).

LM35 formulas Temperature (°C) = Vout × 100  (because 1 °C = 0.01 V)
With Vref = 5 V: T = ADC × 5.0 / 1024 × 100 = ADC × 0.488
Example: ADC = 62 → Vout = 0.303 V → 30.3 °C.
Resolution: one step = 4.88 mV = 0.49 °C. With the internal 1.1 V reference: 1.07 mV = 0.11 °C per step (but max 110 °C).

Readings jump by ±1 step? Normal: the true voltage sits on the edge of an interval and noise moves it. Take the average of several readings: sum += analogRead(A0) 8 times, then divide by 8.

Other analog sensors (Lesson 6 covers them)

Potentiometer, thumb joystick (two pots), accelerometer (3 voltages), water level, soil moisture, gas, sound: all give a voltage that the ADC reads exactly the same way.

8. Exercise 4 solved: the "auto light"

Spec: turn an LED on at nightfall and off in the morning light, using a light sensor. It shows the full chain: light → LDR resistance → voltage (divider) → number (ADC) → decision (CPU) → LED (actuator).

Figure 6. Auto light schematic.

Hysteresis: two thresholds, not one

At dusk the light changes slowly and the reading wobbles around a single threshold, so the LED would flicker on and off. Use two thresholds: switch ON below DARK, switch OFF only above LIGHT. Between them, keep the current state.

Choose the numbers by calibrating: print analogRead(A0) to the Serial Monitor (component test 04) in daylight and with the sensor covered, then pick DARK and LIGHT between those values.

Firmware, Arduino

const int ldrPin = A0, ledPin = 8;

Question 4: controlling a 230 V lamp

Figure 7. A relay lets 5 V logic switch mains safely (drawn for the exam; do not build it).

Why a relay? A pin gives 5 V and ~20 mA; a lamp needs 230 V AC. A relay is an electromagnet (coil) that closes a separate switch (contacts). The coil side is low voltage; the contact side is mains; they are electrically isolated.

Why a transistor? A relay coil needs more current (often 50–100 mA) than a pin can give. The pin drives a BC547 through 1 kΩ; the transistor switches the coil current (Lesson 6).

Why the diode? When the coil switches off it produces a large reverse voltage spike that can destroy the transistor. The 1N4001 across the coil (stripe to +5 V) gives that energy a safe path: the flyback diode.

Firmware: unchanged. PB0 HIGH now energises the relay instead of lighting an LED.

L. What the lecturer explained in the lectures (2020 recordings)

From the five ADC recordings (folders 13–17 in Embedded Systems Lectures). [EXAM] marks things he tied to the exam.

L1. What he expects you to know [EXAM] The learning outcome says describe how the ADC converts an analog input into a number, "not how to use the ADC. How to use it is simple; many people know. But how the conversion happens, you should be able to explain." He also said many people multiply by 5/1024 "blindly, without any clue": you must be able to say why (sections 2 and L4).

L2. Why an ADC (his words)

  • Everything in the physical world varies continuously (temperature, light, distance, pressure, speed, acceleration): this is analog. Inside a computer everything is discrete (1s and 0s): digital.
  • An analog sensor converts one form of energy into electrical energy (a voltage): an LM35 turns thermal energy into a voltage, an LDR turns light (radiation energy) into a voltage, and a potentiometer turns rotation (kinetic energy) into a voltage. The CPU can only process digital data, so the ADC converts the voltage into a number.
  • The input range follows the chip's operating voltage: a 5 V chip measures 0–5 V. A 10-bit ADC gives 0–1023; an 8-bit ADC on a 3.3 V chip would give 0–255 for 0–3.3 V (1.65 V → about 128). The range can be narrowed (e.g. 0–1.1 V) by changing the reference voltage.
  • The ATmega328P has one ADC with six input channels (ADC0–ADC5 = A0–A5 = PC0–PC5). Because there is only one converter, only one channel can be converted at a time. Some chips have several ADCs and can convert in parallel.
  • Port C pins are shared: a pin used as an ADC input cannot be a digital I/O pin at the same time, and vice versa.

L3. Successive approximation, his worked example [EXAM]

Block diagram: the input multiplexer picks the channel; AVCC is the ADC's own supply (normally equal to the chip's 5 V); the reference multiplexer picks Vref; the DAC turns the current guess into a voltage; the comparator outputs 1 if Vin > guess, else 0; the conversion logic stores each bit in the data register and feeds it back to the DAC. The ADMUX register controls both multiplexers.

The rule he used: first guess = Vref/2. If the comparator says 1, the next guess is previous + Vref/4; if 0, previous − Vref/4. Then ±Vref/8, ±Vref/16…: one step per bit. He explained it as "you don't know Vin but you know Vref, so compare Vin with slices of Vref and come closer each time".

4-bit ADC, Vin = 3 V, Vref = 5 V (his recap example)
StepGuessVin > guess?BitNext guess
12.5yes12.5 + 5/4 = 3.75
23.75no03.75 − 5/8 = 3.125
33.125no03.125 − 5/16 = 2.8125

Result 1001 = 9 (out of 0–15). It approximated 3 V as about 2.81 V. With 10 bits the same process runs 10 times and lands much closer to 3 V. He uploaded an Excel simulation of the 10-bit process: Lecture Materials/05 - 10-bit ADC.xlsx. Type any Vin and watch the bits.

More bits = more accurate, but slower Each bit costs one compare cycle: a 4-bit ADC needs 4 steps, 8-bit 8 steps, 12-bit 12 steps. A 12-bit ADC is the most accurate but takes the longest; an 8-bit one is quicker but coarser. The ATmega328P's 10-bit ADC is the middle ground. "Successively we come closer to the input voltage, so it is called successive approximation."

L4. The formulas, explained the way he did

  1. Range 0 to Vref is mapped onto 0 to 2resolution − 1, i.e. 0–1023. 0 to 1023 is 1024 values (like 0 to 2 is 3 values: 0, 1, 2).
  2. Step size = voltage range / number of steps = (Vref − 0) / 2resolution = Vref / 1024.
  3. Vin = number of steps × step size = ADCW × Vref / 1024. In Arduino: analogRead(A0) * 5.0 / 1024. Now you know why that line is written that way.
  4. Put "number of steps = 1": Vin = step size. So the step size is the smallest voltage (or change) the ADC can detect: 5 / 1024 = 4.88 mV; with the internal 1.1 V reference, 1.1 / 1024 = 1.07 mV.
  5. You cannot put more than Vref into the ADC (a student asked about 5.1 V): raise Vref first (never above the supply).
His accuracy example [EXAM] A sensor outputs 0–1 V. At 501 mV and then 503 mV (a 2 mV change): with Vref = 5 V (step 4.88 mV) the ADC gives the same number for both, so the change is lost. With Vref = 1.1 V (step 1.07 mV) it gives two different numbers. Resolution is fixed by the chip, but Vref you can choose, so choose it just above your sensor's maximum. For a 0–3 V sensor, put 3 V on AREF and select external. He said even some industry projects leave the default 5 V with a 0–1.5 V sensor and lose accuracy.

Two sensors with different references? Possible: set the reference (analogReference / REFS bits), read sensor 1, change the reference, read sensor 2. External AREF can be at most the supply voltage (5 V).

L5. The registers: extra points

  • Why two data registers? The result is 10 bits but registers are 8 bits. ADCL holds the low 8 bits; ADCH holds the top 2 bits (with six leading zeros). Combining them by hand is awkward, so the C compiler offers ADCW, a virtual 16-bit register that does it for you. It is not in the datasheet (an 8-bit chip has no 16-bit hardware register) and is not available in assembly, where you read ADCL and ADCH yourself.
  • ADSC (start conversion): you set it to start; the hardware clears it automatically when the result is ready. So while (ADCSRA & (1<<ADSC)); is polling the ADC.
  • ADIF is set when the conversion is over and the data registers are updated; ADIE lets that raise an interrupt. All ADCSRA bits are 0 after reset, and the ADC is off (ADEN = 0) to save power.
  • Prescaler: the ADC is slow (successive approximation), so it can't run at the CPU clock. ADPS = 000 is "reserved": you must choose a prescaler. The datasheet says below 200 kHz for full accuracy: 16 MHz / 128 = 125 kHz. With an 8 or 4 MHz CPU you would pick a smaller divider. If speed matters more than accuracy you may run faster than 200 kHz; the result is still reasonable, just less precise.
  • Arduino fixes the prescaler at 128, and analogRead uses polling. Arduino has no ADC-interrupt wrapper: another example of Arduino being inefficient. In C you control both.
  • ADMUX MUX bits: default 000 = ADC0 (A0). With several sensors on different channels: select the channel, then read; select the next, then read.

L6. Hardware he stressed in System 8

  • The ADC has its own supply pins: AVCC (pin 20) to 5 V and its GND (pin 22). They must be connected on a bare chip (the Uno does it for you).
  • Potentiometer = "potential meter": a variable resistor. A wiper slides on a circular resistive track, so the knob splits it into R1 (to 5 V) and R2 (to GND), forming a voltage divider: Vin = V × R2 / (R1 + R2). Fully clockwise R1 = 0, so Vin = 5 V; fully anticlockwise R2 = 0, so Vin = 0 V. Uses: volume controls, light dimmers, and the accelerator pedal of electric and hybrid cars.
  • One resistor for all 5 LEDs? (a student's idea) No. With three LEDs at 15 mA, one shared quarter-watt resistor would carry 45 mA and could burn, and LEDs of different colours draw different currents. Use a separate resistor per LED (or a resistor array: one package with several resistors).
  • Configuring PC0 as input (DDRC &= ~(1<<0)) is not required (pins are inputs after reset) but is good practice for readability, at the cost of one cycle.

L7. Code points

  • Integer-division trap [EXAM habit]: ADCW * 5 / 1024 is all integers, so the fraction is thrown away. Write 5.0 so at least one operand is floating point (implicit conversion, "casting").
  • Writing a decimal to a port is fine: PORTB = 3; stores 0b00000011 (registers only ever hold bits; binary, hex and decimal are just ways of writing the number).
  • Arduino version trick: store the highest pin to light in a variable n (8–12), then for (pin = 8; pin <= n; pin++) digitalWrite(pin, HIGH); instead of many repeated lines.
  • Interrupt-driven ADC (System 9): polling a slow ADC wastes the CPU, so let it interrupt instead. Start the first conversion before the loop and restart it at the end of ISR(ADC_vect), because ADSC is cleared after each conversion. The main loop is then free for other work.
  • Binary, hex and labelled-constant versions compile to the same code (no difference in size or speed). Hex and labels matter on 32-bit and 64-bit chips.

Written questions

W1. Explain how a 10-bit ADC with Vref = 5 V converts 3.3 V and compute its resolution in volts. How can the accuracy be improved?

Interval size = 5/1024 = 4.883 mV; ADCW = floor(3.3 / 4.883 mV) = floor(675.84) = 675 (binary 1010100011, found by successive approximation: each of the 10 steps compares Vin with a DAC trial voltage). Reconstructed Vin = 675 × 5/1024 = 3.296 V. Accuracy improves with a higher resolution or a smaller Vref (for example the internal 1.1 V reference gives 1.07 mV per step for signals below 1.1 V).

W4. Compare the polling and interrupt-driven voltmeter implementations.

Polling: after setting ADSC the CPU waits in while (ADCSRA & (1<<ADSC)), so it is tied up for about 104 µs every conversion. Interrupt: enable ADIE and sei(), start once, and the ISR(ADC_vect) computes the voltage, sets the LEDs and restarts the ADC; main() is free for other work.

W5. Explain successive approximation using a 4-bit ADC with Vin = 3 V and Vref = 5 V.

Guess Vref/2 = 2.5 V: Vin is higher, bit = 1, next guess 2.5 + 5/4 = 3.75 V. 3 < 3.75, bit 0, next 3.75 − 5/8 = 3.125 V. 3 < 3.125, bit 0, next 3.125 − 5/16 = 2.8125 V. 3 > 2.8125, bit 1. Result 1001 = 9. Each comparison gives one bit, stored in the data register.

W6. Derive the formula Vin = ADC × Vref / 1024 and state the smallest change the ATmega328P ADC can detect with Vref = 5 V and 1.1 V.

0 to Vref maps onto 0-1023, i.e. 1024 steps, so step size = Vref / 1024 and Vin = number of steps × step size. Smallest detectable change = one step: 5/1024 = 4.88 mV; 1.1/1024 = 1.07 mV.

Solution

1. Reference voltage

The LM35 gives 10 mV/°C, so 0 to 15 °C is only 0 to 0.15 V. With 5 V the step is 4.88 mV = 0.49 °C, which is too coarse. The internal 1.1 V reference (REFS1 = REFS0 = 1) gives 1.1 / 1024 = 1.074 mV = 0.107 °C per step, which meets 0.1 °C. Temperature = ADCW × 1.1 / 1024 × 100 = ADCW × 0.1074.
