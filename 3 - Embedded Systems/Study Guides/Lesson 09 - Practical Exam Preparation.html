1. What the practical exam looks like

The only past question available (a photo of the projected screen, an INTE practical exam from 2018) reads:

"Cogni tester"The diffuse axonal injury is a disorder that affects negatively one's cognitive skill to detect, process, and respond to a stimulus. The "cogni tester" is an embedded system used in healthcare to measure the response time of a patient suffering from this disorder accurately to the nearest millisecond.
On every start/restart of the "cogni tester", it waits for a random time period between 1 and 10 seconds. Upon the expiration of this waiting time, the "cogni tester" turns on an LED as a stimulus.
The patient is then supposed to press the "respond" pushbutton on the system as quickly as possible to respond to the stimulus. The "cogni tester" then turns off the LED used as stimulus and measures the time elapsed between the stimulus and the patient's response to the stimulus in milliseconds.
Finally, the "cogni tester" transmits the measured response time to a connected PC over USB using a serial to USB interface and displays the patient's response time to the stimulus on a text terminal in milliseconds.
1. Assemble "cogni tester" using an ATmega328P microcontroller and other necessary hardware components on a breadboard. (The photo shows only the first part; further parts presumably ask for the firmware, upload and a demonstration.)

Pattern of the practical paper (from this question, the exercises and the module outline): a short real-world scenario with a sensing or timing task → build the circuit on a breadboard → write, compile and upload the firmware (C in the Arduino IDE or Microchip Studio, or Arduino wrapper functions) → demonstrate it working. The question combines several lessons (the cogni tester is exercise 5 plus exercise 7). The module outline states that both exams may be based on the self-study exercises, so every exercise in this guide matters.

2. The exam workflow (follow it every time)

  1. Read the whole question and underline every requirement (times, ranges, units, which LED colours, which messages). Note the accuracy required (for example "nearest millisecond").
  2. Plan the pins before touching the board: write a table (function, Arduino pin, port bit, connection). Keep PD0/PD1 (pins 0, 1) free when serial is used; use pins 2 and 3 for external interrupts, 4 and 5 for T0/T1 counters, 6, 5, 9, 10, 11, 3 for PWM, A0 to A5 for analog.
  3. Calculate resistors (R = (Vs − VL)/IL, round up), timer values (initial = max − n + 1), UBRR, ADC thresholds. Do the maths on paper with the working shown; examiners mark working.
  4. Assemble the circuit on the breadboard: power rails, common GND first; LED polarity (long leg to the resistor/pin, cathode to GND); buttons from pin to GND with internal pull-up; sensors to the right pin. Check it twice before powering up.
  5. Write the firmware in small steps: configure pins, test one LED, then the button, then the timer, then serial. Compile after each step.
  6. Upload: select the right board (Arduino Uno) and COM port. Disconnect anything from pins 0 and 1 while uploading.
  7. Test with the terminal (Serial Monitor at the same baud rate) and fix. Keep a working version before making improvements.

4.3 Firmware in C (registers, timer time base)

#include <avr/io.h>
#include <avr/interrupt.h>
#include <stdlib.h>                                   // rand, srand, ultoa

volatile unsigned long ms = 0;                         // milliseconds since the timer started

ISR(TIMER0_OVF_vect)                                   // every 1 ms
{
    TCNT0 = 6;                                         // 250 counts of 4 us = 1 ms
    ms++;
}

static unsigned long now(void)                         // atomic read of the 32-bit counter
{
    unsigned long t;
    cli(); t = ms; sei();
    return t;
}

static void txChar(char c)
{
    while (!(UCSR0A & (1<<UDRE0)));                   // wait for data register empty
    UDR0 = c;
}
static void txString(const char *s) { while (*s) txChar(*s++); }

int main(void)
{
    DDRB  |=  (1<<DDB0);                              // stimulus LED output
    DDRD  &= ~(1<<DDD2);                              // respond button input
    PORTD |=  (1<<PORTD2);                             // pull-up

    UBRR0  = 16000000UL / (16 * 9600UL) - 1;           // 9600 baud: 103
    UCSR0B &= ~(1<<UCSZ02);
    UCSR0C |= (1<<UCSZ01) | (1<<UCSZ00);              // 8 bit
    UCSR0B |= (1<<TXEN0);                              // transmitter on

    ADMUX  = (1<<REFS0) | (1<<MUX2) | (1<<MUX0);      // AVcc, channel ADC5 (floating pin)
    ADCSRA = (1<<ADEN) | (1<<ADPS2) | (1<<ADPS1) | (1<<ADPS0);
    ADCSRA |= (1<<ADSC);
    while (ADCSRA & (1<<ADSC));
    srand(ADCW);                                       // different seed on every start

    TCNT0   = 6;                                       // Timer0: 1 ms time base
    TCCR0B  = (1<<CS01) | (1<<CS00);                  // F_CPU/64
    TIMSK0 |= (1<<TOIE0);                             // overflow interrupt
    sei();

    unsigned long waitMs = 1000UL + (rand() % 9001);   // 1000..10000 ms
    unsigned long t0 = now();
    while (now() - t0 < waitMs);                       // random waiting time

    PORTB |= (1<<PORTB0);                              // stimulus: LED on
    unsigned long start = now();
    while (PIND & (1<<PIND2));                       // wait until "respond" is pressed (pin low)
    unsigned long response = now() - start;
    PORTB &= ~(1<<PORTB0);                             // LED off

    char buf[11];
    ultoa(response, buf, 10);                          // number to text
    txString("Response time: ");
    txString(buf);
    txString(" ms\r\n");
    while (1);                                         // done: wait for restart
}

4.4 Firmware with the Arduino wrapper functions

const int stimulusLed = 8, respondBtn = 2;

void setup() {
  Serial.begin(9600);
  pinMode(stimulusLed, OUTPUT);
  pinMode(respondBtn, INPUT_PULLUP);
  randomSeed(analogRead(A5));                    // floating pin: different seed each start
}

void loop() {
  digitalWrite(stimulusLed, LOW);
  delay(random(1000, 10001));                    // 1 to 10 s
  digitalWrite(stimulusLed, HIGH);               // stimulus
  unsigned long start = millis();
  while (digitalRead(respondBtn) == HIGH);       // wait for the response
  unsigned long response = millis() - start;     // elapsed time in ms
  digitalWrite(stimulusLed, LOW);
  Serial.print("Response time: ");
  Serial.print(response);
  Serial.println(" ms");
  while (true);                                  // stop until restart
}
Improvements that earn marks1) False start: if the button is already pressed when the stimulus is due (or during the wait), print "False start" instead of a time. 2) Debounce the button with a 100 nF capacitor. 3) Make the time base exact with CTC (OCR0A = 249 with prescale 64) if the examiner asks for better than 1 ms drift. 4) Mention that millis() has 1 ms resolution and uses Timer0.

4.5 Likely viva questions

  • Why does the seed need to change? (Same seed = same sequence after every reset.) Why a floating analog pin? (Noise gives an unpredictable value.)
  • How accurate is the measurement? (Timer tick 4 µs, 1 ms counter; loop latency small, so about ±1 ms.)
  • Why is the button wired to GND with the pull-up? (No external resistor; pressed = 0.)
  • Why must ms be volatile and read with interrupts disabled? (Shared with the ISR; a 32-bit read takes several instructions and could be interrupted mid-read.)
  • What happens at 115 200 baud? (−3.55 % error, unreliable.)

6. Rules of thumb for the practical

  • If it says "C using direct register access" do not use pinMode, digitalWrite, Serial and so on at all. If it says Arduino wrapper functions, use them.
  • In the Arduino IDE you may write int main(void) in C (as in Exercises 2, 6, 7) and then setup()/loop() are not used.
  • Pull-up on every button input. Resistor on every LED. Flyback diode on every motor/relay. Common ground everywhere.
  • Declare shared variables volatile; keep ISRs short; never _delay_ms in an ISR.
  • #define F_CPU 16000000UL before #include <util/delay.h>.
  • Use 5.0 / 1024 (floating point, 1024) for ADC to volts.
  • Always include a while(1) loop in bare C main().
  • Time budget: plan 15 %, build 25 %, code 35 %, test and fix 25 %. A working simple version beats an unfinished perfect one.

Question 1: "Greenhouse controller" (40 marks)

A small greenhouse controller keeps plants cool. It uses an LM35 temperature sensor, a 6 V DC fan (about 100 mA) with its own battery, a green "manual" LED and a pushbutton, and a PC connected through the USB serial interface.

  • The fan is off at 25 °C or lower, at full speed at 35 °C or higher, and its speed varies linearly in between.
  • Pressing the pushbutton toggles a manual override: when active the fan runs at full speed whatever the temperature, and the green LED is on. Pressing again returns to automatic control. A press must never be missed.
  • Every 2 seconds the controller sends one line to the PC terminal such as T=29 C, FAN=40 % at 9600 baud.
  1. Draw the schematic (or a connection table) with the pin of every component, including the fan driver and protection. (10)
  2. Calculate and state: the ADC reference you chose and the temperature resolution; the fan driver component values; the timer registers/values for the 2 s period; the baud rate setting and its error. (10)
  3. Write the firmware in C (direct register access). (15)
  4. Outline how the Arduino wrapper functions version would differ. (5)

Question 2: "Quiz buzzer" (35 marks)

A quiz game has two contestant buttons (A and B), a host "ready" button, two LEDs (A and B) and a PC terminal. When the host presses ready, both LEDs go off and a millisecond timer restarts at 0. The first contestant to press their button wins: that contestant's LED turns on, later presses are ignored, and the controller sends Player A won at 842 ms (or B) to the PC at 9600 baud. A contestant who presses before the host presses ready is ignored. All three buttons must use interrupts.

  1. Choose the pins and justify the use of external versus pin change interrupts. Draw the connection table. (10)
  2. Design the 1 ms time base and give all register values. (5)
  3. Write the firmware in C. (15)
  4. Explain why the shared variables are volatile and what happens if A and B press within the same millisecond. (5)

Question 3: quick calculations (25 marks, 5 each)

  1. The loop LDI R16, 200 / L: DEC R16 / NOP / BRNE L runs on a 16 MHz AVR. How many clock cycles does it take (including the LDI) and what is the time?
  2. An 8-bit timer with prescale 256 at 16 MHz must overflow every 2 ms. Give the initial TCNT value. What is the longest period possible with this prescale?
  3. Give UBRR and the baud rate error for 38 400 baud at 16 MHz. How long does a 5-character message take?
  4. An ADC with Vref = 2.5 V and 10 bits converts 1.8 V. Give the ADC value and the interval size. What value would the default 5 V reference give?
  5. A red LED needs 1.8 V at 10 mA; the supply is 5 V. Compute the resistor and pick a standard value. A fast PWM output uses prescale 8: give the frequency and the duty cycle for OCR = 63.

Question 1 solution

(b) Calculations

  • ADC: the LM35 gives 10 mV/°C, so 0 to 50 °C is only 0 to 0.5 V. Use the internal 1.1 V reference (REFS1 = REFS0 = 1): ΔV = 1.1/1024 = 1.074 mV = 0.107 °C per step (with 5 V it would be 0.49 °C). T = ADCW × 1.1/1024 × 100.
  • Fan duty: OCR0A = (T − 25)/10 × 255 between 25 and 35 °C; 0 below; 255 above. At 30 °C: 127 (about 50 %).
  • PWM: Timer0 fast PWM, prescale 64: 16 MHz/(256 × 64) = 976.6 Hz (suitable for a small fan).
  • 2 s period: Timer1 (16-bit), prescale 1024: tick 64 µs, n = 15 625 for 1 s, initial = 65 535 − 15 625 + 1 = 49 911; the overflow ISR counts two overflows.
  • Baud: UBRR = 16 000 000/(16 × 9600) − 1 = 103.17 → 103; actual 9615.4 baud; error +0.16 %.

(c) C firmware

#include <avr/io.h>
#include <avr/interrupt.h>
#include <stdlib.h>

volatile unsigned char override = 0;       // manual override
volatile unsigned char seconds  = 0;
volatile unsigned char report   = 0;

ISR(INT0_vect)                             // button: toggle override and the green LED
{
    override ^= 1;
    PORTB ^= (1<<PORTB0);
}

ISR(TIMER1_OVF_vect)                       // every 1 s
{
    TCNT1 = 49911;
    if (++seconds >= 2) { seconds = 0; report = 1; }
}

static void txChar(char c) { while (!(UCSR0A & (1<<UDRE0))); UDR0 = c; }
static void txString(const char *s) { while (*s) txChar(*s++); }
static void txInt(int n) { char b[7]; itoa(n, b, 10); txString(b); }

int main(void)
{
    DDRB  |=  (1<<DDB0);                                  // LED
    DDRD  |=  (1<<DDD6);                                  // OC0A (fan)
    DDRD  &= ~(1<<DDD2);   PORTD |= (1<<PORTD2);          // button + pull-up

    TCCR0A = (1<<COM0A1) | (1<<WGM01) | (1<<WGM00);       // fast PWM, non-inverted
    TCCR0B = (1<<CS01) | (1<<CS00);                      // /64

    ADMUX  = (1<<REFS1) | (1<<REFS0);                     // 1.1 V reference, ADC0
    ADCSRA = (1<<ADEN) | (1<<ADPS2) | (1<<ADPS1) | (1<<ADPS0);

    UBRR0  = 16000000UL / (16 * 9600UL) - 1;               // 103
    UCSR0C |= (1<<UCSZ01) | (1<<UCSZ00);                  // 8 bit
    UCSR0B |= (1<<TXEN0);                                 // transmitter

    EICRA |= (1<<ISC01);  EICRA &= ~(1<<ISC00);           // INT0 falling edge
    EIMSK |= (1<<INT0);

    TCNT1  = 49911;                                        // Timer1 1 s tick
    TCCR1B = (1<<CS12) | (1<<CS10);                      // /1024
    TIMSK1 |= (1<<TOIE1);
    sei();

    while (1)
    {
        ADCSRA |= (1<<ADSC);
        while (ADCSRA & (1<<ADSC));
        float t = ADCW * 1.1 / 1024 * 100;                 // degrees Celsius
        unsigned char duty;
        if (override || t >= 35) duty = 255;
        else if (t <= 25)        duty = 0;
        else                     duty = (unsigned char)((t - 25) * 255 / 10);

        if (duty == 0) { TCCR0A &= ~(1<<COM0A1); PORTD &= ~(1<<PORTD6); }  // fully off
        else           { TCCR0A |=  (1<<COM0A1); OCR0A = duty; }

        if (report)
        {
            report = 0;
            txString("T=");   txInt((int)t);
            txString(" C, FAN=");  txInt(duty * 100 / 255);
            txString(" %\r\n");
        }
    }
}

Question 2 solution

(a) Pins and interrupt choice

PartPinConnection and interrupt
Host "ready"Pin 2 (PD2 = INT0)to GND, pull-up; external interrupt on the falling edge
Contestant A buttonPin 4 (PD4 = PCINT20)to GND, pull-up; pin change interrupt
Contestant B buttonPin 5 (PD5 = PCINT21)to GND, pull-up; pin change interrupt

Only two pins (INT0, INT1) support external interrupts, and three buttons are needed, so the two contestant buttons use pin change interrupts (any pin, but any change and one shared vector for the port, so the ISR must test which pin is low). The host button uses INT0 with a selectable falling edge. Debounce each button with a 100 nF capacitor.

(b) Time base

Timer0, prescale 64: tick 4 µs; 1 ms = 250 ticks; initial value = 255 − 250 + 1 = 6; TCNT0 = 6, TCCR0B = (1<<CS01)|(1<<CS00), TIMSK0 |= (1<<TOIE0), ISR TIMER0_OVF_vect reloads TCNT0 and increments ms only while a round is armed.

(c) C firmware

#include <avr/io.h>
#include <avr/interrupt.h>
#include <stdlib.h>

volatile unsigned long ms = 0;
volatile unsigned char armed = 0;           // 1 while a round is running
volatile unsigned char winner = 0;          // 0 none, 1 = A, 2 = B
volatile unsigned char announce = 0;        // result ready to send
volatile unsigned long tWin = 0;

ISR(TIMER0_OVF_vect) { TCNT0 = 6; if (armed) ms++; }

ISR(INT0_vect)                              // host: ready
{
    PORTB &= ~((1<<PORTB0) | (1<<PORTB1));   // both LEDs off
    ms = 0;  winner = 0;  announce = 0;
    armed = 1;                              // start the round
}

ISR(PCINT2_vect)                            // contestant buttons (any change on Port D pins enabled)
{
    if (!armed) return;                     // ignore presses before ready (and after a winner)
    if      (!(PIND & (1<<PIND4))) winner = 1;      // A is low: pressed
    else if (!(PIND & (1<<PIND5))) winner = 2;      // B is low: pressed
    else return;                            // a release, not a press
    armed = 0;                              // lock out the other contestant
    tWin = ms;
    PORTB |= (winner == 1) ? (1<<PORTB0) : (1<<PORTB1);
    announce = 1;
}

static void txChar(char c) { while (!(UCSR0A & (1<<UDRE0))); UDR0 = c; }
static void txString(const char *s) { while (*s) txChar(*s++); }

int main(void)
{
    DDRB  |= (1<<DDB0) | (1<<DDB1);
    DDRD  &= ~((1<<DDD2) | (1<<DDD4) | (1<<DDD5));
    PORTD |=  (1<<PORTD2) | (1<<PORTD4) | (1<<PORTD5);       // pull-ups

    EICRA |= (1<<ISC01);  EICRA &= ~(1<<ISC00);          // INT0 falling edge
    EIMSK |= (1<<INT0);
    PCICR  |= (1<<PCIE2);                                 // pin change interrupts on Port D
    PCMSK2 |= (1<<PCINT20) | (1<<PCINT21);               // PD4 and PD5

    TCNT0 = 6;  TCCR0B = (1<<CS01) | (1<<CS00);  TIMSK0 |= (1<<TOIE0);

    UBRR0 = 16000000UL / (16 * 9600UL) - 1;
    UCSR0C |= (1<<UCSZ01) | (1<<UCSZ00);
    UCSR0B |= (1<<TXEN0);
    sei();

    while (1)
    {
        if (announce)
        {
            announce = 0;
            char buf[11];
            txString("Player ");
            txChar(winner == 1 ? 'A' : 'B');
            txString(" won at ");
            ultoa(tWin, buf, 10);
            txString(buf);
            txString(" ms\r\n");
        }
    }
}

(d) Explanation

The flags and counters are changed in ISRs while main() reads them, so they are volatile (otherwise the compiler may keep a stale copy in a register and never see the change). tWin is copied inside the ISR so a later round cannot overwrite it before the message is sent. If A and B press within the same millisecond, the ISR runs once per pin-change event; the first ISR to run locks the round (armed = 0) and the second is ignored. If both buttons are already low when the first ISR runs, the code awards the win to A (it tests A first); a fair design could record the order with finer timer resolution or use separate interrupt vectors per player, which the AVR pin change scheme (one vector per port) does not give.

Question 3 solution

  1. Loop body: DEC 1 + NOP 1 + BRNE. Taken (2 cycles): 4 × 199 = 796; last pass falls through (1): 3. Total = 799, plus LDI (1) = 800 cycles = 800 × 62.5 ns = 50 µs.
  2. Tick = 256/16 MHz = 16 µs; n = 2 ms/16 µs = 125; initial = 255 − 125 + 1 = 131. Longest period = 256 × 16 µs = 4.096 ms.
  3. UBRR = 16 000 000/(16 × 38 400) − 1 = 25.04, so 25; actual = 16 000 000/(16 × 26) = 38 461.5 baud; error +0.16 %. Five characters at 10 bits = 50 bits, 50/38 400 = 1.30 ms.
  4. ΔV = 2.5/1024 = 2.44 mV; ADC = floor(1.8/2.5 × 1024) = floor(737.28) = 737. With 5 V: 1.8/5 × 1024 = 368.64, so 368.
  5. R = (5 − 1.8)/0.010 = 320 Ω, use 330 Ω. Frequency = 16 MHz/(256 × 8) = 7.81 kHz; duty = (63 + 1)/256 = 25 %.
