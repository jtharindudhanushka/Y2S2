2. Answer bank (ready-made theory answers)

A. Introduction and microcontrollers

  • Embedded system: a computer system embedded into another system to perform a dedicated task, using sensors (input), a processor running firmware and actuators (output); it operates under strict constraints of cost, size/weight, power and real-time performance.
  • Why software-based: easier to implement on generic hardware, lower cost, easier to debug and to modify.
  • Microprocessor vs microcontroller: separate chips on a board (single board computer; fast, replaceable parts, but costly, hot, bulky) against everything in one chip (single chip computer; cheap, low power, compact, but limited performance). Choose by requirements: image processing needs a microprocessor; a fire alarm needs a microcontroller.
  • ATmega328P: 8-bit Harvard RISC AVR, 131 mostly single-cycle instructions, 20 MHz max, 32 KB flash, 2 KB RAM, 1 KB EEPROM, 23 I/O pins, 3 timers, 6 PWM channels, 10-bit ADC (6 channels), 1 USART, 2 SPI, 1 I2C, 28-pin PDIP. Chosen for learning as it is popular, well documented and the heart of the Arduino Uno.
  • Firmware development flow: source → compiler/assembler → HEX → programmer or bootloader (AVRDUDE) → flash.
  • Harvard vs von Neumann (syllabus): separate program/data memories and buses allow simultaneous instruction and data access; RISC: simple instructions, predictable timing.

B. I/O and delays

  • DDR, PORT, PIN: direction (1 output), output / pull-up, input read. Bit operations: set with OR, clear with AND-NOT, toggle with XOR.
  • Assembly vs C vs Arduino: efficient/hard/not portable; efficient/easier/portable; easiest/inefficient/not portable. Example: 5-LED chaser = 920 B (Arduino), 200 B (C), 172 B (optimised C).
  • Delay calculation: cycle = 1/f; cycles = delay/cycle; nested loops (b+3)(N−1)+(b+2); add NOPs to trim.

C. Polling and interrupts

  • Polling: the CPU repeatedly checks; can miss fast events; no priority; wastes time.
  • Interrupts: device interrupts the CPU; the return address is pushed; vector table → ISR; RETI pops and resumes; supports priority; CPU free.
  • Enable chain: source enable bit + global sei(); external interrupt: EICRA sense + EIMSK; pin change: PCICR + PCMSKn.
  • Debouncing: contacts bounce, producing several edges; hardware: 100 nF capacitor across the switch; software: ignore changes for about 20 ms (not by delay in an ISR).
  • ISR rules: short, no delays, shared variables volatile.

D. ADC and sensors

  • ADC: converts 0 to Vref into 0 to 1023 (10 bits); interval = Vref/1024; the largest code 1023 does not reach Vref; smaller Vref (1.1 V) improves resolution; successive approximation determines one bit per step from the MSB.
  • ADC registers: ADMUX (reference, left adjust, channel), ADCSRA (enable, start, flag, interrupt, prescaler 125 kHz at /128), ADCW result.
  • LDR: resistance falls with light; voltage divider. LM35: 10 mV/°C.

E. Transducers

  • Sensors convert physical quantities to signals (digital, analog, both); actuators convert electrical energy into other forms and often need drivers: BJT (base current, resistor), MOSFET (gate voltage, pull-down), relay (isolation, mains), flyback diode for inductive loads.

F. Timers and PWM

  • Timer/counter: a peripheral that counts oscillator (time) or external (events) pulses so the CPU is free; registers TCNT, TCCR, TIFR (W1C), TIMSK. Time = prescale/F_CPU × counts; initial = max − n + 1.
  • Why W1C: clears just one flag without a read-modify-write that could clear others.
  • PWM: analog-like output by changing the duty cycle; average = duty × Vhigh. Modes: normal (no PWM), CTC (programmable TOP), fast PWM (duty = (OCR+1)/(TOP+1), high frequency), phase correct (symmetric, half frequency). True analog: DAC or RC filter.

G. Serial communication

  • Serial vs parallel; asynchronous vs synchronous; the framing (start bit, data LSB first, stop bit); baud rate must match; line driver (MAX232) for RS-232; UART-to-USB (FT232RL, ATmega16U2).
  • Registers: UBRR (UBRR = F_CPU/(16×baud) − 1; error), UDR, UCSRnA (RXC, TXC, UDRE), UCSRnB (enables), UCSRnC (size).
  • UDRE vs TXC: UDRE gives max throughput; TXC tells when the frame has completely left.
  • stdio over serial: FDEV_SETUP_STREAM, stdin/stdout; convenient and device independent but costs memory and time.

3. Syllabus topics the slides only touch (syllabus)

TopicWhat to know
Power managementLower the clock or supply voltage; sleep modes (idle, power-down, wake by interrupt); switch off unused peripherals (ADC, timers, USART); use interrupts instead of polling; avoid busy-wait delays; drive LEDs with larger resistors / PWM; efficient actuators. Battery life = capacity / average current.
Resource-aware firmwareFlash 32 KB (code, constants), SRAM 2 KB (variables, stack; heap should be avoided), EEPROM 1 KB (settings, slow writes with limited write cycles). Avoid dynamic memory and the Arduino String class (heap fragmentation, hidden allocations); prefer char arrays and fixed buffers. Put constant tables in flash (PROGMEM). Avoid floating point where integers will do.
Performance and optimisationDirect register access is much faster than digitalWrite() (the Arduino speed test). Measure code size (HEX bytes) and execution time. Use shifts for powers of two, local variables, small data types (uint8_t), interrupts and hardware peripherals instead of software loops.
Hardware-software co-designDecide which function goes in hardware (timer, PWM, USART) and which in software; the hardware peripherals free the CPU.
Debugging and simulationSimulators (Microchip Studio simulator, Proteus, Tinkercad) before building; debugging aids: LEDs, serial prints, logic analyser/oscilloscope, breakpoints with a debugger. Tests: hardware error → replace/rewire components; software error → debug the code.
Choosing a platformPick the board by pins, memory, speed, voltage and peripherals (Uno, Mega, Nano, ESP32...); microcontroller boards against single board computers.
Embedded OSSmall systems run bare-metal (super-loop with interrupts); larger systems use an RTOS for scheduling with deadlines.
Current trendsIoT and wireless connectivity, 32-bit low-power MCUs, RISC-V, edge AI / TinyML, energy harvesting, security of connected devices.

Written questions

W1. Question 1 (introduction and microcontrollers, 20 marks). (a) Define an embedded system and list its constraints. (b) Explain, with the ABS example, how sensors, a processor and actuators cooperate. (c) Compare microprocessor-based and microcontroller-based designs and choose one for a smoke alarm and for a traffic-camera system. (d) Name six core components of a microcontroller with their functions. (e) State five features of the ATmega328P and explain why the Arduino Uno is used in this module.

(a) A computer system embedded in another system to do a dedicated task through sensors, processor and actuators; constraints: cost, weight/size, power consumption, real-time performance. (b) Wheel speed sensors measure rotation; the processor compares the wheels and decides whether one is braked less; the hydraulic pump (actuator) releases fluid to that wheel until all four rotate at the same speed. (c) Table: microprocessor board (high spec, replaceable parts; expensive, power hungry, bulky) against microcontroller (cheap, low power, compact; limited performance). Smoke alarm: microcontroller (binary sensor, battery, small, bought in bulk). Traffic camera: microprocessor (image processing needs RAM and speed, no power limit). (d) CPU executes instructions; flash ROM stores firmware; RAM stores variables; EEPROM stores settings; ADC converts analog to digital; timers count time/events; PWM gives analog-like output; I/O ports connect sensors/actuators; serial ports communicate. (e) 8-bit Harvard RISC; 32 KB flash, 2 KB RAM, 1 KB EEPROM; 23 I/O pins; 3 timers, 6 PWM channels, 10-bit ADC; USART, SPI, I2C; 20 MHz max. The Uno has the ATmega328P, USB programming and power, is cheap, well documented and widely used.

W2. Question 2 (I/O, polling, interrupts, 20 marks). (a) Explain DDR, PORT and PIN. (b) A program uses DDRB = 0x21; PORTB = 0x20; DDRD &= ~0x04; PORTD |= 0x04; State which pins are outputs, their logic levels and the state of PD2. (c) Calculate the delay of LDI R16,100 / L1: LDI R17,200 / L2: DEC R17 / BRNE L2 / DEC R16 / BRNE L1 at 16 MHz. (d) Compare polling and interrupts. (e) Write the C code to toggle an LED on PB0 with INT0 on the falling edge while PB5 blinks every second.

(a) DDR sets direction (1 = output); PORT writes output level or enables the pull-up of an input; PIN reads the pin level. (b) 0x21 = 0b00100001: PB5 and PB0 are outputs; PORTB = 0x20: PB5 high (LED on), PB0 low. PD2 is an input (DDRD bit cleared) with its pull-up enabled, so it reads 1 until the pin is pulled to ground. (c) Inner loop (200): (1+2)×199 + 2 = 599. Outer body = LDI (1) + 599 + DEC (1) + BRNE; taken: 603 × 99 = 59 697; last: 602; total 60 299; plus LDI R16: 60 300 cycles = 60 300 × 62.5 ns = 3.77 ms. (d) Polling checks repeatedly, can miss short events, no priority, uses CPU; interrupts: device interrupts the CPU, return address pushed, ISR via vector table, priority, CPU free. (e) 

DDRB |= (1<<DDB0)|(1<<DDB5);
DDRD &= ~(1<<DDD2); PORTD |= (1<<PORTD2);
EICRA |= (1<<ISC01); EICRA &= ~(1<<ISC00);

while(1){ PORTB ^= (1<<PORTB5); _delay_ms(1000); }

W3. Question 3 (ADC, sensors, actuators, 20 marks). (a) A 10-bit ADC with Vref = 1.1 V reads 512. Find the input voltage, the interval size and the temperature if the sensor is an LM35. (b) Explain successive approximation briefly. (c) Design an automatic night lamp with an LDR: schematic, thresholds and why hysteresis is used. (d) Design the driver to switch a 6 V, 120 mA motor from a pin using a 2N7000 and explain every component. (e) Why is a relay used for mains?

(a) ΔV = 1.1/1024 = 1.074 mV; Vin = 512 × 1.1/1024 = 0.55 V; T = 0.55 × 100 = 55 °C. (b) The ADC finds the bits from MSB to LSB: a DAC produces a trial voltage, a comparator tells whether Vin is above it, the bit is kept or cleared, and the range halves each step: 10 steps for 10 bits. (c) +5 V → LDR → node A0 → 10 kΩ → GND; LED on pin 8 via 220 Ω. Dark gives a low voltage: LED on when ADC < 300, off when ADC > 400. Hysteresis stops flicker when the light level hovers near one threshold. (d) Pin → 100 Ω → gate, 10 kΩ gate to GND (keeps it off when the pin floats); motor between +6 V and the drain; source to GND, common with the Arduino; 1N4001 across the motor, cathode to +6 V (absorbs the spike); 2N7000 handles 200 mA > 120 mA and is turned on fully by 5 V (VGS(th) 0.8 to 3 V). (e) The relay's contacts are isolated from the coil, so the low-voltage electronics never touch the mains; the coil still needs a transistor driver and a flyback diode, and the mains side needs proper isolation, enclosure and qualified handling.

W4. Question 4 (timers and PWM, 20 marks). (a) Why are timers peripherals? (b) Compute the initial TCNT1 value for a 250 ms overflow with prescale 64 at 16 MHz and give the CS bits. (c) Write the ISR-based C code to toggle PB5 every 250 ms. (d) Explain fast PWM and phase correct PWM and give the frequency of each with prescale 64 on an 8-bit timer. (e) Write the registers for 50 % duty at about 1 kHz on OC0A.

(a) Counting in software ties up the small CPU; the timer counts oscillator pulses (time) or external pulses (events) independently, so the CPU does computation. (b) tick = 4 µs; n = 0.25/4 µs = 62 500; initial = 65 535 − 62 500 + 1 = 3 036; CS12:0 = 011 (/64). (c)

W5. Question 5 (serial communication, 20 marks). (a) Describe the asynchronous frame and why the baud rate matters. (b) Compute UBRR and the error for 57 600 baud at 16 MHz and comment. (c) Explain UDRE versus TXC. (d) Write the C code to initialise the USART at 9600 baud, 8 bits, and send the string "HELLO". (e) The temp logger stores the temperature text in char str[4]. Explain. (f) Give two pros and two cons of using printf over the serial port.

(a) Idle high; start bit 0; 8 data bits LSB first; stop bit 1; 10 bits per character; no clock line, so the receiver times each bit with its own clock, which only works if both ends use the same baud rate. (b) UBRR = 16 000 000/(16×57 600) − 1 = 16.36, use 16; actual = 16 000 000/(16×17) = 58 823.5; error = +2.12 %, marginal; use U2X, another rate (e.g. 38 400 with +0.16 %) or an 18.432 MHz crystal. (c) UDRE is set when the data register is empty so the next character can be written while the previous one is still shifting (maximum throughput); TXC is set when the whole frame has been shifted out, useful before sleeping or reversing a half-duplex line. (d) 

UBRR0 = 16000000UL/(16*9600UL) - 1;
UCSR0B &= ~(1<<UCSZ02);
UCSR0C |= (1<<UCSZ01)|(1<<UCSZ00);
UCSR0B |= (1<<TXEN0);
const char *s = "HELLO";
while (*s) { while (!(UCSR0A & (1<<UDRE0))); UDR0 = *s++; }
(e) The range is −55 to 150 °C; the longest text ('-55' or '150') has three characters; with the null terminator '\0' that makes four elements. (f) Pros: standard/portable, device-independent streams, convenient formatting. Cons: large flash/RAM, slower and blocking, no float by default.

W6. Question 6 (design, 20 marks). A "parking sensor" measures the distance to a wall with an analog distance sensor (output 0.4 V at 80 cm and 2.0 V at 10 cm), beeps a buzzer through a transistor with a rate depending on the distance, lights a red LED when closer than 20 cm, and reports the distance to a PC every second at 9600 baud. (a) Draw the connection table. (b) Explain which peripherals you use and why (ADC, timer, PWM or interrupt, USART). (c) Outline the firmware as a flowchart in words or pseudo-code. (d) State the ADC resolution you obtain and one way to improve it.

(a) Sensor: +5 V, GND, output to A0. Buzzer: pin 6 (PD6) → 1 kΩ → BC547 base, buzzer between 5 V and collector, 1N4001 across it (if the buzzer is a coil), emitter to GND. Red LED: pin 8 → 220 Ω → LED → GND. USB to the PC (pins 0, 1 free). (b) ADC reads the sensor voltage; Timer1 overflow interrupt gives a 1 s tick (initial 49 911 with prescale 1024) to report over the USART at 9600 baud (UBRR = 103) without blocking; the buzzer rate is produced by PWM/tone or a Timer0 overflow ISR toggling the pin; interrupts keep the main loop free. (c) Configure ADC (Vref AVcc, ADC0, /128), timers, USART, sei(); loop: start conversion, wait, compute voltage and distance by linear interpolation between the two calibration points, set the LED if distance < 20 cm, set the buzzer rate; the Timer1 ISR sets a flag and the loop sends the distance as text when the flag is set. (d) With 5 V, ΔV = 4.88 mV; the sensor swing 1.6 V covers about 328 steps over 70 cm, about 0.2 cm per step. Improve by using a 2.5 V external or a smaller reference (the 0.4 to 2.0 V range fits a 2.5 V AREF), averaging several readings, or oversampling.
