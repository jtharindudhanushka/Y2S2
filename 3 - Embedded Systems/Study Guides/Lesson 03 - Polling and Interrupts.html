1. Why polling or interrupts?

Both are ways to perform more than one task seemingly at the same time: they give the CPU's service to a peripheral device while the CPU is busy with another task.

PollingInterrupt
IdeaThe CPU keeps checking the status of devices at regular intervals while doing its other task. If the condition is met it serves the device, then resumes.The device interrupts the CPU when it needs service. The CPU suspends its task, serves the device, then resumes.
CPU loadCPU spends time monitoringFrees the CPU from monitoring
Fast eventsMay be missed if the state changes too fast or the check interval is longCaught immediately
PriorityNo priority: all tasks run in the same orderSupports priority (lower vector address = higher priority)

2. System 5: pollingBasedTrigger

Task: toggle one LED on user input (button) while blinking another LED every 2 seconds, using polling.

Hardware: blink LED on PB5 (220 Ω), user-input LED on PB0 (1 kΩ), pushbutton on PD2 to GND with the pull-up (default state high, pressed = low), reset circuit with 10 kΩ pull-up, 16 MHz crystal (on an Uno these are built in).

#include <avr/io.h>
#define F_CPU 16000000UL
#include <util/delay.h>

int main(void)
{
    DDRB  = DDRB | 0b00100001;      // PB0 and PB5 outputs
    DDRD  = DDRD & 0b11111011;      // PD2 input
    PORTD = PORTD | 0b00000100;     // pull-up PD2
    while (1)
    {
        PORTB = PORTB ^ 0b00100000;       // toggle PB5 (main task)
        _delay_ms(2000);                  // wait 2 s
        if ((PIND & 0b00000100) == 0)     // poll the button: low = pressed
            PORTB = PORTB ^ 0b00000001;   // toggle PB0
    }
    return 0;
}
// Arduino wrapper version
const int ledPin1 = 8, ledPin2 = 13, switchPin = 2;
void setup() {
  pinMode(ledPin1, OUTPUT); pinMode(ledPin2, OUTPUT);
  pinMode(switchPin, INPUT_PULLUP);
}
void loop() {
  digitalWrite(ledPin2, !digitalRead(ledPin2));      // toggle the blink LED
  delay(2000);
  if (digitalRead(switchPin) == LOW)                 // poll
    digitalWrite(ledPin1, !digitalRead(ledPin1));
}
How the test works(PIND & 0b00000100) == 0: mask keeps only bit 2. Released: 0000 0100, not 0 (false). Pressed: 0000 0000, equal to 0 (true). XOR with 1 flips a bit: PORTB ^ 0b00000001.

Problems of polling (shown by this very program)

  • The button is looked at only once per 2 s. A quick press that starts and ends inside the delay is not detected. For a sensor there may be many undetected inputs.
  • The reaction is delayed by up to 2 s.
  • There is no priority: with many devices all are served in the same order.

3. Interrupt handling

  1. A device requests an interrupt (a flag is set). If the source is enabled and the global interrupt bit is set, the CPU finishes the current instruction.
  2. The CPU pushes the return address on the stack and jumps to the entry of the interrupt vector table belonging to that source. The entry holds the address of the interrupt service routine (ISR).
  3. The ISR runs. At its end (RETI) the return address is popped and the interrupted task resumes where it stopped.

4. External interrupt registers

  • EICRA (External Interrupt Control Register A): ISC01, ISC00 select what triggers INT0; ISC11, ISC10 select INT1.
  • EIMSK (External Interrupt MaSK): bit INT0 / INT1 enables the interrupt on that pin.
  • INT0 is pin PD2 (Arduino 2), INT1 is pin PD3 (Arduino 3).

5. System 6: externalInterruptBasedTrigger

Same task as System 5, but the button is on INT0 (PD2) and an ISR toggles the LED, so a press is never missed and the main loop needs no checking.

Contact bounce and the capacitor

The contacts of a mechanical switch bounce: one press produces a series of rapid voltage changes that the microcontroller may count as several presses (each edge is an interrupt!). A capacitor (100 nF) placed across the switch smooths the voltage and debounces the input (Exercise 3 uses one 100 nF capacitor in parallel with each pushbutton).

#include <avr/io.h>
#define F_CPU 16000000UL
#include <util/delay.h>
#include <avr/interrupt.h>

int main(void)
{
    DDRB  |= (1<<DDB5) | (1<<DDB0);     // PB5, PB0 outputs
    DDRD  &= ~(1<<DDD2);               // PD2 (INT0) input
    PORTD |= (1<<PORTD2);              // pull-up
    EICRA |=  (1<<ISC01);              // falling edge: ISC01 = 1
    EICRA &= ~(1<<ISC00);              //               ISC00 = 0
    EIMSK |=  (1<<INT0);               // enable INT0
    sei();                             // enable global interrupts
    while (1)
    {
        PORTB ^= (1<<PORTB5);              // main task
        _delay_ms(2000);
    }
}

ISR(INT0_vect)                         // handle INT0
{
    PORTB ^= (1<<PORTB0);                // toggle PB0
}
// Arduino wrapper version
const int ledPin1 = 8, ledPin2 = 13, switchPin = 2;
void setup() {
  pinMode(ledPin1, OUTPUT);
  pinMode(ledPin2, OUTPUT);
  pinMode(switchPin, INPUT_PULLUP);
  int intNum = digitalPinToInterrupt(switchPin);   // map I/O pin to interrupt number
  attachInterrupt(intNum, toggle, FALLING);        // LOW, CHANGE, RISING or FALLING
}
void loop() {
  digitalWrite(ledPin2, !digitalRead(ledPin2));
  delay(2000);
}
void toggle() {                                    // ISR: no arguments, no return
  digitalWrite(ledPin1, !digitalRead(ledPin1));
}

6. Pin change interrupts and System 7

INT0 and INT1 exist on only two pins. Pin change interrupts work on any pin.

  • PCICR: PCIE0 / PCIE1 / PCIE2 enable pin-change interrupts for Port B / C / D.
  • PCMSKn: PCMSK0 (PCINT0 to 7 = PB0 to PB7), PCMSK1 (PCINT8 to 14 = PC0 to PC6), PCMSK2 (PCINT16 to 23 = PD0 to PD7). The bit enables that pin. PD2 = PCINT18.
  • The interrupt fires on any change (rising and falling), and all pins of the port share one vector, so the ISR must check the pin state (for example only act if the pin is low).
int main(void)
{
    DDRB  |= (1<<DDB5) | (1<<DDB0);
    DDRD  &= ~(1<<DDD2);
    PORTD |= (1<<PORTD2);
    PCICR  |= (1<<PCIE2);              // enable pin change interrupts on Port D
    PCMSK2 |= (1<<PCINT18);            // ... for PD2
    sei();
    while (1) { PORTB ^= (1<<PORTB5); _delay_ms(2000); }
}
ISR(PCINT2_vect)                       // any PD pin that is enabled
{
    if ((PIND & (1<<PIND2)) == 0)      // act only on the falling edge (pin low)
        PORTB ^= (1<<PORTB0);
}

7. Writing good ISRs

  • Keep them short and fast; no _delay_ms(), no long loops. Set a flag or update a variable and return.
  • Variables shared with main() must be volatile. For multi-byte shared variables, briefly disable interrupts (cli() / sei()) when main reads them.
  • Never forget the two levels of enable (the source and sei()).
  • An ISR is not called by your code; the hardware calls it. Interrupts are not queued without limit (one pending flag per source).

8. Exercise 3: click counter (worked)

Specification: count the presses of a pushbutton and show the count in binary on LEDs (0 to 255, so 8 LEDs). Display is initially all off. Pressing a second pushbutton ("enter") shows the entered number. Pressing "enter" again clears the display (all off), ready for the next entry. Chip pins 2 and 3 (PD0 / PD1 = RXD / TXD) must be reserved for later serial communication.

Design

FunctionPinNotes
LED bits 0 to 5PB0 to PB5 (Arduino 8 to 13)each with a 220 Ω resistor to GND
LED bits 6 and 7PD6, PD7 (Arduino 6, 7)mapping the number bits 6 and 7 directly to the same bit positions of PORTD
Count buttonPD2 (INT0)to GND, pull-up on, 100 nF across the switch
Enter buttonPD3 (INT1)to GND, pull-up on, 100 nF across the switch
ReservedPD0, PD1 (chip pins 2, 3)not used
Reset, crystal10 kΩ pull-up on RESET, 16 MHz crystal with two 22 pF capacitors (built in on an Arduino Uno)
#include <avr/io.h>
#include <avr/interrupt.h>

volatile unsigned char count   = 0;     // entered number (0..255, wraps after 255)
volatile unsigned char showing = 0;     // 0 = entering, 1 = displaying

static void display(unsigned char v)
{
    PORTB = (PORTB & ~0x3F) | (v & 0x3F);   // bits 0..5 on PB0..PB5
    PORTD = (PORTD & ~0xC0) | (v & 0xC0);   // bits 6..7 on PD6..PD7
}

int main(void)
{
    DDRB |= 0x3F;                          // PB0..PB5 outputs
    DDRD |= 0xC0;                          // PD6, PD7 outputs
    DDRD &= ~((1<<DDD2) | (1<<DDD3));    // PD2, PD3 inputs
    PORTD |= (1<<PORTD2) | (1<<PORTD3);    // pull-ups
    EICRA |= (1<<ISC01) | (1<<ISC11);      // falling edge on INT0 and INT1
    EICRA &= ~((1<<ISC00) | (1<<ISC10));
    EIMSK |= (1<<INT0) | (1<<INT1);
    display(0);
    sei();
    while (1) { }                          // all work is done by the ISRs
}

ISR(INT0_vect)                             // count button
{
    if (!showing) count++;
}

ISR(INT1_vect)                             // enter button
{
    if (!showing) { showing = 1; display(count); }   // show the number
    else          { showing = 0; count = 0; display(0); }  // clear
}
"Is AI safe to trust?" (lecture 04 reading)The lecturer's model answer maps count bits 7 to 2 to PB0 to PB5 (PORTB |= count >> 2) and bits 1 and 0 to PD6 and PD7 (PORTD |= count << 6), with a 100 nF capacitor across each pushbutton, and interrupt-driven code. An AI asked to check it first declared the bit mapping wrong and criticised the missing software debounce. The student replied that the mapping was deliberate and that two 100 nF capacitors already debounce the switches in hardware; the AI then admitted it had misread the schematic. Lesson: AI predicts likely text and can hallucinate with an authoritative tone, so always verify against the schematic and datasheet yourself. Any consistent bit mapping is acceptable (mine above uses bits 0 to 5 on PB0 to PB5 and bits 6 and 7 on PD6 and PD7); just keep schematic and code in agreement.
Common mistakes1) Forgetting sei(). 2) Setting EIMSK but leaving EICRA at the default (low-level trigger fires repeatedly while held). 3) Using INT0/INT1 vectors with the wrong pin (INT0 is PD2, INT1 is PD3). 4) Not marking shared variables volatile. 5) Delays inside an ISR. 6) Pin change ISR acting on both edges (button toggles twice). 7) No debounce capacitor, so one press counts several times.

Written questions

W1. Compare polling and interrupts, giving the problems of polling.

Polling: the CPU repeatedly checks device status while doing another task; simple but a fast change can be missed if the interval is long (a quick button press during a 2 s delay is lost), the CPU wastes time monitoring and there is no priority because all devices are checked in the same order. Interrupts: the device interrupts the CPU, which suspends its task, runs the ISR and resumes. The CPU is free from monitoring, events are caught immediately and priorities are supported (lower vector address = higher priority).

W2. Describe how an interrupt is handled by the ATmega328P.

A source sets its flag; if its enable bit and the global I bit (sei()) are set the CPU finishes the current instruction, pushes the return address on the stack, clears I and jumps to the vector table entry of that source, which leads to the ISR. The ISR runs and RETI pops the return address and re-enables interrupts so the interrupted program continues.

W3. Write the registers and C code to toggle an LED on PB0 each time a button on PD2 is pressed using INT0 on the falling edge, while PB5 blinks every second in main.

A 100 nF capacitor across the switch debounces it.

W4. Explain the difference between external interrupts and pin change interrupts and how each is configured.

External interrupts exist only on INT0 (PD2) and INT1 (PD3), have their own vectors and a selectable trigger (low, change, falling, rising) set in EICRA and enabled in EIMSK. Pin change interrupts work on any pin, fire on any logic change and share one vector per port (PCINT0_vect, PCINT1_vect, PCINT2_vect), so the ISR must test the pin state. They are enabled with PCICR (PCIE0/1/2 for ports B/C/D) and the pin's bit in PCMSK0/1/2.

3. C firmware

#include <avr/io.h>
#define F_CPU 16000000UL
#include <util/delay.h>
#include <avr/interrupt.h>

volatile unsigned char count = 0;

static void show(void)
{
    PORTB = (PORTB & 0b11110000) | (count & 0x0F);     // bits 0..3 on PB0..PB3
}

int main(void)
{
    DDRB  |= 0b00101111;                    // PB0..PB3 and PB5 outputs
    DDRD  &= ~((1<<DDD2) | (1<<DDD3));    // PD2, PD3 inputs
    PORTD |=  (1<<PORTD2) | (1<<PORTD3);    // pull-ups
    EICRA |=  (1<<ISC01) | (1<<ISC11);      // falling edge for INT0 and INT1
    EICRA &= ~((1<<ISC00) | (1<<ISC10));
    EIMSK |=  (1<<INT0) | (1<<INT1);        // enable both
    sei();
    while (1)
    {
        PORTB ^= (1<<PORTB5);               // alive LED
        _delay_ms(1000);
    }
}

ISR(INT0_vect) { count = (count + 1) & 0x0F; show(); }   // 15 + 1 wraps to 0
ISR(INT1_vect) { count = 0;                   show(); }

4. Arduino firmware

const int ledPin[] = {8, 9, 10, 11};
const int aliveLed = 13, visitorBtn = 2, resetBtn = 3;
volatile byte count = 0;

void show() {
  for (int i = 0; i < 4; i++)
    digitalWrite(ledPin[i], (count >> i) & 1);
}
void addVisitor() { count = (count + 1) & 0x0F; show(); }
void clearCount() { count = 0; show(); }

void setup() {
  for (int i = 0; i < 4; i++) pinMode(ledPin[i], OUTPUT);
  pinMode(aliveLed, OUTPUT);
  pinMode(visitorBtn, INPUT_PULLUP);
  pinMode(resetBtn,   INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(visitorBtn), addVisitor, FALLING);
  attachInterrupt(digitalPinToInterrupt(resetBtn),   clearCount, FALLING);
}
void loop() {
  digitalWrite(aliveLed, !digitalRead(aliveLed));
  delay(1000);
}

5. Explanation

count is changed inside the ISRs, outside the normal flow of main(). Without volatile the compiler may keep a copy in a register and never see the change. Polling would be unsuitable because main() sleeps for 1 s in _delay_ms(1000): a visitor press lasting 100 ms would usually be missed, and the count would be wrong. Interrupts catch each press at once and the CPU does not waste time monitoring.

Marking hintsINT0/INT1 on PD2/PD3; EICRA set for falling edge; EIMSK enabled; sei() present; debounce capacitor; ISR short with no delay; volatile; wrap-around with & 0x0F; pins 0 and 1 unused; the wrapper version uses digitalPinToInterrupt.
