1. What is PWM?

  • A technique for getting an analog-like output by digital means.
  • The digital output is toggled fast enough that the attached device reacts not to the individual pulses but to the percentage of time that the output is high in one cycle.
  • How fast? Much faster than the device can respond: an LED must run above about 100 Hz to avoid visible flicker; a motor, whose inertia and inductance smooth the current, works well at hundreds of Hz to several kHz.
  • Why needed: a pin can only be 0 V or 5 V, but we want a dimmed LED or a motor at half speed.

Duty cycle and average voltage

Duty cycle = thigh / (thigh + tlow) × 100 % = thigh / period × 100 % = pulse width / period × 100 %.
Average voltage = duty cycle × Vhigh. Example: 5 V pulses with a 50 % duty cycle average 2.5 V; 0 % gives 0 V and 100 % gives 5 V (the multimeter in the lecture reads 0.00 V, 2.50 V, 5.00 V).

Frequency = 1 / period; for a given frequency, a larger duty cycle means more energy to the load (brighter LED, faster motor).

2. How a timer generates PWM (8-bit timer)

  1. The oscillator (through the prescaler) increments the TCNTn register from BOTTOM (0) to TOP.
  2. A comparator continuously compares TCNTn with the Output Compare Register OCRnX (X = A or B), a value that software writes (the pulse width).
  3. On a compare match the waveform generator changes the OCnX pin (and sets the flag OCFnX in TIFRn).
  4. The waveform generator generates one PWM cycle per timer cycle; software only changes OCRnX to change the duty cycle, with no CPU involvement for the waveform itself.
Mode of the outputBehaviour
Non-inverted (COMnX1:0 = 10)Clears OCnX on the compare match and sets it when the timer comes to BOTTOM. High from 0 until the match, low from the match to TOP: larger OCR means higher duty.
Inverted (COMnX1:0 = 11)Sets OCnX on the compare match and clears it at BOTTOM. Larger OCR means lower duty.

The OCnX output pins: OC0A = PD6 (Arduino 6), OC0B = PD5 (5), OC1A = PB1 (9), OC1B = PB2 (10), OC2A = PB3 (11), OC2B = PD3 (3). The pin must be configured as an output in DDR.

PWM frequency

F_Timer = F_CPU / prescale
FPWM = F_Timer / (TOP + 1) = F_CPU / ((TOP + 1) × prescale) (fast PWM and the generic form in the lecture). TOP = 28 − 1 = 255 for 8-bit timers and 216 − 1 = 65 535 for 16-bit timers. Choose the prescale that gives the required frequency.

For the 8-bit Timer0 at 16 MHz: prescale 1: 62.5 kHz; 8: 7.81 kHz; 64: 976.6 Hz ≈ 1 kHz; 256: 244 Hz; 1024: 61 Hz (too low for LEDs).

3. Timer modes

The mode decides how the timer behaves. It is selected with WGMn2 (TCCRnB bit 3) and WGMn1, WGMn0 (TCCRnA bits 1, 0):

WGMn2WGMn1WGMn0ModeTOP
000Normal255 (0xFF)
001Phase Correct PWM255
010CTC (Clear Timer on Compare)OCRnA
011Fast PWM255

Normal mode

  • TCNTn increments from 0 to TOP, overflows to 0 and starts again; sets TOVn in TIFRn when it overflows; interrupts on overflow if enabled (lesson 6). No PWM support.

CTC mode

  • TOP is programmable: TCNTn counts from 0 to OCRnA, then is cleared to 0 and starts again.
  • Sets OCFnX in TIFRn when TCNTn equals OCRnX (a compare match); interrupts on the compare match if the output compare interrupt is enabled (OCIEnA / OCIEnB in TIMSKn; vector TIMERn_COMPA_vect). No PWM support.
  • Use: exact periodic events. Period = (OCRnA + 1) × prescale / F_CPU. Example: 1 ms with prescale 64: OCR0A = 16 MHz/64/1000 − 1 = 249.

Fast PWM mode

  • TCNTn increments from 0 to TOP, overflows to 0 and starts again (a sawtooth). OCnX is cleared at the compare match during the increment and set when TCNTn becomes 0 (non-inverted).
  • Duty cycle = (OCR + 1) / (TOP + 1) × 100 % (note the +1: OCR = 0 still gives a 1/256 pulse).
  • FPWM = F_CPU / (256 × prescale) for an 8-bit timer.

Phase correct PWM mode

  • TCNTn increments from 0 to TOP and then decrements from TOP to 0 and repeats (a triangle). OCnX is cleared at the compare match while counting up and set at the compare match while counting down (non-inverted), so the pulse is symmetric about the centre of the cycle.
  • Duty cycle ≈ OCR / TOP × 100 %. FPWM = F_CPU / (2 × TOP × prescale) = F_CPU / (510 × prescale) for 8 bits, which is half the frequency of fast PWM at the same prescale.
Fast PWMPhase correct PWM
CountingUp only, then jump to 0Up then down
Frequency (8-bit, /64)976 Hz490 Hz
Pulse positionStarts at BOTTOM (edge aligned)Centred (symmetric), better for motor control
UseLED dimming, DACs, high frequencyMotor control, servo-like accuracy

Arduino's analogWrite() uses fast PWM on pins 5 and 6 (about 977 Hz) and phase correct PWM on pins 3, 9, 10, 11 (about 490 Hz), all with prescale 64, and analogWrite(pin, value) sets the duty cycle value / 255.

Steps to generate PWM with Timer0 (fast, non-inverted, about 1 kHz, on OC0A = PD6)1) DDRD |= (1<<DDD6) output. 2) Mode: WGM02 = 0, WGM01 = WGM00 = 1. 3) COM0A1 = 1, COM0A0 = 0. 4) Prescale 64: CS02 = 0, CS01 = 1, CS00 = 1. 5) Write the pulse width to OCR0A (0 to 255).

5. System 15: fader (fade an LED again and again)

Hardware: LED with a 220 Ω resistor on PD6 (OC0A, Arduino 6), cathode to GND.

Algorithm: configure PD6 as output; WGM = fast PWM; COM = non-inverted; PWM frequency about 1 kHz; loop: pulse width = 255; while pulse width ≥ 0: set OCR0A = pulse width, delay 30 ms, decrement by 5.

#include <avr/io.h>                       // IO definitions
#define F_CPU 16000000UL                   // CPU clock for delay.h
#include <util/delay.h>

int main(void)
{
    DDRD  = DDRD | 0b01000000;                              // PD6 (OC0A) output
    TCCR0B = TCCR0B & 0b11110111;                           // WGM02 = 0
    TCCR0A = TCCR0A | 0b00000011;                           // WGM01 = WGM00 = 1: fast PWM
    TCCR0A = (TCCR0A & 0b10111111) | 0b10000000;            // COM0A1 = 1, COM0A0 = 0: non-inverted
    TCCR0B = (TCCR0B & 0b11111011) | 0b00000011;            // CS02 = 0, CS01 = CS00 = 1: /64, about 1 kHz
    while (1)
    {
        for (int pulseWidth = 255; pulseWidth >= 0; pulseWidth -= 5)
        {
            OCR0A = pulseWidth;                             // set output compare value
            _delay_ms(30);
        }
    }
    return 0;
}

The same with labelled constants: DDRD |= (1<<DDD6); TCCR0B &= ~(1<<WGM02); TCCR0A |= (1<<WGM01)|(1<<WGM00); TCCR0A = (TCCR0A & ~(1<<COM0A0)) | (1<<COM0A1); TCCR0B = (TCCR0B & ~(1<<CS02)) | (1<<CS01) | (1<<CS00);

// Arduino wrapper version
int ledPin = 6;                              // PWM pin
void setup() { pinMode(ledPin, OUTPUT); }
void loop() {
  for (int pulseWidth = 255; pulseWidth >= 0; pulseWidth -= 5) {
    analogWrite(ledPin, pulseWidth);         // output pulses of the given width
    delay(30);
  }
}

The brightness falls from 100 % to about 0 % in 52 steps of 30 ms (about 1.6 s) and then repeats. Note OCR = 0 still outputs a 1/256 duty pulse in fast PWM; to get a true 0 % disconnect the pin (COM0A1 = 0) and write the pin low.

6. True analog output

PWM only approximates an analog output. Three options for a real analog voltage: (1) switch to a microcontroller with a built-in DAC (for example Arduino Due); (2) add a DAC breakout board; (3) pass the PWM signal through an RC low-pass filter, which averages the pulses into a smooth voltage (the cut-off must be well below the PWM frequency).

7. Exercise 6: auto fan (worked)

Specification: drive the 3 to 6 V DC motor of a fan from the room temperature sensed by an LM35: full speed at 35 °C or higher, off at 25 °C or lower, and a smooth increase or decrease in between. This demonstrates: physical phenomenon → analog voltage (LM35) → discrete number (ADC) → processed → analog-like output (PWM) → actuator.

Design

For a 3 to 6 V motor drawing about 100 mA: BC547 with RB = (5 − 0.7)/(100 mA/10) = 430 Ω, so 470 Ω. (A 2N7000 is the better choice for PWM.) Use a separate supply if the fan draws more than the Arduino 5 V rail can give.

Mapping

Temperature T (°C) = ADCW × 1.1 / 1024 × 100 with the internal 1.1 V reference (finer 0.107 °C steps). Duty: T ≤ 25 °C → 0; T ≥ 35 °C → 255; otherwise pulseWidth = (T − 25) / (35 − 25) × 255 (linear). Example: 30 °C gives 127 (about 50 %).

// Q2: Arduino wrapper functions
const int motorPin = 6;
void setup() {
  analogReference(INTERNAL);                 // 1.1 V
  pinMode(motorPin, OUTPUT);
}
void loop() {
  float t = analogRead(A0) * 1.1 / 1024 * 100;      // temperature in Celsius
  int duty;
  if      (t <= 25) duty = 0;
  else if (t >= 35) duty = 255;
  else                duty = (int)((t - 25) * 255 / 10);
  analogWrite(motorPin, duty);
  delay(200);
}
// Q3: C in the Arduino IDE without any wrapper functions
#include <avr/io.h>
int main(void)
{
    DDRD  |= (1<<DDD6);                                  // PD6 = OC0A output
    TCCR0A = (1<<COM0A1) | (1<<WGM01) | (1<<WGM00);       // fast PWM, non-inverted
    TCCR0B = (1<<CS01) | (1<<CS00);                     // /64, about 977 Hz
    ADMUX  = (1<<REFS1) | (1<<REFS0);                    // 1.1 V reference, channel ADC0
    ADCSRA = (1<<ADEN) | (1<<ADPS2) | (1<<ADPS1) | (1<<ADPS0);  // enable, F_CPU/128
    while (1)
    {
        ADCSRA |= (1<<ADSC);
        while (ADCSRA & (1<<ADSC));
        float t = ADCW * 1.1 / 1024 * 100;
        if (t <= 25)
        {
            TCCR0A &= ~(1<<COM0A1);                    // disconnect OC0A
            PORTD  &= ~(1<<PORTD6);                    // pin low: motor really off
        }
        else
        {
            TCCR0A |= (1<<COM0A1);                     // connect OC0A
            OCR0A = (t >= 35) ? 255 : (unsigned char)((t - 25) * 255 / 10);
        }
    }
}
Common mistakes1) PWM pin not set as output. 2) Using a non-PWM pin with analogWrite (only 3, 5, 6, 9, 10, 11). 3) Driving the motor directly from the pin; no flyback diode. 4) Timer0 changes also affect delay()/millis() in Arduino (they use Timer0). 5) Forgetting that fast PWM has a minimum 1/256 pulse at OCR = 0. 6) Using the wrong CS bits for the target frequency. 7) Integer division: write (t - 25) * 255 / 10 with floating t. 8) Mixing up inverted and non-inverted.

1. Why PWM?

So far you can read digital and analog sensors, and you can switch digital actuators fully ON or fully OFF (directly, or through a BJT, MOSFET or relay). But many jobs need something in between:

  • Dim a light instead of only on/off.
  • Slow down a motor: a line-following car must slow down before a bend or it topples; a quadcopter must reduce its 4 motors gradually to land, otherwise it crashes.

The CPU is digital: a pin is either 0 V or 5 V. The ATmega328P has no DAC (digital-to-analog converter), so it cannot output 2.5 V. PWM solves this: it gets an analog-like output by digital means.

The idea in one sentence Toggle a digital pin ON/OFF fast enough that the attached device does not react to each pulse, but to the percentage of time the output is HIGH in one cycle.

The bulb experiment (lecturer's example): a filament bulb needs a short time to fully light and to fully go dark. Switch it on, and before it is fully bright switch it off; before it is fully dark switch it on again, very rapidly. The bulb settles at a brightness in between. Keep it ON for a larger part of each cycle and it is brighter (about 20% on → dim, 90% on → nearly full). The signal is still pure on/off (digital), but you see a smooth (analog-like) brightness.

2. Duty cycle and average voltage

Figure 1. A PWM signal. Here thigh is one third of the period: duty cycle 33%, average 1.67 V.
Formulas duty cycle = thigh / (thigh + tlow) × 100% = pulse width / period × 100%
average voltage = Vhigh × duty cycle   (Vhigh = 5 V on the Uno)

For a fixed frequency the period is fixed (T = 1/f). So the only thing we change is the width of the pulse: changing (modulating) the pulse width changes the duty cycle, the average voltage, and so the brightness or speed. That is the name: pulse width modulation.

Duty cycle0%25%50%75%100%
Average (voltmeter reads)0 V1.25 V2.5 V3.75 V5 V

Voltmeter vs oscilloscope: a multimeter on a 50% PWM pin shows 2.5 V, because it averages, just like your eye or a motor. An oscilloscope (voltage against time) shows the truth: a square wave jumping between 0 and 5 V. PWM is an "illusion" of analog.

3. How fast? Choosing the PWM frequency

  • Too slow: the device follows each pulse. An LED flickers. For LEDs use > 100 Hz; in practice 500 Hz–1 kHz.
  • Too fast for a slow device: a motor needs time to start, so it may not start at all. Toggle slower than the fastest change the device can follow.
  • The right range comes from the device's datasheet (min and max supported PWM frequency). E.g. the datasheet says 100–300 Hz → set about 200 Hz.

4. How a timer makes PWM

Figure 2. PWM hardware of one timer. The comparator compares TCNTn with OCRnx; on a match it sets the OCF flag and triggers the waveform generator, which drives the OC pin.
  1. The timer counts TCNTn from 0 (BOTTOM) up to TOP (255 for 8-bit), then overflows to 0, over and over (Lesson 7).
  2. You put a number between BOTTOM and TOP into OCRnA (Output Compare Register). This number sets the duty cycle.
  3. The comparator constantly compares TCNTn with OCRnA. When they are equal (a compare match) it sets the OCFnA flag in TIFRn and triggers the waveform generator.
  4. The waveform generator switches the OCnA pin. In non-inverted mode it clears the pin (LOW) on the match and sets it (HIGH) when TCNTn returns to BOTTOM.
Figure 3. Fast PWM, non-inverted. Raise OCR → the match comes later → the pin stays HIGH longer → bigger duty cycle.
  • Inverted mode is the opposite: set the pin on a match, clear it at BOTTOM. The duty cycle becomes (TOP − OCR) / (TOP + 1).
  • Each timer has one TCNTn but two OCR registers (A and B), two comparators, two waveform generators and two OC pins. That gives 3 timers × 2 = 6 PWM pins, marked ~ on the Uno.
  • There are two control registers (TCCRnA and TCCRnB) simply because one 8-bit register cannot hold all the control bits.
Duty cycle from OCR (fast PWM, non-inverted) duty cycle = (OCR + 1) / (TOP + 1) × 100%  ⇒  OCR = duty × (TOP + 1) − 1
8-bit: OCR 127 → 128/256 = 50% (2.5 V); OCR 63 → 25% (1.25 V); OCR 191 → 75%; OCR 255 → 100% (5 V).
OCR = 0 gives a very narrow spike (1/256), not a perfect 0 V. analogWrite(pin, 0) avoids this by simply writing the pin LOW.

5. PWM frequency and prescale

Counting from 0 up to TOP and back to 0 takes TOP + 1 timer ticks, and that is one PWM cycle. So:

Fast PWM frequency F_timer = F_CPU / prescale   ⇒   F_PWM = F_CPU / ((TOP + 1) × prescale)   ⇒   prescale = F_CPU / ((TOP + 1) × F_PWM)
TOP = 28 − 1 = 255 for 8-bit, 216 − 1 for 16-bit. (Phase correct PWM counts up and down, so it is about half this frequency: F_CPU / (2 × TOP × prescale).)
8-bit, 16 MHz, fast PWM/1/8/64/256/1024
F_PWM62.5 kHz7.8 kHz976.6 Hz244 Hz61 Hz
Phase correct31.4 kHz3.9 kHz490 Hz122.5 Hz30.6 Hz

Worked (slides): want 1 kHz → prescale = 16 000 000 / (256 × 1000) = 62.5. No such prescale exists, so take the nearest, 64 → actual F_PWM = 16 000 000 / (256 × 64) = 976.5 Hz, close to 1 kHz. (These are also the Arduino defaults: pins 5 and 6 ≈ 980 Hz, the others ≈ 490 Hz.)

8. System 15: the fader (LED fades from full to off, again and again)

Hardware: LED + 220 Ω on D6 (PD6 = OC0A) to GND. It must be a ~ pin: an LED on D8 cannot be dimmed by PWM. Settings: fast PWM (LED, high frequency), non-inverted, prescale 64 → 976.5 Hz.

// faderC.c
#include <avr/io.h>
#define F_CPU 16000000UL                      // CPU clock for delay.h
#include <util/delay.h>                       // _delay_ms()

int main(void)
{
    DDRD = DDRD | 0b01000000;                         // PD6 (OC0A) output
    TCCR0B = TCCR0B & 0b11110111;                     // WGM02 = 0
    TCCR0A = TCCR0A | 0b00000011;                     // WGM01 = 1, WGM00 = 1: fast PWM
    TCCR0A = (TCCR0A & 0b10111111) | 0b10000000;      // COM0A1 = 1, COM0A0 = 0: non-inverted
    TCCR0B = (TCCR0B & 0b11111011) | 0b00000011;      // CS = 011: /64 -> ~1 kHz
    while (1)
    {
        for (int pulseWidth = 255; pulseWidth >= 0; pulseWidth -= 5)
        {
            OCR0A = pulseWidth;                       // new duty cycle
            _delay_ms(30);                            // so the eye can see the fade
        }
    }
    return 0;
}

OCR 255 → 5 V, about 125 → 2.5 V, about 63 → 1.25 V, down to 0. Without the 30 ms delay the whole fade would take under a millisecond and you would not see it.

9. True analog output

PWM is fine for lights and motors, but for audio or music a real continuously varying voltage gives much better quality. Three options:

  1. A microcontroller with a built-in DAC, e.g. the AT91SAM3X8E on the Arduino Due (10-bit DAC: 0–1023). Expensive.
  2. A DAC breakout board: cheap, but uses several I/O pins to talk to it.
  3. An RC filter (resistor + capacitor) on the PWM pin smooths the pulses into an analog voltage. R and C depend on the PWM frequency (formula beyond this course).

10. Build example: Exercise 6 — the auto fan

Task: an LM35 measures room temperature. ≤ 25 °C → motor OFF, ≥ 35 °C → full speed, and in between the speed rises and falls smoothly. This one system uses everything: a sensor (Lesson 6), the ADC (Lesson 5), PWM (this lesson) and a transistor driver (Lesson 6).

Figure 5. Auto fan. LM35 (flat face toward you: +Vs, Vout, GND) on A0. D6 drives the BC547 base through 1 kΩ; motor between its own supply + and the collector; flyback diode across the motor (stripe to +).

Why these choices: D6 is a PWM pin. The motor can't run from the pin (Lesson 6), so a transistor switches it. The motor has its own supply with the grounds joined. Check the motor current: the BC547 handles at most 100 mA; for a bigger motor use a 2N7000 (200 mA) or a power transistor. For a motor, phase correct PWM (≈ 490 Hz at /64) is the traditional choice.

The mapping. LM35: 10 mV/°C. With Vref = 5 V: T(°C) = ADC × 500 / 1024. Then:

T ≤ 25 → OCR = 0 (off)   |   T ≥ 35 → OCR = 255 (full)   |   between: OCR = (T − 25) × 255 / 10 (e.g. 30 °C → 127 ≈ 50%)
Here Vref = 5 V keeps the maths simple (1 step ≈ 0.49 °C). The Part 1 notes use the 1.1 V internal reference instead (ADMUX REFS = 11, T = ADC × 110 / 1024), which gives finer steps (≈ 0.11 °C) for the 0–1 V the LM35 produces in a room. Either is acceptable.
// Exercise 6 Q3: auto fan in C (no wrapper functions)
#include <avr/io.h>

int main(void)
{
    DDRD = DDRD | 0b01000000;                      // PD6 (OC0A) output: motor driver
    TCCR0A = (TCCR0A & 0b11111100) | 0b00000001;   // WGM01 = 0, WGM00 = 1: phase correct PWM
    TCCR0B = TCCR0B & 0b11110111;                  // WGM02 = 0
    TCCR0A = (TCCR0A & 0b10111111) | 0b10000000;   // COM0A = 10: non-inverted
    TCCR0B = (TCCR0B & 0b11111011) | 0b00000011;   // /64 -> ~490 Hz
    ADMUX = 0b01000000;                            // Vref = AVcc (5 V), right-adjusted, channel ADC0
    ADCSRA = 0b10000111;                           // ADC enable, prescale /128

    while (1)
    {
        ADCSRA = ADCSRA | 0b01000000;              // ADSC = 1: start conversion
        while (ADCSRA & 0b01000000) { }            // wait until ADSC = 0 (done)
        long t10 = (long)ADCW * 5000 / 1024;       // temperature x10 (e.g. 302 = 30.2 C)

        if (t10 <= 250)
            OCR0A = 0;                             // 25 C or lower: off
        else if (t10 >= 350)
            OCR0A = 255;                           // 35 C or higher: full speed
        else
            OCR0A = (t10 - 250) * 255 / 100;       // smooth in between
    }
}

L. What the lecturer explained in the lectures (2020 recordings)

From the three PWM recordings (folders 22–24 in Embedded Systems Lectures). [EXAM] marks things he tied to the exam.

L1. "Analog-like", not analog [EXAM] He stressed the word like: "PWM is not true analog. It gives analog-like output." It is a digital technique, a kind of illusion. Users see and feel analog, a voltmeter even reads 2.5 V, but "only the oscilloscope can tell us the truth": it is a 0/5 V square wave. "You don't need any rocket science to understand PWM" (the bulb example), even though books are full of mathematics.

L2. Why PWM: his examples

  • So far you can turn actuators fully on or off. PWM is how a digital computer drives analog actuators: dim a light, slow a motor.
  • A small line-following car must slow down for a bend or junction or it topples, then speed up again. A quadcopter ("quad = four propellers") must take off and land gradually; switching the motors off is a crash landing.
  • The filament bulb experiment (section 1): switch on and off faster than the filament can fully heat or cool. 20% on → dim, 40% → brighter, 90% → nearly full.

L3. Frequency and datasheets

  • "Faster than a human eye can see any flicker": for LEDs > 100 Hz, normally 500 Hz to 1 kHz.
  • Slow devices like motors take time to start; toggle too fast and "the motor would not start at all". Toggle slower than the maximum speed the device can react.
  • Find the supported PWM range in the datasheet. Every reliable component has one (even a resistor): dimensions, voltage, current, heat, PWM range, hazardous materials such as mercury or cadmium.
  • Cheap local parts often come with no datasheet. Find the identical clone on SparkFun and download its datasheet ("get the cheap device from Pettah, the datasheet from SparkFun").

L4. Instruments

  • A multimeter must at least be a voltmeter, ammeter and ohmmeter; modern ones also measure capacitance, inductance and frequency. A good (Japanese) one costs under Rs 10 000; cheap ones about Rs 1 000 are less accurate.
  • An oscilloscope plots voltage against time. Even a cheap one costs Rs 40–50 000; a good one can be about Rs 500 000.
  • His quiz: 50% duty → 2.5 V; for 1.25 V use 25%; 75% → 3.75 V.

L5. How the waveform is made [EXAM]

  • "To use PWM you don't need to know all these things", but as university students you must know how the waveform generator works. He said many good embedded programmers know how to use PWM but not this. At graduation you should be able to self-learn what wasn't covered ("we stopped at S; T to Z you learn yourself").
  • Duty cycle formula he wrote: (OCR + 1) × 100 / (TOP + 1). OCR 127 → 50%, OCR 63 → 25%.
  • OCR at TOP keeps the pin at 5 V; near BOTTOM it is (almost) always 0 V. OCR closer to TOP = longer HIGH time.
  • Derivation of F_PWM: with TOP = 3 the counter makes 0→1→2→3→0 = 4 = TOP + 1 ticks per PWM cycle. So ttimer = tPWM / (TOP + 1), F_PWM = F_timer / (TOP + 1) = F_CPU / ((TOP + 1) × prescale).
  • Student asked why there are two control registers (TCCRnA and TCCRnB): there are too many control bits for one 8-bit register. Other peripherals (like the USART) do the same.

L6. Modes

  • Normal mode is why the Lesson 7 timers worked without touching WGM: all WGM bits default to 0.
  • CTC example: count to 5 by putting 5 in OCR and watching OCF; no need to reset TCNT, because the timer clears it itself. A student asked why CTC exists when normal mode can do the same. He said honestly he would check and let them know, and that CTC "is not widely used".
  • He prompted the class to ask "why two PWM modes?" and answered: for the same prescale, fast PWM gives more pulses (higher frequency) for LEDs, while phase correct gives fewer (about half, e.g. 1 kHz vs 500 Hz) for motors. You get both just by changing the mode.
  • Dimming a 230 V bulb? Not with a relay: a relay cannot switch on and off fast enough for PWM. Use a TRIAC (3 pins: gate, T1, T2). He discouraged it because of the shock risk with mains, unless you have experience.

L7. Fader details [EXAM]

  • A common mistake: connecting the device to a pin that is not PWM-capable (e.g. D8) and expecting a fade. Use a ~ pin; he used D6 = OC0A of Timer0.
  • Fast PWM for the LED (avoid flicker), non-inverted ("the widely used mode"), 1 kHz.
  • Prescale for 1 kHz = 62.5, which does not exist, so use 64 → 976.5 Hz, "not exactly 1 kHz".
  • The 30 ms delay is there only so the eye can see the fade.
  • Demo with analogWrite(9, 250): the multimeter read 4.72 V, not 5 V (250/255 × 5 ≈ 4.9 V; a real pin and meter read a little lower).
  • The Arduino version hides WGM, COM and frequency inside analogWrite. You only give the pin and the width.

L8. True analog, and the reaction-timer seed

  • True analog matters for quality audio/music. Three options: a built-in DAC (Arduino Due, AT91SAM3X8E, 10-bit DAC; about Rs 4 000 for a clone, Rs 12 000 original), a DAC breakout (about Rs 300–350, but it uses about 4 I/O pins), or an RC filter (formula is beyond the course).
  • Exercise 5 question: why seed srand? Without a random seed, anyone who knows the algorithm can predict the numbers. PCs use the system clock; a microcontroller has none. So use the elapsed time from power-up to the first press (a timer), or a floating analog pin, which acts like an antenna and picks up random electromagnetic noise.
  • He prefers to guide students to answers rather than give them. Keep asking questions.
  • Next lesson: data communication (serial, parallel, synchronous, asynchronous), first what happens behind Serial.print, then Arduino.

Written questions

W1. Explain how a timer generates a PWM waveform and derive the PWM frequency and duty cycle for fast PWM.

The prescaled clock increments TCNT from 0 to TOP. A comparator compares TCNT with OCRnX; at the match the waveform generator clears the OCnX pin (non-inverted) and it is set again when TCNT returns to 0. FPWM = F_CPU / ((TOP + 1) × prescale); duty cycle = (OCR + 1) / (TOP + 1). With TOP = 255, prescale 64 and F_CPU = 16 MHz, FPWM = 976.6 Hz; OCR = 127 gives 50 %.

W2. Compare fast PWM and phase correct PWM.

Fast PWM counts up only then jumps to 0 (frequency F_CPU/(256×prescale), edge aligned, highest frequency). Phase correct PWM counts up and down (frequency F_CPU/(510×prescale), half of fast PWM), and its pulses are symmetric about the centre, which suits motor control; duty ≈ OCR/TOP.

W3. Write the register configuration to produce 1 kHz non-inverted fast PWM on PD6 and explain each bit. 
DDRD |= (1<<DDD6);                       // PD6 output
TCCR0A = (1<<COM0A1)|(1<<WGM01)|(1<<WGM00); // non-inverted, fast PWM
TCCR0B = (1<<CS01)|(1<<CS00);              // /64 = 976.6 Hz
OCR0A = 128;                               // about 50 % duty

COM0A1:0 = 10 clears OC0A at the match; WGM02:0 = 011 is fast PWM; CS = 011 selects F_CPU/64.

W4. Describe the auto fan design and the firmware logic.

LM35 on A0 with the 1.1 V reference (T = ADCW × 1.1/1024 × 100). PWM on pin 6 (OC0A) drives a BC547 or 2N7000 that switches the motor, with a 1N4001 flyback diode and a common ground. Duty: 0 at ≤ 25 °C, 255 at ≥ 35 °C and (T − 25)/10 × 255 between, written to OCR0A (or analogWrite(6, duty)).

W5. [2020 recording] Explain PWM using the filament bulb example and say why it is called analog-like.

A filament takes a short time to fully heat (bright) and to fully cool (dark). If you switch it on and, before it reaches full brightness, switch it off, and before it is fully dark switch it on again, very rapidly, it settles at an in-between brightness. It reacts not to each pulse but to the percentage of time the supply is ON in one cycle (the duty cycle): about 20% ON looks dim, 90% looks nearly full. The signal is still purely digital (on/off), which an oscilloscope shows, but the eye, a motor or a voltmeter respond to the average, so it is analog-like, not true analog.

W6. [2020 recording] Derive F_PWM = F_CPU / ((TOP + 1) x prescale) and use it for 8-bit fast PWM at 1 kHz.

In fast PWM the counter goes 0→TOP and back to 0: that is TOP + 1 timer ticks (e.g. TOP = 3: 0→1→2→3→0 = 4 ticks) and it produces one PWM cycle. So tPWM = (TOP + 1) ttimer and F_PWM = F_timer / (TOP + 1). Since F_timer = F_CPU / prescale, F_PWM = F_CPU / ((TOP + 1) × prescale). For 1 kHz: prescale = 16 000 000 / (256 × 1000) = 62.5, which does not exist, so use 64: F_PWM = 16 000 000 / (256 × 64) = 976.5 Hz.

Practical question: "Twin-lamp dimmer" (exam style)

Original practice question modelled on the fader and Exercise 6 (ADC in, PWM out) and using the inverted mode of the compare output.

ScenarioA reading lamp has a bright LED and a night-light LED. A potentiometer sets the main LED brightness from off to full. The night-light LED does the opposite: it is brightest when the main LED is off and off when the main LED is at full brightness. Both are driven by PWM at about 1 kHz from the two outputs of the same timer.
  1. Choose the timer, mode and prescaler, and calculate the PWM frequency.
  2. Give the connection list.
  3. Write the firmware in C. Use the inverted output mode for the night light.
  4. Write the firmware with the Arduino wrapper functions.
  5. What duty cycle does each LED get when the potentiometer is at the middle (ADC = 512)?
Solution

1. Timer

Timer0 in fast PWM (WGM02:0 = 011), prescale 64 (CS02:0 = 011). FPWM = 16 MHz / (256 × 64) = 976.6 Hz ≈ 1 kHz. Outputs: OC0A = PD6 (pin 6, main LED, non-inverted, COM0A1:0 = 10) and OC0B = PD5 (pin 5, night light, inverted, COM0B1:0 = 11). The same OCR value then gives opposite brightness: duty A = (OCR + 1)/256, duty B = 1 − (OCR + 1)/256.

2. Connections

PartConnection
10 kΩ potentiometerends to 5 V and GND, wiper to A0 (PC0)
Main LEDpin 6 (PD6) → 220 Ω → LED → GND
Night LEDpin 5 (PD5) → 220 Ω → LED → GND

3. C firmware

#include <avr/io.h>

int main(void)
{
    DDRD  |= (1<<DDD6) | (1<<DDD5);                     // OC0A, OC0B outputs
    TCCR0A = (1<<COM0A1)                                 // OC0A non-inverted (10)
           | (1<<COM0B1) | (1<<COM0B0)                  // OC0B inverted (11)
           | (1<<WGM01)  | (1<<WGM00);                  // fast PWM
    TCCR0B = (1<<CS01) | (1<<CS00);                     // /64, 976.6 Hz
    ADMUX  = (1<<REFS0);                                 // AVcc, channel ADC0
    ADCSRA = (1<<ADEN) | (1<<ADPS2) | (1<<ADPS1) | (1<<ADPS0);
    while (1)
    {
        ADCSRA |= (1<<ADSC);
        while (ADCSRA & (1<<ADSC));
        unsigned char v = ADCW >> 2;                     // 10-bit to 8-bit (0..255)
        OCR0A = v;                                       // main LED
        OCR0B = v;                                       // night light (inverted output)
    }
}

4. Arduino firmware

const int mainLed = 6, nightLed = 5;
void setup() { pinMode(mainLed, OUTPUT); pinMode(nightLed, OUTPUT); }
void loop() {
  int v = analogRead(A0) / 4;          // 0..255
  analogWrite(mainLed, v);
  analogWrite(nightLed, 255 - v);      // analogWrite is non-inverted, so invert in software
}

5. Middle position

ADC = 512 gives OCR = 512 >> 2 = 128. Main LED: duty = (128 + 1)/256 = 50.4 %. Night LED (inverted): 1 − 129/256 = 49.6 % (about half each).
