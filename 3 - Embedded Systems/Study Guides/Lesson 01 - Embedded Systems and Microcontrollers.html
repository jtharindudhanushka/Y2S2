1. What is an embedded system?

  • A computer system embedded into some other system, used to get one dedicated task done.
  • It performs physical computing: Sensors → Processor → Actuators (input, process, output).
  • It usually works under strict constraints.
  • Sensors capture the state of the real world and feed it to the processor as input.
  • The processor processes the inputs following instructions given by programming. These instructions are called firmware (it does not change once loaded).
  • The outputs drive the actuators (for example the motor of a fan).
  • Example: sense temperature; if it is above 30 °C, turn on the fan.

Constraints (the four to remember)

ConstraintMeaning
CostMust be cheap (bought in bulk, for example fire alarms)
Weight and sizeMust be small and light
Power consumptionMust consume very little power (battery operation, little heat)
Real-time performanceMust respond to events within a deadline

(syllabus) Other design pressures include reliability, memory limits (small RAM and ROM) and safety.

Examples from the lecture

SystemMain taskHow it is achieved
Anti-lock braking system (ABS)Apply equal braking to all four wheels so none locksRotational speed sensors measure each wheel (RPM). The processor compares them. The actuator is a hydraulic pump: if one wheel is braked less than the other three, fluid is released to that wheel until all four rotate at the same speed.
Flight controller (quadcopter)Fly the drone stablySensors: gyroscope, accelerometer and the radio-control receiver (pilot commands). The processor varies the speed of the four motors (through four ESCs) from these inputs.

2. Evolution, growth and the shift of industry

  • Early days: Apollo guidance and Minuteman missile guidance systems. Military and scientific use only, because they were very expensive.
  • Today: agriculture, manufacturing robots, medical MRI, consumer electronics. The embedded computing market grows from about USD 101 billion (2022) to about USD 178 billion (2032), which is why the subject matters.
  • Shift of industry (compare a Nokia 3310 with a later phone that has far fewer chips): most functionality moved from hard-wired electronics to software. A software-implemented function is an embedded system.
Advantages of software over hard-wired electronics (peer notes)1. Easier to implement (software runs on generic hardware). 2. Lower cost. 3. Easier to debug. 4. Easier to modify.

3. Components of an embedded system

A CPU connected to RAM (keeps temporary data), ROM (keeps the firmware), input/output ports and clock / timers / counters. The I/O ports connect to sensors and actuators.

4. Microprocessor-based vs microcontroller-based

Microprocessor-based (single board)Microcontroller-based (single chip)
ProsVery high specification and performance; each component can be replaced or upgradedCheap; power efficient and low heat; compact
ConsExpensive; consumes a lot of power and generates heat; bulkyComponents cannot be replaced individually; everything is miniature so the specification is modest

Which to choose?

  • Adaptive traffic control (camera + image processing): needs a lot of RAM and processing, and has no size or power constraint, so use a microprocessor-based board (for example a Raspberry Pi class board).
  • Fire / smoke alarm: binary sensors, binary outputs, little processing, battery operated, small and bought in bulk, so use a microcontroller.
  • Most embedded systems are microcontroller-based because they do not need power-hungry, bulky hardware.

5. The microcontroller (lecture 02)

A microcontroller is a single chip computer. It integrates CPU, RAM, ROM, ADC, oscillator, I/O ports, serial ports, PWM and timers.

ComponentPurpose
CPUExecutes the instructions of the firmware
ROM (Flash)Stores the firmware. Called Flash because the developer can rewrite it. Larger than RAM because firmware is bulky.
RAMStores variables and temporary data (small, volatile)
EEPROMNon-volatile but changeable data such as settings. Firmware goes into ROM (by the developer); EEPROM data is written by the user or program at run time.
ADCAnalog to Digital Converter. Most real-world inputs (temperature, speed, light) are analog but the processor only understands digital.
OscillatorGives precise clock pulses (1,0,1,0...) to the processor
PWMPulse Width Modulator. Gives an analog-like output (for example dim a light) rather than plain ON/OFF.
Timers (T0, T1, T2)Measure elapsed time and count events
I/O ports (A, B, C, D...)Receive inputs and deliver outputs. More ports means more I/O pins; the number is chosen by requirement.
Serial communicationUSART (microcontroller to PC), SPI (fast, 4 wires, microcontroller to microcontroller or memory chip), I²C (slower, 2 wires, also called TWI, nearby devices)
RESET and power supplyRESET clears and restarts execution from the very first instruction

What is an I/O port and how does it work?

  • An I/O port is an 8-bit register associated with microcontroller pins. Pins are counted like array indexes, 0 to 7.
  • The bit value is the logic level of the pin. Logic high is about 2 to 5 V and logic low is about 0 to 1 V.
  • Input: a switch on pin 0 with a resistor to 5 V. Switch open: the pin sees 5 V, so the bit is 1. Switch pressed: the pin is connected to ground, so the bit is 0. The resistor stops a short circuit between 5 V and ground.
  • Output: the program writes a bit to the port register, which drives the pin high or low and so turns an LED on or off.
Internal working examplePseudocode: if bit 0 of PORT = 0 then bit 2 of PORT ← 1 else bit 2 of PORT ← 0. External electronics change the flow of the program through an input pin, and the program drives external electronics through an output pin.

6. How a microcontroller is programmed

  1. Write the program in a high-level language (C) or assembly on a PC.
  2. The compiler / assembler converts it to machine code in a .hex file (hexadecimal text, almost machine code).
  3. A programmer (or the Arduino bootloader) uploads the hex file into the ROM (Flash).
  4. The programmed microcontroller sits on the system board. The CPU fetches instructions from ROM, sensors give input and actuators take output.

7. Word size and the AVR family

  • Word size is the number of bits processed at a time: 8, 16 or 32.
  • For learning, 8-bit is ideal: easier to learn, cheaper, free and open tools and a large community. You can migrate to 32-bit later. (The 8-bit segment grows slowly, about 11.7 % CAGR 2022 to 2030, but remains widely used.)
  • 8-bit families: 68HC08 / 68HC11 (NXP, formerly Motorola), 8051 (Intel), AVR (Microchip, formerly Atmel), PIC (Microchip), STM8 (STMicroelectronics).

10. Extra theory (syllabus)

  • Harvard vs von Neumann: Harvard has separate program and data memories and buses so an instruction and data can be fetched at the same time (AVR is Harvard). Von Neumann shares one memory.
  • RISC vs CISC: RISC uses a small set of simple instructions, mostly one cycle each, so execution time is predictable (AVR). CISC has many complex instructions.
  • Firmware is the program stored in ROM. A bootloader is a small resident program that lets the board load new firmware over serial/USB without an external programmer (the Arduino method, using AVRDUDE). A hardware programmer writes the chip directly.
  • Hardware-software co-design: designing hardware and firmware together, deciding which function goes in hardware and which in software.
  • Embedded OS / RTOS: an operating system with deterministic timing; small systems (like our Arduino) run bare-metal with no OS, which is why an endless loop is needed.

Written questions

W1. Define an embedded system, name its three functional blocks and list four constraints. Illustrate with an example.

An embedded system is a computer system embedded into another system to perform a dedicated task. It performs physical computing with sensors (capture the state of the physical world), a processor (executes firmware) and actuators (change the physical world). Constraints: cost, weight/size, power consumption, real-time performance. Example: ABS. Speed sensors measure wheel rotation; the processor compares the four wheels; a hydraulic pump (actuator) releases brake fluid to a wheel braked more than the others until all rotate at the same speed.

W2. Compare microprocessor-based and microcontroller-based implementations and justify the choice for (a) an adaptive traffic control camera and (b) a fire alarm.

Microprocessor-based: separate CPU, ROM, RAM, I/O on a board (single board computer); high performance, replaceable parts, but expensive, power hungry, hot and bulky. Microcontroller-based: everything in one chip (single chip computer); cheap, low power, compact, but parts cannot be replaced and performance is modest. (a) Traffic camera: image processing needs a lot of RAM and speed and there is no size or power limit, so a microprocessor board. (b) Fire alarm: binary sensors, tiny processing, battery power, small and bought in bulk, so a microcontroller.

W3. Explain the function of the core components of a microcontroller.

CPU executes instructions; ROM/Flash stores firmware; RAM stores variables; EEPROM stores non-volatile settings; ADC converts analog sensor voltages to numbers; oscillator provides precise clock pulses; PWM produces analog-like outputs; timers measure time and count events; I/O ports connect sensors and actuators; serial interfaces (USART, SPI, I2C) communicate with other devices; RESET restarts execution from the first instruction.

W4. Explain how a program written on a PC ends up running on an ATmega328P, and why ATmega328P / Arduino Uno is chosen for learning.

The source (C or assembly) is compiled/assembled to a HEX file, which a programmer or the Arduino bootloader (via AVRDUDE) uploads into the Flash ROM. The CPU then fetches and executes the instructions. The ATmega328P is an 8-bit AVR (easy to learn, cheap, free tools), the most popular and best documented MCU, and the heart of the Arduino Uno, the most used development board. It has 32 KB Flash, 2 KB RAM, 1 KB EEPROM, 23 I/O pins, 3 timers, 6 PWM channels, 10-bit ADC, USART, SPI and I2C, in a breadboard-friendly 28-pin PDIP.

Practical question: "Status light" (warm-up, exam style)

Original practice question written for this guide in the style of the practical exam. It tests only what lessons 1 and 2 cover: choosing the platform, reading the pin diagram, the resistor calculation and the first firmware.

ScenarioA workshop needs a "status light" that shows the state of a machine with three LEDs (green, yellow, red). The system is battery powered, produced in thousands and has a single binary input from a limit switch. All three LEDs are driven at 2 V and 10 mA. The supply is 5 V.
  1. State, with reasons, whether a microprocessor-based or microcontroller-based design is appropriate.
  2. Calculate the series resistor for each LED and give the nearest preferred value. Prepare a Bill of Materials.
  3. Assemble the circuit on a breadboard using an Arduino Uno: connect green, yellow and red LEDs to Arduino pins 8, 9 and 10. Give a wiring table with the ATmega328P port bit for each pin.
  4. Write the firmware (Arduino wrapper functions) that cycles green, yellow, red, each for 1 second, repeatedly.
  5. Write the same firmware in C using direct register access.
Solution

1. Platform

Microcontroller-based. Binary input and outputs mean very little processing; battery operation needs low power and compactness; thousands of units need low cost.

2. Resistor and BOM

R = (VS − VL) / IL = (5 − 2) / 0.010 = 300 Ω. The nearest standard value from the E-series kit parts is 330 Ω (slightly less current, about 9 mA, still bright). Using 220 Ω gives 13.6 mA, which is also within a typical LED rating.

4. Arduino wrapper version

const int led[] = {8, 9, 10};          // green, yellow, red

void setup() {
  for (int i = 0; i < 3; i++)
    pinMode(led[i], OUTPUT);           // configure as outputs
}

void loop() {
  for (int i = 0; i < 3; i++) {
    digitalWrite(led[i], HIGH);        // LED on
    delay(1000);                       // 1 s
    digitalWrite(led[i], LOW);         // LED off
  }
}

5. C version

#include <avr/io.h>
#define F_CPU 16000000UL
#include <util/delay.h>

int main(void)
{
    DDRB |= (1<<DDB0) | (1<<DDB1) | (1<<DDB2);   // PB0..PB2 outputs
    while (1)
    {
        for (int i = 0; i < 3; i++)
        {
            PORTB |= (1<<i);        // LED on
            _delay_ms(1000);
            PORTB &= ~(1<<i);       // LED off
        }
    }
    return 0;
}
Marking hintsReasoning for the platform; the working for R shown; BOM complete; LED polarity and common ground; DDR set before PORT; while(1) loop present; F_CPU defined before including util/delay.h.
