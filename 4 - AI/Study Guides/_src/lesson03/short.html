TopicRemember
AgentSenses the environment, decides, acts through actuators/tools, repeats. AI agent ≠ chatbot: takes a goal, interprets instructions, may call tools, may coordinate with other agents.
n8nVisual workflow tool: trigger + connected nodes; can call LLMs and apps (Gmail, Google Calendar).
Booking assignmentForm → Edit Fields (start/endDateTime, Asia/Colombo) → Calendar check → IF free: create event → Basic LLM Chain + Gemini writes email → Gmail → success page; else "unavailable" message. 8 required nodes.
Google ADKOpen-source framework to build, test, evaluate, deploy agents. Lab: Python + ADK Web Visual Builder (experimental).
Why a frameworkModel interprets intent · instructions set boundaries · tools do controlled deterministic work · specialist agents split the task · workflow agents control order.
LlmAgentName, model, instructions, optional description / tools / sub-agents.
Root agentEntry point and coordinator: identify request, pick one child, transfer (transfer_to_agent); do not do specialist work; keep tools off it.
Sub-agentSpecialist child (intake, classification, outage, billing, response).
ToolControlled capability (Python Function tool). Narrow, structured results. Read-only tools never modify; write tools validate and enforce authorisation themselves. Register on the agent that owns the responsibility.
Built-in toolget_user_choice: explicit consent before writes.
Session / eventsSession = one conversation (new one per test). Events show agent run, transfers, tool calls with input/output, errors.
Workflow agentsDeterministic (no model decides). Sequential: in order. Parallel: concurrent, independent branches. Loop: repeat until stop or max iterations.
One-parent ruleAn agent instance has one parent; use uniquely named copies (seq_triage_agent, par_triage_agent). Visual Builder only creates new sub-agents.
Model vs toolModel: understand, pick intent, ask follow-ups, explain. Tool: CSV reads, exact matching, duplicate checks, IDs, validated appends. Never let the LLM invent stored values.
Safe write flowPresent data → explicit choice → duplicate check → validate again → one write → report result.
Dev cycleScope, tool contracts, specialists, test functions, create agents, attach tools, test each specialist, workflows, inspect events, fix one problem at a time, retest in new session.
Exam tipLikely questions: draw the multi-agent structure with tools on the right owners; choose sequential vs parallel vs loop for a scenario; say what the model does and what the tool does; describe a safe write flow.
