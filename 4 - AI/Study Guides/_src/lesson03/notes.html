1. What is an agent?

In Lesson 1 an AI system was drawn as a loop: it senses the environment through sensors, decides, then acts on the environment through actuators, and repeats. A system built around that loop is an agent.

Agent vs chatbotAn AI agent is more than a chatbot: it receives a goal, interprets instructions, may call tools, and may coordinate with other agents to complete a task. (A chatbot only replies with text.)

Examples from Lesson 1: embodied agents (self-driving car, robot vacuum) and disembodied agents (ChatGPT-style assistants). Loop engineering (Lesson 2) is the idea of making an agent act, observe, evaluate and correct itself.

2. Workflow automation with n8n

n8n is a visual workflow tool: you connect nodes (each does one job) into a flow that starts from a trigger (a form submission, a webhook call) and can call AI models and other apps. The course used it to orchestrate AI agents, webhooks and tool calling.

Example 2: Assignment 1, lecture hall booking

A requester submits a form (requesterName, requesterEmail, bookingDate, startTime 8:00 to 17:00 by hour, endTime 9:00 to 18:00 by hour) to book Lecture Hall A. The workflow checks availability for the chosen date and time.

BranchSteps
Available1. Create a Google Calendar event. 2. Store the booking details in the event. 3. Use Gemini to generate a short confirmation email. 4. Send it with Gmail. 5. Show a success page.
UnavailableShow an unavailable message to the requester.

Required nodes (8): Edit Fields, Google Calendar (check), IF, Google Calendar (create), Basic LLM Chain, Google Gemini Chat Model, Gmail, Form Ending. Question 1 builds two fields in Edit Fields with the timezone Asia/Colombo: startDateTime = DateTime.fromISO(bookingDate + 'T' + startTime, {zone:'Asia/Colombo'}).toISO() and endDateTime likewise from endTime. Submission: exported JSON, screenshots of the workflow, form, calendar event and confirmation email, and evidence for both an available and an unavailable booking.

The language model's role here: only to write the friendly email text (Basic LLM Chain + Gemini); the decision "is the hall free?" is made by a deterministic node (IF on the calendar result). This mirrors the ADK rule in section 6.

3. Google Agent Development Kit (ADK)

DefinitionGoogle ADK is an open-source framework for building, testing, evaluating and deploying AI agents. It supports several languages; the lab uses the Python version and the ADK Web Visual Builder (an experimental feature of the ADK web interface for creating and connecting agents visually).

Why use an agent framework?

A normal program follows rules written in code. A language model understands natural language but must not be trusted to invent factual records or take unrestricted actions. ADK combines both:

PartResponsibility
Language modelInterprets the user's intention
InstructionsDefine the agent's responsibility and boundaries
ToolsPerform controlled, deterministic operations
Specialist agentsDivide a large task into smaller responsibilities
Workflow agentsControl the order or pattern of execution

This separation makes the application easier to understand, test and improve.

Core concepts

ConceptMeaning
LLM agent (LlmAgent)An agent controlled by a language model. Normally has: a unique name, a model, instructions, an optional description, optional tools and optional sub-agents. Example: a billing agent interprets a bill request, gets an account alias, calls a bill-summary tool and explains the result. Names must be valid, useful identifiers because routing refers to them.
Root agentThe application's main entry point; receives the user's message first. In a multi-agent system it acts as coordinator: understands the request type, selects one suitable child agent or workflow, transfers the request, and avoids doing specialist work itself. Keeping specialist tools off the root reduces accidental tool calls and makes event traces easier to read.
Sub-agentA child of another agent, e.g. intake, classification, outage, billing and response agents. An LLM parent can transfer a request to a child; the event history may show a transfer_to_agent action.
ToolGives an agent a controlled capability. A Python Function tool wraps a function and exposes its parameters and result. Examples: classify_issue(issue_description, area=""), check_outage_status(area), get_bill_summary(account_alias). Tools should have narrow responsibilities and structured results. A read-only lookup must not modify a file; a write tool must validate inputs and enforce authorisation itself instead of relying only on an LLM instruction.
Built-in toolProvided by ADK in addition to custom functions. In the project get_user_choice shows controlled options to collect explicit consent, which is better than treating any user text as permission for a write.
SessionOne conversation. Start a new session for every independent test so earlier messages do not influence the next.
EventsADK Web shows events: which agent ran, whether control was transferred, which tool was called, its input and output, and where an error occurred. The interface supports session management, event inspection and state inspection.
Important ruleRegister a tool on the agent that owns the responsibility, not on the root or an unrelated specialist.

What a good LLM-agent instruction states

  1. its responsibility; 2. the information it needs; 3. the information it must not request or handle; 4. the tools it owns; 5. what to do when information is missing; 6. its expected response style; 7. its authority and side-effect boundaries.

Workflow agents

Workflow agents are deterministic controllers: unlike an LlmAgent they do not use a model to choose the execution pattern.

AgentBehaviourUse when
SequentialAgentRuns its children one after another in the order added (order is essential).Later stages depend on earlier ones: understand request → classify issue → retrieve record → explain result.
ParallelAgentRuns its children concurrently.Branches are independent and all inputs are ready (outage lookup and bill lookup). Not when one child must wait for another's output.
LoopAgentRepeats its child workflow until a stopping condition or a maximum iteration count is reached.Repeated refinement; in a classroom prototype use a small maximum to prevent endless questioning or an accidental infinite loop.

Parent limitation (Visual Builder): the "Sub Agents +" menu creates a new LlmAgent, SequentialAgent, ParallelAgent or LoopAgent; it cannot select an existing agent. ADK also gives each agent instance one parent, so an instance cannot belong to several parents. Workflow-specific copies therefore need unique names, e.g. seq_triage_agent and par_triage_agent: same instruction pattern and Python tool, separate instances.

Do not ask an LLM to calculate or invent a value already stored in an authoritative record.

Key takeaways An agent senses, decides and acts; an AI agent takes a goal, uses tools and may coordinate with other agents. n8n builds visual workflows from a trigger and nodes (form, edit fields, IF, LLM chain, Gmail / Calendar). In ADK: root agent routes, sub-agents specialise, tools do deterministic work and are registered on their owner, sessions and events are for testing. Workflow agents (sequential, parallel, loop) control execution without a model. Let the model understand and explain; let tools compute, look up and write, with explicit consent and validation.
