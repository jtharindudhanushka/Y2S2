State Space and Heuristic Search

Covers: AI search and why it is everywhere, describing a problem as a state space (initial state, operators, goal test), breadth-first and depth-first search with the two-jug puzzle, why equation methods fail, heuristics, uniform cost search, greedy best-first and A*, and the travelling salesman and knapsack problems. No prior lecture attendance needed.

Learning outcomes

  • Define AI search and state why it is important; name the three aims of search
  • Describe a problem as a state space: initial state, operators, state space, goal test
  • Run breadth-first search (BFS) and depth-first search (DFS) and compare them
  • Solve the two-jug puzzle with BFS
  • Explain heuristics and run uniform cost search, greedy best-first search and A*
  • Describe the travelling salesman and knapsack problems

1. What is AI search?

DefinitionAI search is the process of finding a sequence of actions (steps) that leads from an initial state to a goal state.

Analogy: finding your way in a new city. You start at the bus stand and want the hotel; you try roads, turn back from dead ends and compare routes. That trial and comparison is search. Applications: problem solving, game playing, route planning, optimisation. Why important: it lets machines make intelligent decisions, solve complex problems and navigate large search spaces to find optimal or near-optimal solutions. Problem-solving AI agents (task planners, assistants) must do some search. When AI is applied to a problem there is always a search.

Three objectives of a search

#Aim
1Finding a solution (any answer that works)
2Finding all the solutions
3Finding the best solution (lowest cost / highest value)

Search is everywhere in AI

  • Neural network weights: finding the best weight W is a search: each training cycle changes the weights and reduces the error; we look for the weight with the lowest error (Lesson 6).
  • Linear regression: many (m, c) pairs for y = m x + c; the best pair (least error) is found by search (Lesson 5).
  • Path-finding agents: shortest distance from A to E among many routes.
  • Travelling salesman problem (section 8) and games (find paths avoiding obstacles, choose the best moves).

Search is also called the "core behind AI". Searching for a state in a state space (all possible solutions) where the state is the solution of the problem is state space search.

2. Describing the problem: the state space

In state space search the problem is a set of situations (states). The computer moves from one state to another using legal steps until it reaches a state that passes the goal test. Analogy: a maze or GPS (each spot is a state, each move an operator).

PartMeaning
Initial stateWhere the problem starts.
OperatorsThe legal steps (instructions) that change one state into another.
State spaceAll the states reachable from the initial state.
Goal testA check of whether a state is an acceptable answer.
  • A state is a possible solution configuration: a complete snapshot of the problem at one moment, holding everything needed to decide what can happen next. States are written compactly, e.g. the pair (2, 4).
  • Two states are the same if their contents are identical, even if reached by different paths. This lets us avoid repeating work (pruning).
  • The answer is the path (the sequence of operators used), not only the final state: a GPS gives the route, not just the address.

3. Uninformed (blind) search

BFS and DFS are called uninformed, blind, exhaustive or brute-force search: they know only the operators and the goal test and cannot tell which state is closer to the goal.

Breadth-first search (BFS)

Search the whole breadth first, horizontally: every state at depth 1, then depth 2, and so on (ripples on a pond). It uses a queue (FIFO) and a visited list used to prune repeats.

  1. Put the initial state in the queue and mark it visited.
  2. Remove the front state; if it passes the goal test, stop and return the path.
  3. Apply every operator to it.
  4. Discard successors that cause no change or are already visited.
  5. Add the rest to the back of the queue, mark them visited, repeat.

1AB, C
2BC, D, E
3CD, E, F
4DE, F

6F: goal found

Properties: complete (finds a solution if one exists); optimal when every step costs the same (the first goal found is the shallowest); time and space about bd (b = branching factor, the choices per state; d = depth of the goal; b = 2, d = 3 gives 8 states; b = 10, d = 5 gives 100,000). Weakness: memory (a whole level is stored).

Depth-first search (DFS)

Follow one branch as deep as possible, then backtrack to the most recent state that still has an unexplored option (exploring one tunnel to its end). It uses a stack (LIFO) or recursion.

Properties: not complete (can loop forever in a deep or cyclic space); not optimal; time about bm (m = maximum depth); space about b × m (low memory: only the current branch).

4. Worked example: the two-jug puzzle (BFS)

Two jugs without markings: a 3 L jug and a 4 L jug, unlimited water. Measure exactly 2 litres. (Written in the lecturer's notes as: both jugs empty; collect 2 L of water in either jug.)

  • State (x, y): x = litres in the 3L jug, y = litres in the 4L jug. Initial (0, 0). Goal: (2, 0) or (0, 2).
#OperatorResult
1Fill 3L(3, y)
2Fill 4L(x, 4)
3Empty 3L(0, y)
4Empty 4L(x, 0)
5Pour 3L into 4Luntil the 4L jug is full or the 3L jug is empty
6Pour 4L into 3Luntil the 3L jug is full or the 4L jug is empty

A pour moves the smaller of (what the source holds) and (free space in the other jug). From (0, 4) "pour 4L into 3L": source holds 4, the 3L jug has 3 free, so 3 litres move: (3, 1). A successor is discarded if it causes no change or is already visited (otherwise the search loops: (3,0) regenerates (0,0), which regenerates (3,0)...).

LevelExpandedNew states added
0(0,0)(3,0), (0,4)
1(3,0), (0,4)(3,4), (0,3), (3,1)
2(3,4), (0,3), (3,1)(3,3), (0,1)
3(3,3), (0,1)(2,4), (1,0)
4(2,4), (1,0)(2,0): goal

Lessons from the example: BFS is blind (it expanded (3,4) as readily as (3,3)); pruning with the visited list is essential (it also removed the duplicate (3,4) produced by two parents); 11 of the 20 possible states were generated; the first goal found is shortest because no level is skipped; the cost is memory, which is why heuristic search was developed. The order in which operators are tried can change the order states are found but BFS still finds a shortest path. The handwritten BFS tree of the class shows the same solution path, with repeated or dead states marked with a stop sign.

5. Why not solve it with equations?

The graphical and simplex methods come from Linear Programming (LP): they assume a linear objective, linear constraints, continuous variables and a convex feasible region (no dents). Example: a bakery makes cakes (profit 5, 2 hours) and cookies (profit 2, 1 hour) with 10 hours: maximise 5 × cakes + 2 × cookies subject to 2 × cakes + cookies ≤ 10. The best answer is at a corner: (0,0) gives 0; (5 cakes, 0) gives 25; (0, 10 cookies) gives 20; best = 5 cakes, profit 25. The graphical method picks the best corner on a graph; simplex hops from corner to corner.

Why they cannot be used for search problems:

  • The world is not linear (curved, conditional, interacting relationships).
  • Many states are discrete: a jug holds 2 or 3 litres, not a meaningful 2.4.
  • The answer is a sequence of actions, not a single point: LP returns values, not a plan.
  • Constraints are logical rules ("cannot pour into a full jug"), not linear inequalities.
  • The graphical method works only for two or three variables.
  • In a non-convex space a corner point is not guaranteed to be optimal, so simplex logic fails.

So we explore the space step by step.

6. Informed (heuristic) search

A heuristic h(n) estimates how close a state is to the goal (lower = more promising). It lets the search expand promising states first and so cuts the number of expansions. It is an estimate, not a guarantee. Analogy: the hot-and-cold game, or Google Maps using straight-line distance to try roads that head the right way (the A* idea). Examples: straight-line distance to a destination; the number of misplaced tiles in the 8-puzzle.

Small map for all three methods. Start S, goal G. Roads: S–A 1, S–B 4, A–B 2, A–G 6, B–G 3. Heuristic (guessed distance to G): h(S) = 5, h(A) = 4, h(B) = 2, h(G) = 0.

Uniform cost search (UCS; uninformed)

Always expand the state with the smallest total path cost so far, g(n) (a priority queue). It finds the lowest-cost path but uses no guess about the goal, so it can explore many states. On the map: expand S (0): A = 1, B = 4. Expand A (1): B via A = 3 (better than 4), G = 7. Expand B (3): G via B = 6 (better than 7). Smallest is now G (6): goal, path S → A → B → G, cost 6.

Greedy best-first search (informed)

Always expand the state with the smallest h(n), ignoring cost so far. From S the neighbours are A (h = 4) and B (h = 2), so it goes to B, then G. Route S, B, G costs 7: fast but not guaranteed best.

A* (A-star)

f(n) = g(n) + h(n)g = real cost from the start to n; h = guessed cost from n to the goal. Expand the state with the smallest f. If h never overestimates the true remaining cost (an admissible heuristic), A* finds the shortest path.

7. Famous hard search problems

Travelling salesman problem (TSP)

A salesman must visit each city exactly once and return to the start; all cities are connected and paths work both ways. Find the shortest tour. With a fixed start there are (n − 1)! orders (n! = n × (n−1) × ... × 1).

Cities nRoutes (n − 1)!
54! = 24
65! = 120
109! = 362,880
2019! = 121,645,100,408,832,000 (about 1.2 × 1017)

(If a route and its reverse are the same tour, halve these numbers.) TSP is NP-hard: no known fast method always finds the best tour for every size, so large cases cannot be solved by trying all routes; we use heuristics and genetic algorithms (Lesson 11). Even checking a million routes per second, 20 cities would take thousands of years.

Knapsack problem

An optimisation problem: choose items with the maximum total value without exceeding a weight limit. Example: limit 5; A (weight 2, value 3), B (3, 4), C (4, 5).

Key takeaways Search = find the sequence of steps from initial to goal state. State space = initial state, operators, state space, goal test; the answer is the path. BFS: queue, complete, optimal (equal costs), memory heavy. DFS: stack, not complete, low memory. Blind search uses only operators and goal test. Heuristics guess closeness to the goal. UCS uses g, greedy uses h, A* uses f = g + h and is optimal with an admissible h. TSP ((n−1)! routes) and knapsack are hard search/optimisation problems.

Written questions

W1. Define AI search, list its three aims and name four places search appears in AI.

AI search is finding a sequence of actions from an initial state to a goal state. Aims: find a solution, find all solutions, find the best solution. It appears in neural network weight training, linear regression (best m, c), path-finding agents, the travelling salesman problem and games.

W2. Explain the four components of a state space search problem and why the answer is the path.

Initial state (where it starts), operators (legal steps changing one state into another), state space (all reachable states) and goal test (is this state an acceptable answer). The answer is the sequence of operators used, like a GPS route rather than just the destination.

W3. Compare BFS and DFS (structure, completeness, optimality, memory) and trace both on a small tree.

BFS: queue, level by level, complete, optimal with equal costs, high memory (about b^d). DFS: stack, branch by branch, not complete, not optimal, low memory (about b x m). On A(B(D,E),C(F)) BFS visits A B C D E F; DFS visits A B D E C F.

W4. Solve the 3L/4L jug puzzle to get 2 L using BFS and explain pruning.

State (x, y), initial (0,0), goal (2,0) or (0,2), six operators (fill, empty, pour each way). BFS levels: (0,0); (3,0),(0,4); (3,4),(0,3),(3,1); (3,3),(0,1); (2,4),(1,0); (2,0). Path (0,0),(3,0),(0,3),(3,3),(2,4),(2,0). Pruning with a visited list discards repeated states so the search does not loop or duplicate work.

W5. Explain heuristics and compare uniform cost, greedy best-first and A*, using the map S-A 1, S-B 4, A-B 2, A-G 6, B-G 3 with h(S)=5, h(A)=4, h(B)=2, h(G)=0.

A heuristic estimates closeness to the goal. UCS uses g only and finds the cheapest path S, A, B, G (cost 6). Greedy uses h only: S, B, G cost 7 (not optimal). A* uses f = g + h: expand S (f=5), A (f=5), B (f=5 via A), G (f=6): path S, A, B, G, cost 6, optimal because h is admissible.

W6. Why are the graphical and simplex methods unsuitable for search problems?

They assume a linear objective, linear constraints, continuous variables and a convex region. Search problems are non-linear, have discrete states, need a sequence of actions rather than values, have logical rather than linear constraints, the graphical method handles only 2 to 3 variables, and corner optimality fails in non-convex spaces.

W7. Describe the travelling salesman and knapsack problems and why they are hard.

TSP: visit each city once and return at minimum distance; (n-1)! routes with a fixed start (9! = 362,880 for 10 cities; about 1.2 x 10^17 for 20); NP-hard. Knapsack: pick items of maximum total value within a weight limit; the number of combinations explodes with more items. Both need heuristics or genetic algorithms for large cases.
