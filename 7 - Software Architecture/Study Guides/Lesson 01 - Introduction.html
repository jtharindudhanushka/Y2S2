Introduction: Architecture and Process

Covers: module aims and assessment, digital innovation vocabulary (invention vs innovation, digitization, digitalization, digital transformation), what software architecture and a software process are and how they differ, and the reverse-engineering activity. No prior lecture attendance needed.

Learning outcomes

By the end of the module (course aims, session 1) you should be able to:

  • Describe software development process models, and select a suitable one and suitable tools
  • Apply system thinking and design thinking
  • Describe the importance of software architecture and identify its essential elements
  • Describe different architecture patterns
  • Describe quality attributes and the basic rules of software design; evaluate the effect of design on software quality
  • Design a software architecture that satisfies the system requirements

Course content: software process models; system thinking and design thinking (generating new ideas, problem solving, decision making); software architecture and its importance, the architect's role, architectural drivers; architectural styles; designing a suitable architecture for a given system, architecture vs design; factors that affect designs and the effect of design on quality; quality attributes; basic design rules; the design process (inputs and start point, outcome, transformation of data, satisfying and discovering constraints).

1. Useful terms: innovation and transformation

The session introduces literacy terms (IT literacy, data literacy, digital dexterity, AI literacy) and three families of terms.

Invention vs innovation

The lecture contrasts the high-wheeler "penny-farthing" bicycle with a modern road bicycle: an invention is a new thing that did not exist before; innovation is making something work better in practice and in the market. In the Tim Herglotz diagram quoted in the lecture, innovation is "the process of creating value by doing the same things, better".

2. In-class activity 1: what do you already think?

The session opens with four questions to answer from your own understanding: What is software architecture? What is a software process model? Who decides the architecture and the process model for a project? When are they decided during a project? The model answers follow in sections 3–5.

3. Software architecture

DefinitionThe high-level structure / organisation of a software system. It includes the fundamental components, their interactions, and the principles guiding their design and evolution.
  • It provides a blueprint for the project, addressing concerns such as performance, scalability, security, maintainability.
  • It is a critical framework guiding the development, deployment and ongoing management of the software.

4. Software process

DefinitionA structured set of activities, methods and practices used to develop and maintain software. It defines the sequence of steps: requirements gathering, design, coding, testing, deployment and maintenance.
  • It provides a framework for managing and improving the quality, efficiency and predictability of development.
  • It often incorporates best practices and methodologies so the final product meets the specification and stakeholder needs.

5. Architecture vs process

Software architectureSoftware process
FocusThe structure and design of the systemThe sequence of activities in developing the software
ScopeHigh-level components, their relationships and guidelines for building and evolving the system; how parts interact to achieve objectivesMethodologies, practices and procedures across the life cycle: requirements, design, coding, testing, deployment
Concerned withThe system's technical blueprint: performance, scalability, security, maintainabilityWorkflow and management: efficiency, quality, timely delivery
OutcomeA well-defined architecture guiding developers and stakeholders so the system meets technical and business goalsA systematic approach giving consistent, repeatable results and adherence to timelines

They are distinct but complementary: the architecture defines the technical structure; the process defines the steps to create and maintain that structure. (Process models such as waterfall and agile / Scrum are studied again in the group project, Lesson 8.)

Key takeaways Invention = new; innovation = value by doing better; digitization changes information, digitalization processes, digital transformation organisations, AI transformation decisions. Architecture = what the system is and how it is built (structure, components, interactions, principles); process = how it is developed, managed and delivered. Both are needed. Written questions

W1. Define software architecture and software process and explain how they differ.

Architecture: the high-level structure of a software system, its fundamental components, their interactions and the principles guiding design and evolution; a blueprint addressing performance, scalability, security and maintainability. Process: a structured set of activities, methods and practices to develop and maintain software (requirements, design, coding, testing, deployment, maintenance). Architecture is about what the system is and how it is constructed; process is about how it is developed, managed and delivered. They are distinct but complementary.

W2. Distinguish digitization, digitalization, digital transformation, AI transformation and human-AI transformation.

Digitization transforms information (analog to digital); digitalization transforms processes; digital transformation transforms organisations; AI transformation transforms decision-making; human-AI transformation transforms how people create value.

W3. List the sections of the reverse-engineering presentation and give two non-functional requirements for WhatsApp with reasons.

Overview, stakeholders, functional requirements, non-functional requirements, high-level architecture, data flow, scalability, security, technology stack. Examples: availability (people expect messages to be delivered at any time) and privacy/security (messages are personal, so encryption and authentication matter).
