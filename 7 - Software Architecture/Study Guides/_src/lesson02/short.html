Short note: revision sheet

TopicRemember
Good designHigh cohesion (a module does one specific job; things inside belong together) and low coupling (little interdependency between modules). Kitchen analogy: chef = cohesion; small hand-off opening to the dishwashing station = low coupling.
Architecture vs designArchitecture = plan with enough detail to produce a design. Design = plan with enough detail to implement. Analysis = investigate the problem; system design = conceptual solution.
Architectural vs design patternArchitectural: design phase, blueprint, the base. Design pattern: building phase, implementation, structure classes for common problems.
Why architectureSoftware affects the business; wrong pattern = main cause of failure; without it code lacks clear roles and relationships; analyse risks beforehand.
Architect vs developer vs tech leadArchitect: system structure and long-term integrity; months to years; boundaries, tech stack, integration patterns; trade-off analysis + communication; audience executives. Developer: features, sprint, coding. Tech lead: team execution and code quality.
Architect's responsibilitiesSystem decomposition · trade-off analysis · stakeholder communication · quality attribute ownership · decision documentation · technical roadmap.
Quality attributesFunctional = what; quality = how well. Performance, scalability, availability, security, maintainability, interoperability.
ATAMArchitecture Trade-off Analysis Method: 1 identify scenarios, 2 map to quality attributes, 3 analyse architectural approaches, 4 surface risks and trade-offs.
Architectural patternReusable blueprint: predefined subsystems, roles, responsibilities and rules. Types: monolithic, layered, MVC, event-driven, client-server, microservice. Know for each: pattern, usage, shortcomings, examples.
Importance of patternsDefine basic characteristics · maintain quality and efficiency · agility · problem solving · productivity.
SOLIDSRP one reason to change · OCP open for extension, closed for modification · LSP subclasses replace parents safely (Penguin vs Bird) · ISP no forced unused methods (Machine split into Printer / Scanner / Fax) · DIP depend on abstractions (Database interface for MySQL / Mongo). Goal: maintainable, extendable, easy to understand.
Exam tipFor SOLID questions give: the definition, a non-technical analogy, a "wrong" example and the fix. The five principles all reduce coupling.
