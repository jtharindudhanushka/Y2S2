Short note: revision sheet

TopicRemember
Project7 weeks; 56 students in 8 teams of 7; 2 projects, 4 teams each: A Apartment Management (G1–4), B University Services (G5–8). Functional prototype with synthetic data. Isolated services cannot earn full marks.
DomainsA: G1 identity/residents, G2 property/lease/occupancy, G3 billing/payments, G4 operations/community. B: G5 identity/directory, G6 facilities/reservations, G7 service requests/work orders, G8 events/communications/feedback.
RolesScrum Master, BA/PM, Team Lead (mandatory), UI/UX+Frontend, Frontend, Backend 1, Backend 2, QA/DevOps. No ceremonial-only roles.
Tech standardReact + TypeScript + Redux (one shared app); Spring Boot microservices + JPA; MySQL schema per service; JWT + RBAC; OpenAPI + Postman; Docker + Compose; GitHub (org per project, repo per service); Jira per team; GitHub Actions on PRs.
Mandatory architectureIndependent services with owners; API Gateway; central auth service (JWT); own data store, no cross-DB access; documented REST + timeouts/errors; consistent conventions and exception handling; Compose; health + logs; versioned OpenAPI; modular shared frontend. Optional: RabbitMQ/Kafka, discovery, tracing, Kubernetes, log aggregation, circuit breakers.
Prototype minimumAuth + roles; 2 cross-team end-to-end workflows; validated CRUD and status transitions; search/pagination/validation; integration; tests, Postman, defects, security checks, simulated UAT; deployment guide and release notes.
GovernanceProject Integration Council (4 Team Leads) weekly; contract changes announced before implementation; no silent change to auth, gateway routes, shared data definitions or response formats; at least 2 sprints before release.
User storyAs a [role], I want [capability], so that [benefit]; acceptance criteria testable (Given-When-Then).
WorkflowBacklog → Ready → In Progress → Code Review → QA/Verification → Done; Blocked records blocker, owner, next action.
DoR / DoDReady: clear value, testable criteria, dependencies known, enough design, estimate + owner, fits sprint. Done: criteria pass with evidence, reviewed PR merged, tests pass, docs updated, no secrets, integrated env not broken, Jira updated.
GitHub rulesProtected main; feature/fix branches named with Jira key; PR with purpose, Jira link, evidence, tests, limitations; at least one meaningful review; Jira key in commits; quality over commit count; CI on PRs; RC tag + final tag; synthetic data; no secrets.
DeliverablesProposal, plan, risk register, SRS, traceability, architecture doc, ADRs (context, decision, alternatives, consequences), API specs, test plan/cases/defects/report, progress reports, change requests, sprint review/retro, release notes, deployment guide, user/admin guides, repo index, Jira evidence, demo.
Marks (100)Planning/Jira 15; requirements 15; architecture 20; implementation 25; testing 15; deployment/docs 5; individual 5.
DemoTagged release; synthetic data; 2 cross-team workflows; Jira, PRs, CI, Swagger/Postman; explain one architecture decision and one integration problem; fallback local environment.
Exam tipConnect the project to the lectures: bounded services with their own data (microservices, Lesson 5), API gateway and contracts (REST, Lesson 5), JWT / never trust the client (Lesson 6), incremental delivery (Lesson 4), ADRs as decision documentation (architect's role, Lesson 2).
