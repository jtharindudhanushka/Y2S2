AssessmentContinuous 20–40 % (incl. PBL), final exam 60–80 %; at least 20 % of marks needed from BOTH components.
Invention vs innovationInvention = something new; innovation = creating value by doing things better.
TransformationsDigitization → information. Digitalization → processes. Digital transformation → organisations. AI transformation → decision-making. Human-AI transformation → how people create value.
Software architectureHigh-level structure of a system: fundamental components, their interactions, and principles guiding design and evolution. A blueprint addressing performance, scalability, security, maintainability; guides development, deployment, management.
Software processStructured set of activities, methods, practices to develop and maintain software: requirements, design, coding, testing, deployment, maintenance. Manages quality, efficiency, predictability.
Architecture vs processArchitecture = what the system is and how it is constructed. Process = how it is developed, managed and delivered. Distinct but complementary.
Reverse-engineering activityOverview, stakeholders, FR, NFR, high-level architecture, data flow, scalability (100k to 100M users), security, tech stack; 5-minute presentation; diagrams: architecture + data flow.
Exam tip"Architecture vs process" is a classic short-answer question: use the four rows (focus, scope, concerned with, outcome) and finish with "distinct but complementary".
