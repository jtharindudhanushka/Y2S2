Short note: revision sheet

TopicRemember
Conway's Law (1968)Organisations produce designs that copy their communication structures. Boundaries appear where communication is weakest. Cross-functional capability-owning teams naturally produce microservices.
N-tierPresentation, business logic, data access, database; dependencies point downward only.
Server layersController (HTTP, validation, status codes) → Service (rules) → Repository (SQL only). Never backwards, never skipping a layer. Rule in one place.
FoldersPackage by layer vs by feature (feature usually wins for group projects).
HTTP request / responseMethod, URL, headers (auth, format), body; response status + body.
RESTNouns in URL, verbs in method. GET list/read; POST create (not repeatable); PUT replace; PATCH partial; DELETE remove (repeatable). Idempotency: double POST creates two.
Status codes2xx worked (200, 201, 204); 4xx client error (400, 401, 403, 404); 5xx server error (500, 503). Don't return 200 with an error body.
MonolithOne app, one deployment, one DB. Simple to build, deploy, debug; one-DB transactions. Scale and deploy together; coupling can creep in.
Modular monolithOne deployment with clean internal boundaries: where a student project should live.
MicroservicesSmall independently deployable services, each owning one business capability and its data, talking over the network, one team end to end. Fail any of five properties = distributed monolith.
Forces to splitRelease traffic jam; uneven load; blast radius; team autonomy (3 of 4 are people problems).
Do you need them?Need: teams blocking releases, 10x scaling for one part, different tech, 24/7 ops capability, stable boundaries. Don't: one small team, changing domain, no ops, no users yet, "big companies do it".
CampusEats vs IslandWideSame checklist, opposite verdicts: modular monolith vs microservices. No driver, no service. Merge where boundaries cost more than they earn (6 to 4 deployments).
Network costsNetwork fails; no shared transaction (eventual consistency); operational weight; boundaries permanent. Six challenges: debugging, testing, consistency, API versioning, operations, local development.
Return tripPrime Video 2023 (back to a monolith, 90 % cost cut); Segment 2018 (about 140 services collapsed). Fowler: don't start with microservices.
5 patternsAPI gateway, database per service, service discovery, circuit breaker, async messaging.
Sync vs asyncAsk: is anyone waiting? Sync (REST / gRPC) when the answer is needed now; async (events via broker) for notifications, receipts, analytics.
Orchestration vs choreographyOrchestrate money and critical workflows (conductor, one failure owner); choreograph broadcasts. Saga = distributed workflow pattern.
SizingCapability-sized, not code-sized. Avoid nano-services and distributed monoliths. Acid test: deploy alone on a Tuesday without a meeting.
Exam tip"Monolith or microservices for this system?" Answer with the checklist (team, load, domain stability, ops, deploy independence), give the verdict (often modular monolith for small teams) and name the costs you accept.
